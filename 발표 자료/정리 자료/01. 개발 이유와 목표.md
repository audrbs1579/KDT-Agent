# 01. 개발 이유와 목표

범위: 본편 01~03장 · 기준 3분 · [전체 구성](<00. 전체 발표 전략 및 장표 구성.md>)

시각자료는 사용자 요청이 있을 때만 SVG 그래프·도형·그림으로 제작한다. 시각 자료 폴더에 HTML을 만들지 않는다. 아래 화면·도식 설명은 제작 명세다.

## 이 파트가 남길 메시지

개발 목적은 반복적인 교육 운영 업무를 최대한 자동 실행해 사람의 수작업을 줄이는 것이다. 여러 기수 운영의 반복 장면에서 출발하고 일정·자료·업무가 연결되는 목표를 보여준다.

## 01장. 반복적인 교육 운영 업무를 최대한 자동 실행한다

- **핵심 문장:** “중요한 결정과 예외를 제외한 반복 운영 업무를 에이전트가 실행하도록 만듭니다.”
- **화면:** 프로젝트명과 `일정 등록 → 준비·안내·수집·대조·집계 → 결과 기록` 흐름. 사람에게 연결되는 승인·예외를 곁에 표시한다.
- **설명:** 처음부터 목적을 말한다. 매니저가 매번 명령해야 하는 도구가 아니라 등록한 일정·규칙에 따라 예약과 실행을 이어가는 개발 방향임을 설명한다.
- **강조:** 자동화를 통해 줄이려는 것은 반복적인 확인·연락·정리·재확인 작업이다. 달성한 절감 시간은 제시하지 않는다.
- **근거:** [00 보고서 안내](../../설계보고서/00_보고서_안내.md), [F01 과정·규칙](../../설계보고서/기능/F01_과정_기능_규칙.md).

## 02장. 여러 기수를 운영하면 같은 확인·연락·정리가 반복된다

- **핵심 문장:** “기수마다 수업은 하루 하나지만 운영 업무는 매일 반복됩니다.”
- **화면:** 같은 날짜의 A·B·C기수 강의와 각 기수의 강사 확인·출결·자료 업무를 나란히 배치한다. 현재 사람이 확인하는 지점을 표시한다.
- **설명:** 한 기수에 하루 여러 강의가 있다는 의미가 아님을 달력으로 설명한다. 기수가 늘면 비슷한 일을 서로 다른 강사·학생·자료·채널에 반복하는 운영 장면을 짚는다.
- **강조:** 업무량 증가를 보여주는 도식이다. 확인하지 않은 시간·인력 절감률 그래프로 바꾸지 않는다.
- **근거:** [01 공통 아키텍처](../../설계보고서/01_공통_아키텍처.md), [F05 일정](../../설계보고서/기능/F05_Outlook_일정.md), [F21 대시보드](../../설계보고서/기능/F21_대시보드.md).

## 03장. 일정에서 시작해 운영 업무 전반으로 연결한다

- **핵심 문장:** “하루 운영을 먼저 연결하고 검증된 방식으로 업무 범위를 넓힙니다.”
- **화면:** `과정 준비 → 일별 수업 운영 → 행사·멘토링 → 후속 자료 업무` 운영 주기 지도. 일정·강사·출결·학습 지원을 일별 운영에 묶고 과정 종료 만족도는 마무리 단계에 두며, OT·모집·행사·인재 자료는 주변 범위로 표시한다.
- **설명:** 본편에서 일별 수업 운영을 대표 사례로 따라간다고 안내한다. 설문·출결만 만드는 프로젝트로 보이지 않게 전체 범위를 먼저 위치시킨다.
- **강조:** 기능마다 자동 실행·사람 검수·승인 범위는 설계서에 따른다. 모든 주변 기능이 첫 구현에 동시에 포함되거나 무인화됐다는 뜻은 아니다.
- **근거:** [00 기능 목록](../../설계보고서/00_보고서_안내.md), [05 구현 계획](../../설계보고서/05_구현_검증_계획.md), [F03 OT](../../설계보고서/기능/F03_OT_체크리스트.md), [F11 행사](../../설계보고서/기능/F11_타운홀_특강.md), [F12 멘토링](../../설계보고서/기능/F12_멘토링_사전자료.md), [F13 인재 자료](../../설계보고서/기능/F13_이력서_인재검색.md).
