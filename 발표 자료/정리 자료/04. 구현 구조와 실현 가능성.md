# 04. 구현 구조와 실현 가능성

범위: 본편 16~20장 · 기준 5분 · [전체 구성](<00. 전체 발표 전략 및 장표 구성.md>)


## 이 파트가 남길 메시지

앞에서 본 업무 사례를 구현하는 데 필요한 계정 연결·Azure 실행·데이터·복구 구조를 설명한다. 본편은 역할과 동작을 보여주고 제품별 사양·전체 권한표는 부록에서 확인한다.

## 16장. 세 계정의 역할을 유지하며 업무를 연결한다

- **핵심 문장:** “직원 업무·교육 운영·Azure 기반을 허용된 범위로 연결합니다.”
- **화면:** 세 영역 `@msacademy: Azure 운영`, `@elixirr: 직원 Outlook·업무`, `@dataschool: 교육 Teams·Forms·자료`. 중앙에 교육 PM 업무 흐름을 둔다.
- **설명:** 직원 일정과 교육 채널 수업은 역할이 다르다. 계정·권한을 합치지 않고 업무에 필요한 연결을 구성한다.
- **강조:** 본편에는 역할 이름과 연결 목적을 보여준다. 실제 테넌트 ID·전체 권한 문자열은 부록에 둔다. Forms의 조직 계정 인증은 Graph 앱 권한과 별도로 확인한다.
- **근거:** [02 테넌트 연결](../../설계보고서/02_테넌트_연결.md), [07 연결 조건](../../설계보고서/07_세계정_연결권한_체크리스트.md).

## 17장. Azure가 예약·실행·기록을 이어간다

- **핵심 문장:** “운영자 노트북이 꺼져도 서버가 예약과 실행 상태를 유지하도록 구성합니다.”
- **화면:** `화면·업무 서버 → 규칙·예약 → 작업 대기열 → 실행기 → 업무 DB·파일 → 화면` 구조. 각 역할에 Container Apps, Functions, Service Bus, PostgreSQL, Blob을 대응시키고 AI·Logic Apps·브라우저 실행 경로를 연결한다.
- **설명:** 강사 안내는 예약과 발송, Forms 응답은 수집과 집계, 채널 수업/Forms 준비는 검증된 브라우저 절차로 연결된다. AI는 문맥 처리·초안·요약을 맡고 규칙·집계·권한 검사는 서버 코드가 수행한다.
- **강조:** 업무 상태를 AI 대화에만 의존하지 않는다. 모든 서비스의 아이콘을 나열하기보다 앞선 사례가 통과하는 역할을 설명한다.
- **근거:** [01 아키텍처](../../설계보고서/01_공통_아키텍처.md), [03 리소스](../../설계보고서/03_Azure_리소스_근거.md), [F19 실행기](../../설계보고서/기능/F19_컴퓨터유즈_경험메모리.md).

## 18장. 기수·학생·수업일과 원천 버전으로 자료를 연결한다

- **핵심 문장:** “같은 날짜에 여러 기수가 있어도 자료와 응답이 섞이지 않게 연결합니다.”
- **화면:** 일정·강사 자료·출결 신고/LMS는 기수·수업일·하루 회차에, 종료 설문은 과정/기수·종료일에 연결되는 관계도. 각 자료 옆에 원문·버전·수집 시각을 표시한다.
- **설명:** 학생이 필요한 업무는 검증된 학생 계정으로 연결한다. 익명 만족도는 종료한 과정/기수에 연결하되 개인 학생과 연결하지 않는다. 원본 저장소와 DB 업무 기록·별도 결과 파일의 역할을 구분한다.
- **강조:** 전체 DB 컬럼은 부록에 둔다. 강사팀·운영 채널·학생 공개 영역의 자료 역할을 구분한다.
- **근거:** [04 데이터](../../설계보고서/04_데이터_권한_복구.md), [09 입력·출력](../../설계보고서/09_데이터_컬럼_엑셀양식.md), [KDT 자료 구조](../../설계보고서/KDT_폴더_구조.md).

## 19장. 권한·중복 방지·실패 복구를 실행 과정에 적용한다

- **핵심 문장:** “잘못된 대상 발송과 중복 실행을 막고 실패는 기록해 복구합니다.”
- **화면:** 정상 실행 흐름과 `권한/대상 불명 → 확인 대기`, `실패 → 재처리`, `결과 불명 → 기존 결과 대조` 가지를 보여준다.
- **설명:** 발송 직전에 일정·수신자·최신 신고를 재확인한다. 같은 요청의 재전달로 업무를 중복 생성하지 않고, 결과가 불명확한 외부 발송은 무조건 반복하지 않는다.
- **강조:** 내부 보관과 외부 전달, 신고 접수와 공식 인정, 검수와 실제 게시를 각 상태로 남긴다. 권한 상세표는 부록에 연결한다.
- **근거:** [04 권한·복구](../../설계보고서/04_데이터_권한_복구.md), [F15](../../설계보고서/기능/F15_LMS_입퇴실.md), [F19](../../설계보고서/기능/F19_컴퓨터유즈_경험메모리.md).

## 20장. 확인 사실과 남은 연동 검증을 구분한다

- **핵심 문장:** “현재 근거와 실제 업무에서 더 확인할 조건을 분명히 봅니다.”
- **화면:** 아래 표를 근거 문서·확인일과 함께 간결하게 보여준다.

| 구분 | 보여줄 내용 | 의미 |
|---|---|---|
| 기록된 확인 사실 | 06에 기록된 당시 계정·구독·관리자 역할 등 | 해당 기록 범위의 조회 사실 |
| 사용자 운영 기준 | 한 기수 하루 한 강의·여러 기수 운영, 3항목 설문, 사전 출결 신고 | 설계에 적용한 요구사항 |
| 공식 기능·설계 경로 | Forms 응답 커넥터, 서버 실행·저장, 브라우저 절차 후보 | 구현 경로가 있다는 근거 |
| 남은 실제 검증 | 실제 채널·파일·권한, Forms UI/OAuth·양식별 수집, 게시판/LMS 대조·완료 검사 | 우리 환경의 연결·반복 실행 확인 필요 |

- **설명:** 이번 발표 자료 정리는 새로운 계정 접속·배포·실행 성공 기록이 아니다. 달력·대시보드 목업도 설계 구상이다.
- **강조:** 체크리스트 전체를 읽지 않고 첫 구현을 위해 확인할 연결을 설명한다. 확인 사실의 기준은 설계보고서 06이다.
- **근거:** [06 실환경 기록](../../설계보고서/06_실환경_확인기록.md), [07 미확인 조건](../../설계보고서/07_세계정_연결권한_체크리스트.md), [F06 실현 가능성](../../설계보고서/기능/F06_만족도조사.md).
