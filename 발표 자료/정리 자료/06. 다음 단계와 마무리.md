# 06. 다음 단계와 마무리

범위: 본편 26~28장 · 기준 3분 · [전체 구성](<00. 전체 발표 전략 및 장표 구성.md>)


## 26장. 현재 개발 범위와 추후 확장을 구분한다

- **핵심 문장:** “반복 운영의 실행 기반을 만들고 검증된 범위를 확대합니다.”
- **화면:** 현재 설계의 업무 지도와 추후 후보를 나란히 표시한다.
- **현재 범위:** 일정·규칙·강사 소통·출결 신고/LMS 대조·자료 처리·학습 지원·과정 종료 3항목 만족도·대시보드·비용 관리. 첫 구현과 이후 연결 단계는 25장의 순서를 따른다.
- **추후 후보:** U01 경험 개선 후보 생성, U02 카카오톡 연결, U03 단위기간 제출 패키지, U04 출결 종합 내재화, U05 표준 종료 만족도 외 범용 Forms·퀴즈 자동화.
- **강조:** 과정 종료 만족도 준비·수집 자동화는 F06 개발 범위다. U05를 이유로 이를 전체 추후 범위로 옮기지 않는다. U05가 일별·중간·행사 만족도를 다시 운영한다는 의미도 아니다.
- **근거:** [00 범위](../../설계보고서/00_보고서_안내.md), [11 추후 업데이트](../../설계보고서/11_추후_업데이트.md), [F06](../../설계보고서/기능/F06_만족도조사.md).

## 27장. 첫 대상·자료·연결 책임과 운영 규칙을 정한다

- **핵심 문장:** “다음 개발에 필요한 대상·자료·책임·규칙을 구체화합니다.”
- **화면:** 아래 준비 항목에 담당자·다음 확인 시점을 남기는 표.

| 준비 항목 | 논의할 내용 |
|---|---|
| 첫 대상 | 테스트용 과정과 실제 적용 후보 기수 |
| 허용 자료 | 일정·명단·강사 자료·사전 출결 신고·원천 파일의 사용 범위 |
| 연결 책임 | Teams/SharePoint/LMS·Forms OAuth·양식별 수집 연결·인증 복구 담당 |
| 운영 규칙 | 사전 지각/조퇴/외출 확인·승인, 과정 종료 확인·3항목 양식·응답 기한/익명·재안내 |
| 검증·확대 | 통과 기준·예외 처리·비용 기록·다음 연결 순서 |

- **설명:** 만족도 문항 수와 주기는 이미 합의된 과정 종료 1회·객관식 2개·주관식 1개를 적용한다. 새로운 일별·중간 양식 선택을 논의 항목으로 넣지 않는다.
- **강조:** 워크샵의 실행 준비를 요청한다. 설계서의 참고 기간·비용을 확정 견적·납기 승인 요청으로 바꾸지 않는다.
- **근거:** [05 남은 결정](../../설계보고서/05_구현_검증_계획.md), [07 연결 준비](../../설계보고서/07_세계정_연결권한_체크리스트.md).

## 28장. 반복 업무는 자동 실행하고 사람은 중요한 일에 집중한다

- **핵심 문장:** “일정과 운영 규칙에 따라 에이전트가 반복 업무를 이어서 처리하게 만듭니다.”
- **화면:** 첫 장의 `일정·규칙 → 자동 실행 → 결과·예외` 흐름을 다시 사용하고, 다음 검증의 출발점을 표시한다.
- **마무리 발언:** “여러 기수의 반복 확인·연락·정리를 최대한 자동화하는 것이 목표입니다. 중요한 결정과 예외는 사람이 맡고, 실제로 어디까지 자동 처리됐는지는 실행 결과와 근거로 확인하겠습니다.”
- **강조:** 새로운 기능·가격·확정 일정은 마지막 장에 추가하지 않는다. 현재 남는 사람 작업과 실제 검증이 필요한 연결은 앞선 설명을 유지한다.
- **근거:** [00 보고서 안내](../../설계보고서/00_보고서_안내.md), [01 아키텍처](../../설계보고서/01_공통_아키텍처.md).

질의응답은 [07 부록·참조표](<07. 부록 및 설계보고서 참조표.md>)에서 질문에 맞는 근거를 연다.
