# 교육운영 AI PM — 아키텍처 및 기능 상세 명세

기준일: 2026-10-28 · 문서 버전: 0.6 · 대상: 운영국

## 자료의 목적과 해석 기준

**이 자료는 워크샵에서 구조·실현 방법을 설명하기 위한 사전 참고 자료입니다. 예산·개발 일정·인력 배치의 승인 요청서나 확정 견적·납기 약속이 아닙니다.** 아래 기준은 모든 공통 문서·기능 문서·도식·Excel 예시에 적용합니다.

- **모델:** 조사한 가격·후보를 참고해 운영에 적용하고, 품질·수정률·응답 시간·비용을 확인합니다. 더 좋은 모델 또는 더 가성비 있는 모델을 찾으면 실제 테스트 및 운영을 하면서 바꿀 수도 있습니다. 현재 후보·순위는 확정 모델이나 품질 보증이 아니며 상위 가격 모델로만 바꾸는 것도 아닙니다.
- **리전·배포 유형:** 상황에 따라 다른 리전에 생성하거나 다른 지역에서 처리할 수 있습니다. 생성 위치·저장 위치·AI 처리 위치를 구분하고, 실제 테스트 및 운영을 하면서 바꿀 수도 있습니다. 리전 이전은 설정값 변경만으로 기존 데이터까지 이동하는 것이 아니므로 권한·정책·데이터 이동 조건을 확인해 수행합니다.
- **지원 형식·API·SKU:** 현재까지 조사한 정보는 구현 후보입니다. 조사상 지원 가능과 우리 환경에서 실제 검증 완료를 구분하며, 파서·분석기·API 버전·서비스는 실제 테스트 및 운영을 하면서 바꿀 수도 있습니다.
- **예산·일정·데이터 예시:** 금액·기간·컬럼·문항·인물·완료 상태는 별도 확인 기록이 없는 한 설명용 예시이며 변경 가능합니다. 예시 보완이나 미확정 값 자체를 워크샵 자료의 결함 또는 예산·일정 승인 차단 사유로 해석하지 않습니다.
- **확인 사실의 기준:** 실제 계정·구독·권한·조회 이력은 06 실환경 확인 기록을 주력 문서로 사용합니다. 다른 문서의 참고안으로 그 기록을 덮어쓰거나 새 검증을 했다고 간주하지 않습니다.
- **바뀌지 않는 실행 통제:** 모델·리전·예시의 변경 가능성과 별개로 접근 권한·대상 확인·민감정보 보호·필요한 사람 승인·결과 불명 시 중단은 유지합니다.
- **Teams 자료 위치:** KDT 폴더 구조와 기능별 매핑을 공통 참고 기준으로 사용합니다. 수강생 팀 `일반`·기수별 운영 채널·강사팀 자료를 구분하며, 날짜·이름·파일명·세부 구성은 실제 테스트 및 운영을 하면서 바꿀 수도 있습니다. 제공된 예시는 실제 ID·권한·파일 내용·자동 연동 확인 완료를 뜻하지 않습니다.

## 운영국 의사결정 요약

**과정과 수업 일정표를 등록하면 일자별·강사별 운영 업무를 기본 템플릿에 따라 자동 예약·실행하고, 직원은 대시보드에서 진행 상황과 확인할 일을 봅니다.** 반복 운영 업무는 최대한 자동 실행하고 중요한 결정·승인과 예외는 사람이 맡습니다. 과정 종료 만족도는 기수별 과정 종료 시 1회, 객관식 2개·주관식 1개를 받으며 설문 준비·안내·수집·집계 자동화를 F06에 포함합니다. 원본 문서 편집과 퀴즈 정답·검수 등 별도 사람 작업은 해당 기능 기준을 따릅니다. 직원·학생 계정을 하나로 바꾸는 것이 아니라, 각 조직이 허용한 업무를 중앙에서 연결합니다.

| 계정 구분 | 실제 역할 | 설계상 위치 |
|---|---|---|
| `@msacademy` | Azure 실습·리소스 운영 계정 | AI·앱·DB·예약 실행의 운영 기반 |
| `@elixirr` | 직원 업무 계정 | 직원 Outlook, 공유 일정, 사내 Teams 회의·보고 |
| `@dataschool` | 교육용 Teams 계정 | 온라인 강의, 강사·수강생 소통, 교육 자료 |

실제 확인한 Azure 운영 구독은 **엘릭서**, 소속 디렉터리는 **대한상공회의소 인력개발사업단 / msaischool.onmicrosoft.com**이며, 세 계정(`@msacademy`, `@elixirr`, `@dataschool`) 모두 각 조직에서 **Global Administrator** 권한이 확인되었습니다. 실환경 확인 기록을 참고하세요.

**만족도 운영 기준:** 전체 과정 종료 시 1회 객관식 2개·주관식 1개 Forms만 운영합니다. 매일·중간·별도 최종 다문항·특강·멘토링 만족도는 운영하지 않습니다. 퀴즈·신청·동의서 등 다른 목적 양식과 구분합니다.

### 설계 결정

**일정 운영 기준(사용자 설명·캘린더 기준): 한 기수는 수업일마다 하루 강의 일정 1개를 운영하고, 같은 날짜에 여러 기수가 각각의 강의를 동시에 운영합니다.** 기수별 달력에는 해당 기수의 일별 강의 하나가 보이며, 전체 달력의 같은 날짜에 보이는 여러 강의는 서로 다른 기수의 일정입니다. 강사·과목은 날짜에 따라 바뀔 수 있고, 공동 멘토링의 복수 담당자도 하루 일정 하나에 연결합니다. 오전·오후 출결이나 분할 녹화는 같은 하루 강의의 내부 구간입니다.

1. **과정 생성 + 공유 엑셀 일정표 연결 후, 저장된 파일의 변경을 읽어 표준 운영 업무를 자동 예약·실행**하도록 설계합니다. 기수별·수업일별 강의 일정 1개, 날짜별 담당 강사·과목·휴일과 여러 기수의 동시 운영을 검증하고, 필수값이 모호하면 매니저 확인을 요청합니다. 매번 명령하거나 파일을 다시 업로드할 필요는 없습니다.
2. **문서 협업 방식은 대상에 따라 이원화**합니다. **① 운영진·강사는 기존 Teams/M365 공유 엑셀·워드를 직접 편집**하고, 에이전트는 허용된 SharePoint 파일을 다운로드·파싱해 집계합니다. 무인 앱이 Excel 셀이나 Word 원문을 직접 수정한다고 가정하지 않으며, 원본 수정은 사람이 하고 에이전트는 별도 결과 파일을 생성합니다. **② 수강생은 Microsoft Forms로 응답**합니다. 과정 종료 만족도는 **과정 종료 시 1회 객관식 2개·주관식 1개**이며, 승인된 템플릿을 에이전트가 복제·설정하고 종료 시 Teams로 안내합니다. 응답은 Azure Logic Apps의 Forms 커넥터로 자동 수집해 DB 집계·주관식 요약·결과 Excel 생성을 수행합니다. 양식별 수집 연결과 화면 자동화는 실제 검증 후 활성화합니다([F06](기능/F06_만족도조사.md)). 다른 Forms 업무는 각 기능의 사람 작업 기준을 따르며 다운로드 Excel은 과정 종료 설문의 장애 복구·대조에도 사용합니다. 다운로드 사본과 Forms 연결 Excel은 구분합니다.
3. **Teams 수업 이벤트는 반드시 ‘1개월 단위’로만 생성**합니다. 현재 매니저가 일일이 만드는 **채널 수업 일정은 Teams 웹 일정의 컴퓨터 사용으로 생성·수정**하고, 실제 생성된 회의 링크를 직원 Outlook 일정에 연결합니다. 해당 월 강사 등록은 확인된 팀·채널 유형과 사전 승인 범위에 맞춰 수행합니다.
4. **`@dataschool` Teams는 4개 업무 역할로 연결**합니다. **① 기수별 수강생 팀**은 수업·학생 소통이며 파일 공유는 **`일반 (General) / 공유 탭` 안에서만** 합니다. **② 출석 관리 팀**은 외부 기관 출석 업무의 승인 자료 공유 역할입니다. **③ 강사팀**은 양식·결과보고서·멘토링 일지·산출물·중간평가문제·호명 출석부를, **④ 기수별 운영 채널**은 매뉴얼·상담·설문 결과·행사 운영 자료·내부 출결을 관리합니다. 강사팀 `출석부`는 호명 원본 수집 위치, 운영 채널 `출석부 / 월 / 주차 / 일자`는 내부 3종 원본·종합본의 보관 목적지로 구분합니다. AI 11기 구조는 제공받은 예시이며 운영 채널의 소속 팀·실제 ID·권한은 연결 시 확인합니다. 자료가 보이는 것과 에이전트의 업무별 접근 범위는 다릅니다.
5. Teams·Outlook을 기본값으로 하되 과정별로 체크박스(On/Off)와 커스텀 기능 추가로 변경할 수 있습니다.
6. 기본 자동화 외에 예외 업무나 규칙 변경이 필요할 때만 화면 설정 또는 자연어 지시로 조합합니다. 새로운 사이트·새 권한·새 코드는 검증을 거쳐 추가합니다.
7. 예약과 실행 상태는 Azure에 저장하므로 매니저 노트북이 꺼져도 자동 처리합니다. 사람의 편집·게시·승인을 기다리는 작업은 별도 대기 상태로 표시합니다.
8. 컴퓨터 사용은 Teams 채널 수업 일정과 새 사이트 작업 등 API로 처리하지 않는 업무에 활용합니다.
9. 운영 문제는 매니저에게, 출결 게시판의 사전 신고를 반영한 확인 시각·LMS 기록 대조 후 필요한 입퇴실/제출 확인만 학생에게 안내합니다. 외부 출석 업무는 **기관·자료 버전·수신 위치를 지정하고 매니저가 승인한 뒤에만** 출석 관리 팀으로 전달합니다.
10. 영상 및 참여도 모니터링은 관찰 가능한 사실과 확인 필요 장면을 정리해 매니저에게 보고합니다. 하루 3~4개로 나뉘어 저장되는 녹화 중 **처음 저장 완료된 오전 구간을 오후 퀴즈의 근거**로 사용하며, 없는 구간을 본 것으로 처리하지 않습니다. **원본 기획안(3-4, 3-5)의 참여도 하위 Top 3·자동 경고는 오판·민원 위험 때문에 ‘태도 순위 산출 금지 및 매니저 사전 확인 후 안내’로 변경했습니다(발표·보고 시 변경 사유 설명 항목).**

**출결 게시판 연계 기준:** `01. 출결 게시판`의 지각·조퇴·외출·결석 사전 예정과 변경/취소를 기수·학생·수업일별로 수집하고 LMS 실제 입퇴실·호명 출석부와 대조합니다. 접수된 예정에 맞춰 확인 시각·일반 미클릭 안내를 자동 조정하되, 신고 접수와 공식 출결 인정·정정 완료는 구분합니다. `02. LMS 정정 요청 게시판`은 사후 누락/오류 처리 상태로 별도 연결합니다. 상세는 [F15](기능/F15_LMS_입퇴실.md)를 따릅니다.

### 원문 대비 현재 설명 범위

다음은 확정 개발 계약이 아니라 현재 참고 설계의 범위 구분입니다. 우선순위·자동화 수준은 실제 테스트 및 운영을 하면서 바꿀 수도 있습니다.

| 원문 취지 | 현재 참고 설계 | 사람 업무·추후 범위 |
|---|---|---|
| 강의·설문·퀴즈·자료 수집 자동화 | 과정 종료 시 1회 3항목 Forms 준비·안내·응답 자동 수집·집계, 일정 기반 퀴즈 초안·자료 처리 | 과정 종료 설문 최초 규칙·문항 승인과 인증·예외는 사람. 퀴즈의 검수·정답/배점·게시 등은 F07 기준 |
| 참여도 하위 Top 3·영상 자동 경고 | 순위·자동 경고 제외, 관찰 사실을 매니저에게 보고 | 매니저 확인 후 필요한 안내 |
| LMS에서 이미 반려된 사유 안내 | F14에서 확정 결과·사유 조회 안내와 신규 증빙 1차 판독을 구분 | 최종 승인·반려는 매니저 |
| 단위기간 서류 이메일 | 일일 출결·증빙 운영은 [F14](기능/F14_LMS_서류_반려안내.md)~[F17](기능/F17_단위기간_서류메일.md), 단위기간 서류 이메일·패키지는 U03 추후 후보 | 기관 양식·수신자·승인 규칙을 확인한 뒤 별도 구현 |
| 카카오톡을 Teams로 전환 | Teams 중심으로 단계적 전환 | 기존 필요한 소통은 갑자기 중단하지 않으며 카카오톡 자동화는 U02 추후 후보 |
| 경험 개선·새 사이트 대응 | 검증된 절차 실행·기록은 [F19](기능/F19_컴퓨터유즈_경험메모리.md) | 자동 개선 후보 생성은 U01, 표준 과정 종료 만족도 외 범용 Forms·퀴즈 생성/게시 자동화는 U05. 과정 종료 만족도 자동화는 F06 개발 범위 |

## 읽는 방법과 문서 상태

**현재 문서는 새 시스템의 설계와 구현 기준을 다룹니다.** 확인된 환경은 06, 배포 전 확인·결정할 항목은 07에서 구분합니다.

- 각 기능은 **목적 → 입력·설정 → 처리 구조 → 리소스·권한 → 저장·출력 → 예외·승인 → 운영 품질 기준** 순서입니다. 운영 품질 기준은 정식 운영 중 대시보드·감사 로그로 상시 측정하는 기준입니다.
- 쉬운 설명을 먼저 두고, 구현자가 사용할 제품명·데이터 필드는 뒤에 적었습니다.
- 공통 구조는 모든 기능에 적용됩니다. 기능 문서에서 달리 정하지 않은 실행·보안 규칙은 공통 통제를 따릅니다.
- 공식 문서의 기능 지원, 해당 구독에서의 사용 가능 여부, 실제 업무 정확성은 서로 다른 검증 항목입니다.
- 이 보고서는 설계 결과물입니다. 제품 배포·외부 사이트 연동 완료 보고서가 아닙니다.
- 도식은 직접 작성한 SVG입니다.
- 원문 요구사항은 최초 기획안을 기준으로 했습니다.

## 확장성과 운영 한계

과정이 늘어난다고 매번 별도 시스템을 만드는 설계가 아닙니다. 같은 규칙·데이터 구조를 재사용하고, 처리 담당 프로그램의 수와 저장 용량을 늘립니다. 다만 어느 설계도 외부 사이트 변경·서비스 중단·AI 오판을 없애지는 못합니다. 이 보고서는 그 상황에서 **오류를 숨기지 않고, 잘못된 처리를 막고, 복구하고, 성능을 측정할 수 있는 구조**를 명세합니다.
