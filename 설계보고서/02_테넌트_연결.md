# 세 테넌트를 연결하는 방법

[문서 목록](00_보고서_안내.md)

[공통 구조](01_공통_아키텍처.md)

이 문서의 연결 방식은 공통 참고 기준을 따릅니다. 모델·리전·구현 일정은 테스트·운영에서 변경할 수 있으며, 실제 계정·권한 확인값의 주력 문서는 06입니다.

## 1. 쉽게 설명하면: 세 사무실을 연결하는 업무 데스크

`@msacademy`, `@elixirr`, `@dataschool`을 서로 다른 출입증을 쓰는 사무실이라고 생각하면 됩니다. 벽을 없애고 직원과 학생의 권한을 섞는 것이 아니라, 중앙 AI가 **각 사무실에서 허용한 업무용 출입증**으로 필요한 일만 합니다.



| 사무실 | 남겨둘 역할 | 중앙 시스템이 연결할 것 |
|---|---|---|
| `@msacademy` | Azure 운영·실습 | 운영 앱·DB·AI, 허용 구독의 사용량 |
| `@elixirr` | 직원 전용 업무 | Outlook 일정·업무 메일·직원 Teams |
| `@dataschool` | 교육 운영 | 강의 회의·학생/강사 Teams·교육 자료 |

**`@elixirr`에 Azure 리소스를 만들 필요는 없습니다.** 해당 조직의 일정과 Teams에 접근할 앱 권한만 준비할 수 있습니다.

Teams 자료는 사용자 제공 폴더 구조의 **수강생 팀 `일반`·기수별 운영 채널·강사팀**으로 나눠 연결합니다. 이는 세 테넌트와 다른 구분이며, 세 자료 영역마다 새 테넌트를 만드는 설계가 아닙니다. 수강생 파일은 `일반`에서만 공유하고, 운영 채널·강사팀 자료를 자동 공개하지 않습니다.

실제 Azure 화면에서는 회사 **엘릭서 구독**이 `msaischool.onmicrosoft.com` 디렉터리에 연결되어 있습니다. “엘릭서 구독”이라는 청구/관리 이름과 “`@elixirr` 회사 계정의 테넌트”는 다른 개념입니다.

## 2. 무엇을 합치고, 무엇을 분리하는가

- 합치는 것: 운영 화면, 과정·학생 연결 정보, 실행 요청, 진행 상태, 직원용 보고.
- 분리하는 것: 로그인 계정, 테넌트별 권한, 강의/사내 회의, 비밀값, 민감 자료 열람 범위.
- 복사하지 않는 것: 회사 전체 메일·대화, 다른 과정 자료, 권한 없는 녹화본.

같은 사람이 여러 계정을 갖더라도 내부 인물 번호와 각 조직의 계정 번호를 연결합니다. 메일 표시 이름이나 학생 닉네임만으로 자동 결합하지 않습니다.

## 3. 기본 연결 방식

테넌트마다 필요한 연결 앱을 등록하고 동일한 연결 프로그램에 설정합니다.

```text
중앙 업무: AI 5기 강사에게 안내
  → 대상 과정의 연결 설정 조회
  → @dataschool 테넌트용 인증 토큰 발급
  → 허용된 Teams 대화에 안내
  → 결과만 공통 DB에 저장
  → @elixirr 직원 화면에서 확인
```

- `@elixirr`: 직원 일정·메일용 앱. 직원 Teams 봇 연결은 해당 조직의 설치·동의 절차를 따릅니다.
- `@dataschool`: 교육 메시지·문서용 앱과 Teams 앱. 채널 수업 일정은 별도로 허용된 Teams 웹 실행 계정·로그인 정책을 확인합니다.
- `@msacademy`: 운영 프로그램의 관리 ID를 우선 사용합니다.
- **과정 종료 만족도 Forms:** Azure Logic Apps Consumption은 엘릭서 구독에 배치하고 Forms 연결은 권한 있는 `@dataschool` 조직 계정으로 최초 OAuth 인증합니다. Graph 앱 동의·관리 ID를 Forms 연결 인증과 혼동하지 않습니다. 설문 복제·링크 확보는 F19 브라우저 절차, 응답은 양식별 커넥터 트리거로 수집합니다. 다른 테넌트 구독에서의 API 연결·정책·인증 갱신은 실제 검증합니다([F06](기능/F06_만족도조사.md)).
- 서버는 연결 대상 테넌트를 명시해 토큰을 발급받습니다. 세 조직의 권한이 합쳐진 만능 토큰을 만들지 않습니다.
- 인증서/지원되는 연합 자격 증명을 우선 검토하고, 비밀값은 Key Vault에서 관리합니다. 운영자 비밀번호를 상시 보관해 대신 로그인하는 방식을 Graph의 기본 인증으로 사용하지 않습니다.

테넌트가 계속 추가될 경우, 연결 앱을 멀티테넌트 앱으로 전환해 설치 절차를 표준화할 수 있습니다. 이 경우에도 각 조직의 서비스 주체 생성·관리자 동의는 필요합니다.

## 4. 세 조직에 직접 설정할 내용 (관리자 권한 확보 완료)

세 계정(`@msacademy`, `@elixirr`, `@dataschool`) 모두 각 조직의 **Global Administrator** 권한이 확인되었으므로, 별도의 타 관리자 승인 대기 없이 아래 설정을 직접 구성하고 검증합니다.

| 대상 | 직접 설정할 내용 | 확인할 실제 동작 |
|---|---|---|
| `@msacademy` Azure | 운영 구독·배포 권한·정책·모델별 쿼터(06 CLI 조회 완료) | 운영 앱 배포 가능 범위, 모델/리전 목록 |
| `@elixirr` Entra/Exchange | 앱 등록 및 관리자 동의, 일정·발신 메일함 범위 지정 | 지정 일정 읽기/쓰기, 지정 발신자 배포 전 확인 |
| `@elixirr` Teams | 직원용 앱 설치·공지 채널 지정 | 운영국 경보·승인 카드 수신 |
| `@dataschool` Entra/Teams | 교육용 앱 동의·팀/채팅 설치·주최자 정책 | 메시지 수신·발송, 교육 회의·자료 접근 |
| `@dataschool` Forms / Azure Logic Apps 연결 | 과정 종료 시 1회 3항목 설문의 소유 계정·양식별 연결·조직 계정 OAuth·브라우저 세션 준비 | 같은 날 서로 다른 두 기수의 자동 준비·수집·집계, 익명 설정, 연결 만료 복구 |
| `@dataschool` SharePoint | 지정 교육 사이트 권한 | 교안·녹화·서류의 허용 범위 읽기/쓰기 |

**Azure 구독 Owner와 조직별 Entra Global Administrator는 서로 다른 테넌트 권한입니다.** 현재 `@msacademy`는 엘릭서 구독 Owner이자 해당 디렉터리의 Global Administrator이며, `@elixirr`와 `@dataschool` 역시 각 조직의 Global Administrator임이 확인되었습니다([06 실환경 확인 기록](06_실환경_확인기록.md) 참조). 단, 세 조직 모두 최고 관리자 권한을 보유하고 있더라도 에이전트에는 관리자 계정을 그대로 쓰지 않고 앱별 최소 권한만 부여합니다.

## 5. 권한 설계

| 작업 | 설계 기준 |
|---|---|
| 직원 캘린더 | Exchange Application RBAC로 필요한 메일함·일정 범위 설정. 엑셀 일정표 기반 **1개월 단위 수업 이벤트 일괄 생성/갱신** 및 범위 밖 접근 차단 확인 |
| 메일 발송 | 필요한 발신 메일함으로 제한. 메일 읽기 권한과 별도로 검토 |
| Teams 메시지 읽기 | 팀/채팅별 RSC가 지원하는 작업은 해당 범위 동의 사용. 채널·그룹채팅·회의채팅의 API와 권한을 구분 |
| Teams 알림 | 설치된 Teams 앱/봇의 대화 컨텍스트로 발송. Graph 일반 앱 권한이 모든 메시지 발송을 허용한다고 가정하지 않음 |
| 강사 구성원 관리 | 표준 채널은 팀 가입, 비공개·공유 채널은 유형별 가입 조건 확인. 공통 팀의 다른 기수 자료 열람 가능성을 기록하고 실제 구조 확인 후 사전 승인된 추가만 자동 수행. 기존 권한은 임의 회수하지 않음 |
| 교육 회의 생성 | 실제 채널 수업은 Teams 웹 일정의 컴퓨터 사용으로 1개월치 생성·수정. 일반 온라인 회의를 만들고 채널에 링크만 게시하는 것과 구분 |
| 녹취·참석·녹화 조회 | 회의 유형·주최자·자료 생성 상태별 권한 확인. 저장 완료된 분할 녹화를 조회하고 채널 수업 참석 CSV는 Teams 웹 일정에서 다운로드 |
| SharePoint 파일 읽기·결과 저장 | `Sites.Selected`와 실제 사이트 허용 범위 확인 후 Drive API로 저장된 파일 다운로드·파싱. 별도 결과 파일만 지정 폴더에 저장하며 Excel 셀·Word 원문 수정은 사람이 수행 |
| Azure 비용 | 대상 구독의 Cost Management 조회 역할. 리소스 변경 권한은 분리 |

정확한 요청 권한은 실제 API 선택 후 권한 목록으로 고정하고 허용·거부를 배포 전 확인으로 함께 점검합니다.

## 6. 엑셀 일정표 기반 1개월 단위 수업 이벤트 생성 및 수업방 강사 구성원 연결

1. 사람이 편집·저장한 수업 일정표를 읽고, 대상 연월(`YYYY-MM`) 1개월의 기수별·수업일별 강의 1개와 시작/종료 시각·날짜별 담당 강사를 검증합니다. 같은 날짜에 여러 기수가 운영되어도 각 기수의 일정·채널·수신자를 구분합니다.
2. 실제 팀·채널 유형과 기존 강사 접근을 조회합니다. 구조·권한 영향이 미확정이면 매니저 확인 대기로 두고, 사전 승인된 범위의 구성원 추가만 자동 수행합니다.
3. 현재 매니저가 일일이 만드는 채널 수업 이벤트를 **`@dataschool` Teams 웹 일정에서 컴퓨터 사용으로 생성·수정**합니다. 대상 팀·채널·주최자·날짜와 생성된 회의 링크를 확인합니다.
4. 생성 결과 확인 후 Graph로 `@elixirr` 운영 일정에 같은 수업의 시간·참가 링크를 기록합니다. 별개의 일반 온라인 회의를 중복 생성하지 않습니다.
5. 실제 회의 유형·회의 링크·Teams 일정 참조·조회 가능한 외부 ID·직원 Outlook 이벤트 ID·생성 월·강사·원본 버전을 DB에 연결합니다. 확인하지 못한 ID는 임의 생성하지 않습니다.
6. 수업 편성 변경은 원본 일정표 확인 후 해당 회차에 반영합니다. Teams 또는 Outlook 반영 실패는 부분 동기화로 표시하고 잘못된 안내를 보류합니다.
7. 같은 수업 참조로 분할 녹화([F10](기능/F10_영상_수업관찰.md))와 참석 CSV([F16](기능/F16_중간출결.md))를 수집합니다. 녹취가 없는 채널 수업을 일반 회의 API로 조회할 수 있다고 가정하지 않습니다.

**회의 유형 구분:** Graph의 `isOnlineMeeting=true` 이벤트나 독립 `onlineMeeting` 생성은 채널 회의 생성과 같지 않습니다. 수업은 실제 Teams 채널 일정 생성에 맞추고, 일반 온라인 회의를 쓰는 별도 행사는 유형을 명시해 지원 API를 선택합니다. 라이선스·정책·주최자 권한·로그인 세션·채널 선택 동작은 배포 전에 확인합니다.

**파일 구조와 연결 확인:** 제공받은 경로 예시는 KDT 폴더 구조를 기준으로 하되, 기수별 운영 채널의 소속 팀·채널 유형 및 테넌트·사이트·드라이브·폴더 ID·권한은 실제 대상에서 확인해 등록합니다. 강사팀 `출석부` 읽기와 운영 채널 `출석부` 결과 저장을 별도 범위로 지정합니다. 예시 이름은 테스트 및 운영을 하면서 바꿀 수도 있으며, 이름만으로 다른 기수나 외부 공유 위치를 추정하지 않습니다.

## 7. 직원 로그인과 Teams 탭

직원 대시보드는 `@elixirr` 로그인을 기준으로 합니다. 회사 Teams 탭에서도 같은 화면을 엽니다. `@dataschool`에 탭을 설치하는 경우에는 해당 계정과 직원 역할을 확인한 계정만 허용합니다. 교육 계정으로 로그인했다는 이유로 직원 운영 화면을 열어주지 않습니다.

다른 테넌트 간 SSO가 자동 완성된다고 가정하지 않고, 지원되는 OAuth 로그인/팝업 또는 회사 웹 로그인 경로를 검증합니다.

## 8. 연결 마법사의 완료 조건

`테넌트 식별 → 앱/인증서 등록 → 관리자 동의 → 리소스 지정 → 배포 전 확인 → 바로 정식 운영 활성화`

- 토큰 발급 성공만으로 연결 완료라고 표시하지 않습니다.
- 읽기·쓰기·범위 밖 거부·만료 처리를 배포 전 확인 항목으로 구분하고, 운영 중에는 실패 시 경보합니다.
- 연결 변경은 이후 작업에 반영하되 이미 승인된 외부 전송의 내용·대상을 바꾸면 재승인합니다.
- 연결이 끊기면 학생 잘못으로 처리하지 않고 운영 연결 장애로 알립니다.

## 9. Copilot Studio에서 권한을 요구했던 이유

Azure 리소스가 없는 계정도 아래 권한을 별도로 갖습니다.

| 영역 | 무엇을 결정하는가 |
|---|---|
| Azure RBAC | Azure 앱·DB·모델 같은 리소스의 생성/관리 |
| Entra 앱 등록·관리자 동의 | 앱이 Microsoft Graph 등 조직 데이터에 접근할 수 있는지 |
| Teams/Exchange 정책 | 앱 설치·메시지·회의·일정·메일 작업 허용 범위 |
| Power Platform 환경 역할 | 해당 환경에서 앱·에이전트·흐름을 만들 수 있는지 |
| Dataverse 보안 역할 | 환경 DB와 데이터에 접근할 수 있는지 |
| Copilot Studio 라이선스·용량 | 제작/관리 및 실행 과금 조건 |

이번 설계는 Azure 기반 직접 구현을 기준으로 하므로 Copilot Studio를 필수로 요구하지 않습니다. Copilot Studio를 선택하면 그 환경·라이선스·정책을 추가 확인합니다. 이전 오류의 정확한 메시지가 없으므로 어느 권한이 원인이었는지는 아직 확정하지 않습니다.

근거: [Copilot Studio 라이선스·접근](https://learn.microsoft.com/en-us/microsoft-copilot-studio/requirements-licensing), [Power Platform·Dataverse 역할](https://learn.microsoft.com/en-us/power-platform/admin/database-security)
