# F02. 모집·지원자·면접 기록

[전체 목록](../00_보고서_안내.md)

난이도: 2~3

## 목적

지원서와 인성·기술 면접 기록을 같은 사람에게 연결하고, 매니저가 근거를 찾아볼 수 있게 합니다.

## 입력·설정

Forms 지원서는 응답 화면에서 Excel로 다운로드한 파일을 받습니다. 파일 형식·파서·모델은 현재 조사한 구현 후보이며 실제 테스트·운영에서 결과를 보고 바꿀 수 있습니다. 원본 접수와 내용 추출 성공을 구분합니다.

지원자 Excel(또는 Forms 지원서 응답 다운로드 Excel), **비정형 지원서·자소서·포트폴리오 파일(아래아한글 `.hwp`/`.hwpx`, `.pdf`, 노션/웹 내보내기 `.html`/`.md`, `.docx`, `.pptx`, 이미지 등 조사한 지원 후보)**, 면접 일정, 면접관, **Teams/SharePoint에서 여러 면접관·매니저가 실시간 동시 편집하는 면접 평가 공유 엑셀**, 모집 과정, 열람 역할, 보관 기간. 실제 접수 가능 형식·한도는 설정으로 관리하고 추출 미지원·실패는 사람 확인으로 남깁니다. 합격·대기·불합격 상태는 담당자가 확정합니다.

## 처리 구조

**자료 위치 참고:** 운영 채널 구조 예시의 루트 합격자 명단은 입과 명단의 입력 후보이지 지원서·면접 평가 원본이 아닙니다. 지원서·면접 평가·AI 요약은 모집 담당자 제한 위치를 별도로 지정하고 수강생 팀 `일반`에 공개하지 않습니다. 기수·파일명은 참고용으로 바뀔 수 있으며 실제 ID·권한·컬럼을 확인한 뒤 연결합니다.

```text
파일/양식 접수 → 형식·중복·필수값 검사
→ 지원자 임시 기록 → 인물 매칭 확인
→ 원본 보관(SharePoint/Blob) + 형식별 비정형 텍스트·표 추출
  (.pdf·.html·.docx·.pptx·이미지는 R16 Content Understanding, .hwp·.hwpx는 서버 한글 파서/PDF 변환 후 추출 → PostgreSQL extracted_fields JSONB 저장)
→ Teams/SharePoint 면접 평가 공유 엑셀 연결
→ 인성·기술 면접관이 공유 엑셀에 동시 편집으로 점수·메모 입력 (또는 엑셀 업로드) → 에이전트가 저장된 버전의 파일을 Drive API로 다운로드·파싱해 취합·근거 요약
→ 입과 확정 시 수강 등록 생성
```

정형 값은 DB로, 원본은 SharePoint/Blob으로 저장합니다. 문서마다 양식이 다른 비정형 자소서·포트폴리오 항목은 PostgreSQL `document_versions.extracted_fields (JSONB)`와 `chunks`에 저장합니다.

## 리소스·권한

PostgreSQL, SharePoint/Blob, Container Apps, Foundry. 면접관·모집 담당자의 역할로 제한하며, 강사나 다른 과정 학생에게 평가 내용이 노출되지 않게 합니다.

## 저장·출력

`people`, `applications`, `interview_sessions`, `interview_scores`, `documents`, `enrollments`.

평가 필드: 작성자, 평가 시각, 질문/항목 버전, 점수, 관찰 메모, 원문 근거. AI 요약과 면접관 원문은 별도 필드입니다.

출력: 지원자 카드, 면접 일정, 인성/기술 평가표, 누락 자료 목록, Excel 내보내기. 표준 엑셀 시트 컬럼과 샘플은 09 데이터 컬럼·엑셀 양식을 따릅니다.

## 예외·승인

- 동명이인·같은 연락처·여러 계정은 자동 병합하지 않고 확인합니다.
- 추출 실패 자료는 원본 상태로 보관하고 수동 확인을 요청합니다.
- AI가 합격·불합격을 확정하거나 개인의 성격을 사실처럼 추론하지 않습니다.
- 등록 전 탈락자 자료도 정해진 보관 기간을 적용합니다.
- 기업 제공·외부 면접관 제공은 허용 목적과 접근 기간을 확인합니다.

## 운영 품질 기준

동명이인과 복수 지원을 분리하고, 입과 후에도 면접 원문이 올바른 수강생과 연결되어야 합니다. 추출된 점수·연락처를 원본과 표본 대조하고, 권한 없는 계정의 조회는 차단되어야 합니다.

## 근거·연관

[공통 데이터](../04_데이터_권한_복구.md), [Content Understanding](https://learn.microsoft.com/en-us/azure/ai-services/content-understanding/overview)
# F03. OT 준비·공통 체크리스트

[전체 목록](../00_보고서_안내.md)

난이도: 2~3

## 목적

OT 식순·장소·식사·도시락·노트북·동의서·명찰을 담당자와 기한이 있는 업무로 관리합니다. 운영진은 공유 엑셀·워드를 공동 편집하고 에이전트는 저장 파일을 다운로드·파싱합니다. 수강생은 매니저가 게시한 Forms에 응답하며 응답 화면에서 Excel로 다운로드한 파일을 에이전트가 수집합니다.

## 입력·설정

OT 일정, Teams/SharePoint에서 **실시간 동시 편집하는 `OT 준비 체크리스트` 공유 엑셀** 및 입과생 명단 공유 엑셀, 수강생 제출용 **Microsoft Forms 동의서와 응답 화면에서 다운로드한 Excel**, 항목별 담당자·승인자, 선행 작업, 마감일, 재안내 횟수, 완료 증거.

예: “도시락 수량 확정은 참석 인원 확정 후”, “명찰은 이름 검수 후 출력”.

**폴더 매핑 예시:** KDT 폴더 구조의 수강생 `일반 / 01. OT`는 학생 배포용 Orientation·LMS 안내이고, 운영 채널 루트 OT 자료 및 `운영관리 매뉴얼 / 각종양식`은 내부 참고 자료입니다. 내부 체크리스트·동의 결과·명찰 원본의 실제 위치는 별도 지정합니다. 예시 목록에 체크리스트가 이미 존재하거나 권한·서명이 검증됐다고 가정하지 않습니다. 이름·날짜·파일 구성은 테스트 및 운영을 하면서 바꿀 수도 있습니다.

## 처리 구조

```text
과정 시작일·OT 일정 확정
→ 확인된 내부 기수 채널에 체크리스트 별도 파일 생성/연결 (원본 공동 편집은 운영진)
→ 항목·담당자·기한·선행조건 자동 인식 및 직원 Teams 알림 예약
→ 운영진이 상태·수량·장소를 수정·저장하면 버전 확인·다운로드·파싱으로 집계 갱신
→ 매니저가 동의서 양식·동의/서명 요건 확인·게시·링크 등록 → Teams 안내 → Forms 응답 → 매니저가 Excel 다운로드·전달 → 파일 수집
→ 완료 검사 및 미완료·지연 항목 대시보드 표시, 미제출 수강생 Teams 재안내
```

자연어로 새 항목을 요청하거나 공유 엑셀에 행을 추가하면 기존 업무 등록 도구가 자동으로 읽어 반영합니다. 등록된 컬럼·규칙 범위는 설정으로 반영합니다. 원본 문구 수정은 사람이 수행하고 새 추출 형식·동작은 개발·검증합니다.

## 리소스·권한

PostgreSQL, Durable Functions/Task Scheduler, Service Bus, Teams 앱, **Microsoft Graph Drive API(저장 파일 읽기·별도 결과 파일 저장)**, Microsoft Forms/SharePoint(다운로드 응답 Excel 보관·수집), 필요 시 Outlook. 직원 알림은 `@elixirr` 또는 `(주)엘릭서`, 강사·학생 안내는 `@dataschool`의 연결된 교육 채널을 선택합니다.

## 저장·출력

`checklist_templates`, `tasks`, `task_dependencies`, `task_evidence`, `work_runs`.

출력: 진행률, 담당자별 할 일, 명찰 인쇄 파일(`[기수명] 성명` 자동 배치), 동의서 제출 현황 집계(Forms/엑셀 연동 기준), 장소 안내 메시지 자동 치환본, 미준비 항목 Excel. 엑셀의 행마다 안정적인 항목 ID를 부여해 재수입 때 중복을 막습니다. 예시 엑셀 컬럼과 샘플은 09 데이터 컬럼·엑셀양식을 따릅니다.

## 예외·승인

- 알림 발송 성공을 “도시락 준비 완료”로 간주하지 않습니다.
- 담당자 없음·장소 미정은 차단 상태로 표시합니다.
- OT 일정 변경은 마감일·예약을 함께 재계산합니다.
- 구매·계약·대금 지출은 매니저 승인 정책을 따릅니다.
- 동의서 버전이 바뀌면 기존 서명 유효성을 자동 단정하지 않습니다.
- Forms 응답은 매니저가 필요한 서명 요건을 확인하기 전 전자서명 완료로 간주하지 않습니다. 다운로드 시각 이후 응답은 다시 Excel로 내려받아 반영하며 응답 ID로 중복을 제거합니다.

## 운영 품질 기준

새 체크리스트 항목을 자연어로 추가하고 다음 기수 템플릿으로 재사용할 수 있어야 합니다. 선행 항목 미완료와 단순 지연이 구분되어야 하며, 일정 취소 후 재안내가 나가지 않아야 합니다.
