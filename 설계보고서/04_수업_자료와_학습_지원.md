# F07. 교안·오전 녹화 기반 퀴즈 초안·검수·배포

[전체 목록](00_보고서_안내.md)

난이도: 3

## 목적

당일 교안과 **처음 저장 완료된 오전 수업 녹화·녹취**를 바탕으로 오후에 낼 복습 퀴즈의 문항·정답·해설을 자동 작성합니다. 강사/매니저가 검수하고 **사람이 Microsoft Forms 게시·정답/배점 설정·링크 등록**을 마치면 Teams로 배포·집계합니다.

한 기수의 하루 수업 일정은 1개입니다. 여러 날에 걸친 강의 단위는 별도 ID로 묶습니다. 아래 오전·오후 구간은 같은 하루 강의의 내부 시간 구간이며, 여러 기수가 같은 날 운영되면 교안·녹화·퀴즈를 기수·수업일별로 구분합니다.

## 입력·설정

당일 과목·회차·교안 버전(PDF·PPT·Word·HTML·Markdown·HWP/HWPX 등), 확인된 진도·학습 목표, 오전 분할 녹화·녹취, 담당 강사별 시간대·검수자, 문항 수(예: 20개)·난이도·유형, 초안 마감·배포 시각·응답 기한·채점 방식.

하루 **3~4개로 나뉘어 저장되는 녹화 중 해당 회차의 오전 구간이 저장·분석 완료됐는지** 확인합니다. 하루 전체 수업 종료를 기다리는 방식이 아니며, 오후 내용을 미리 확인한 것으로 취급하지 않습니다. “수업 종료 1시간 전”과 “매시간”은 별도 규칙으로 설정합니다.

**자료 위치 예시:** 폴더 구조의 수강생 `일반 / 05. 강의자료`와 `일반 / Recordings / 월 / 주차 / 일자`를 회차·강사·파일 버전으로 연결합니다. 강사팀 `중간평가문제`는 강사별 중간평가 자료이며 일일 퀴즈 초안·정답·응답 결과의 공용 저장소로 가정하지 않습니다. 검수본·정답·개인 응답의 제한 위치는 별도 지정하고 학생에게는 게시된 Forms 링크만 안내합니다. 경로·날짜·파일명·세부 구성은 테스트 및 운영을 하면서 바꿀 수도 있으며 실제 ID·권한은 확인 전입니다.

## 처리 구조

```text
교안·회차·강사별 시간대·확인된 진도 확인
→ F10에서 오전 첫 저장 완료 구간·녹취 수집·분석 상태 확인
→ 확인된 학습 범위로 문제·정답·해설·근거 초안 생성
→ 문항 수·중복·정답 형식·출제 범위 검사
→ 담당 강사/매니저에게 검수용 Excel 및 가져오기용 Word/PDF 전달
→ 사람이 검수·수정, Forms 생성/가져오기 검토·정답/배점 설정·게시
→ 게시 링크·양식 버전 등록 및 대상 학생의 응답 가능 여부 확인
→ 예약 시각에 해당 기수 Teams로 링크 안내
→ 매니저가 Forms 응답 화면에서 Excel 다운로드·전달 → 에이전트 수집·채점·복습 자료 제공
```

**Forms Quick Import는 로컬 Word/PDF(10MB 이하)의 선택형·텍스트형 위주 변환**입니다. Excel은 검토·집계용이며 문제 시트를 그대로 가져오는 기능으로 설명하지 않습니다. 변환 결과·정답·배점은 사람이 확인합니다. 별도 학생용 퀴즈 사이트는 만들지 않습니다.

다운로드한 응답 Excel은 해당 시점의 사본입니다. 새 응답은 다시 다운로드하고 양식 버전·응답 ID로 중복을 제거합니다. 모델·지원 형식·파서 후보는 실제 테스트·운영에서 품질·비용·추출 결과에 맞게 변경하며, 강사 검수·정답/배점·게시 확인은 유지합니다.

## 리소스·권한

Foundry, PostgreSQL/벡터 검색, SharePoint/Blob, Teams/Microsoft Forms, Durable Functions. 강사·매니저는 담당 문항을 검수하며 학생은 게시 전 문항·정답에 접근하지 못합니다.

## 저장·출력

`quiz_versions`, `questions`, `answer_keys`, `source_references`, `quiz_attempts`, `form_versions`.

교안 버전·페이지, 녹화 파일·구간 시각·분석 상태, 사용한 진도 범위, 검수자·검수 버전, 게시 담당자·완료 시각·Forms 링크·양식 버전·응답 파일 수집 상태를 기록합니다. 검수 완료와 게시 완료는 별개입니다.

## 예외·승인

- 오전 녹화 저장·권한·분석이 늦으면 담당자에게 알리고 **교안과 확인된 진도만으로 초안**을 만들며 녹화 미반영 범위를 표시.
- 교안 없음·실제 진도 불명확: 생성 대기. 없는 구간의 발언·내용을 만들어내지 않음.
- 강사 미승인·정답/배점 미설정·미게시·잘못된 링크: 배포 보류. 사람 작업 시간을 배포 전에 확보.
- 멘토링·중간평가·방학은 일정 분류에 따라 정규 퀴즈 생략 가능.
- 게시 후 오답: 정정·재채점 이력과 학생 안내. 서술형 AI 채점은 피드백 보조.
- 퀴즈 미참여를 수면·불성실·공식 결석으로 자동 환산하지 않음.

## 운영 품질 기준

설정 문항 수·유형과 실제 확인된 학습 범위를 지키고 모든 문항에 근거·정답을 연결합니다. 녹화 지연을 숨기지 않고, 미검수·미게시 문항은 발송하지 않습니다.

## 근거·연관

[F05](02_과정_설정과_일정_운영.md#f05) 일정, [F10](#f10) 분할 녹화, [Forms Word/PDF 가져오기](https://support.microsoft.com/en-us/forms/convert-a-word-or-pdf-form-or-quiz-to-microsoft-forms)

# F08. 수업 질문·답변 취합

[전체 목록](00_보고서_안내.md)

난이도: 3

## 목적

수업 중 질문과 실제 답변을 수업 회차·과목 단위로 자동 정리하고, 미답변 항목은 **캘린더상 당일 해당 과목/시간대를 담당한 강사**에게 정확히 전달합니다.

## 입력·설정

허용된 교육 Teams 채널(`{과정명} {기수} 수강생 팀 > 03. 교육문의 게시판` 및 `일반` 실시간 수업 회의채팅), 수업 ID·강사별 실제 시간대, 교안, 각 녹화 구간 저장 후 생성된 녹취, 요약 시각, 공개 범위, 미답변 기한, 강사 전달 채널(`강사팀 > {기수} 강사팀` 또는 강사 개인 채팅).

**파일 위치 예시:** KDT 폴더 구조의 수강생 `일반 / 05. 강의자료`·`Recordings / 월 / 주차 / 일자`를 참고합니다. 교육문의 게시판은 질문·안내용이며, 학생용 Q&A 파일을 공유한다면 `일반` 안의 지정 위치에만 저장합니다. 내부 검토본·상담 내용은 공개본과 분리하고, 예시에 없는 Q&A 폴더를 이미 존재한다고 가정하지 않습니다. 파일명·날짜·구성은 테스트 및 운영을 하면서 바꿀 수도 있으며 실제 ID·권한은 별도 확인합니다.

## 처리 구조

```text
권한 있는 메시지·녹취 수집
→ 수업·시각·발신자 연결
→ 질문과 답변 후보 연결
→ 비슷한 질문 묶기
→ 실제 답변 / 답변 미확인 / AI 보조 초안 구분
→ 원문 링크가 있는 정리본 생성
→ 강사 확인·배포
```

## 리소스·권한

Graph/Teams, Foundry, PostgreSQL, SharePoint/Blob, Durable Functions. 회의 녹취는 생성·정책·주최자·API 권한을 확인합니다. 일반 Graph 녹취 경로를 수업 중 실시간 음성 수집으로 설명하지 않습니다.

F10의 실제 회의 참조·저장 파일·분석 구간을 재사용하고 수집 가능한 채팅·녹취 범위만 정리합니다. 채널 수업과 일반 회의의 지원 API를 혼용하지 않습니다.

## 저장·출력

`source_messages`, `transcript_references`, `qa_items`, `qa_summaries`, `tasks`.

출력: 오늘의 Q&A, 미답변 항목, 강사 확인 목록, 원문 시각/링크. 민감한 상담 내용은 학급 전체 요약에서 제외합니다.

## 예외·승인

- 답변 연결이 모호하면 “미확인”으로 남김.
- AI가 생성한 설명을 실제 강사 발언처럼 표시하지 않음.
- 채팅 일부 누락·녹취 미생성을 요약 범위에 표시.
- 메시지 편집·삭제는 원천 정책과 보관 목적에 따라 반영.
- 강사가 공개하지 않은 내용을 자동 전체 공유하지 않음.

## 운영 품질 기준

요약 항목에서 실제 원문으로 이동할 수 있어야 합니다. 질문에 답하지 않은 발언이 정답으로 잘못 연결되지 않도록 운영 중 표본 검사하고, 수집 범위 밖 내용을 취합 완료로 표시하지 않아야 합니다.

## 공식 근거

[Teams 녹취·녹화 조회](https://learn.microsoft.com/en-us/microsoftteams/platform/graph-api/meeting-transcripts/overview-transcripts), [callTranscript](https://learn.microsoft.com/en-us/graph/api/resources/calltranscript?view=graph-rest-1.0)

# F10. 녹화본 접근·수업 관찰 보조

[전체 목록](00_보고서_안내.md)

난이도: 5 · 실제 영상·정책·정확도 검증 필요

모델·분석기·리전·영상 구간과 비용은 현재 조사 기준의 참고 후보이며 실제 테스트·운영에서 변경할 수 있습니다. 지원 가능 정보와 실제 검증 기록은 구분하고, 변경해도 아래 관찰 한계·접근 통제·사람 확인 원칙은 유지합니다.

## 목적

강의 녹화본을 API 또는 컴퓨터 사용으로 열어, **관찰할 수 있는 장면과 확인이 필요한 구간**을 시각·근거와 함께 매니저에게 제공합니다.

“API로 어려우면 컴퓨터 사용으로 볼 수 있는가?”에 대한 답은 **허용된 화면을 재생·탐색하는 경로는 가능하지만, 자료에 없는 화면이나 모호한 사람 상태까지 알아낼 수는 없다**입니다.

> **[현실적 한계와 활용 범위 — 왜 학생 개별 감시용이 아닌가]**
> 1. **Teams 녹화본의 구조적 한계:** 하루 8시간 수업 녹화본은 용량이 크고, Teams 녹화 화면에는 **발표자(강사 화면 공유) + 발언자 1~4명 정도만 작게** 찍힙니다. 즉 녹화 영상만으로는 **수강생 30명 개개인이 그 시각에 졸았는지·자리에 있었는지를 알아내는 것이 물리적으로 불가능**합니다(Teams가 모든 학생의 웹캠 원본을 개별 녹화하지 않기 때문).
> 2. **원본 기획안(3-4, 3-5) 대비 변경 사유:** 원본 기획안에는 *"녹화본과 채팅을 입체적으로 봐서 참여도가 낮은 사람 Top 3를 뽑거나, 카메라 꺼진 사람·자는 사람에게 에이전트가 자동으로 경고를 보낸다"*고 기재되어 있습니다. 하지만 화면에 안 찍힌 학생이나 필기하느라 고개를 숙인 모습·네트워크 장애를 AI가 '수면'이나 '고의적 카메라 꺼짐'으로 오판해 자동 경고를 보낼 경우 심각한 민원이 발생합니다.
> 3. **본 설계의 현실적 역할:** 따라서 학생 태도 순위 산출과 AI 자동 경고 발송은 제외하고, **① 당일 수업 녹화·녹취가 정상 생성되었는지, ② 강사 화면 공유·교안 표시·음성 송출 사고가 없었는지, ③ 오전/당일 수업 녹화·녹취에서 다룬 내용을 요약해 일일 퀴즈([F07](#f07))·Q&A([F08](#f08)) 생성에 활용하고, 확인이 필요한 구간과 시각만 매니저에게 요약 제공**하도록 설계했습니다.



한 기수의 하루 수업 일정은 1개이며, 하루 3~4개 녹화는 그 강의의 분할 저장 파일입니다. 같은 날 여러 기수가 운영되므로 기수·수업일·일정 참조로 녹화를 구분하고 녹화 개수를 강의 수로 세지 않습니다.

## 입력·설정

수업·녹화 ID, 허용된 파일/재생 링크, 영상 시간 범위, 관찰 항목, 표본 추출 간격, 확인 담당자, 비용/보관 한도, 접근 목적.

기본 관찰 항목: 녹화/음성 누락, 화면 공유 상태, 교안 표시, 명시적 기술 장애, 영상에서 확인 가능한 참여 장면. 개인별 확인은 확실한 수업 계정/표시 정보가 있을 때만 연결합니다.

**저장 위치 예시:** 수강생 팀 폴더 구조의 `일반 / Recordings / [YY년 MM월] / [N주차 (MMDD ~ MMDD)] / [MMDD]`를 참고합니다. 폴더·날짜 규칙은 테스트 및 운영을 하면서 바꿀 수도 있습니다. 이 계층이 있다는 것만으로 Teams가 파일을 해당 위치에 자동 정리했거나 녹화·녹취가 생성 완료됐다고 판단하지 않습니다. 실제 저장·정리 방식과 파일 ID·권한·수업·구간 시각을 확인합니다. 운영 채널·강사팀 `출석부`와는 월/주차/일자 계층만 유사하며 서로 다른 자료입니다.

## 처리 구조

```text
하루 3~4개 분할 녹화의 각 구간 종료·저장 완료 확인
→ 권한 있는 Graph/SharePoint 파일 접근 우선
→ 해당 경로가 업무상 부적합하고 화면 접근이 허용되면 브라우저/PC 재생
→ 영상 시각·화면 유형·관찰 가능 범위 확인
→ 허용 구간/프레임 추출
→ 이미지/영상 분석으로 관찰 사실과 불확실성 기록
→ 오전 첫 저장 완료 구간의 확인된 학습 내용을 오후 퀴즈(F07) 근거로 연결
→ 담당자 확인
→ 필요한 상담·확인 업무 생성
```

브라우저 경로에서는 사이트·수업명·영상 ID·재생 위치를 검증합니다. 플레이어 로딩 실패나 버퍼링 상태를 수업 장면으로 분석하지 않습니다.

녹화가 하루 전체 종료 후에만 수집되는 것으로 설계하지 않습니다. 오전 첫 저장본도 해당 수업·구간·저장 완료·분석 완료를 확인한 뒤 활용합니다. 녹화·녹취가 늦으면 F07에 지연 상태를 전달하고, 교안과 확인된 진도만 사용하거나 진도 확인까지 대기합니다.

## 리소스·권한

- Graph/SharePoint: 허용된 녹화·녹취 접근.
- Foundry Browser Automation: 웹 플레이어 탐색.
- 전용 Windows/PAD 또는 computer use: 브라우저 밖 조작이 필요한 경우.
- Foundry의 지원 이미지 입력 모델 또는 Content Understanding: 허용 프레임/영상 구간 분석.
- Blob/PostgreSQL: 제한된 증거와 관찰 메타데이터.

Content Understanding은 영상에서 사용자 정의 정보를 추출하는 도구이지 “불량 태도 판정기”가 아닙니다. 선택 분석기·모델·지역과 평가 데이터가 필요합니다. 얼굴 인식으로 신원을 확정하는 기능은 기본 범위에 넣지 않습니다.

## 관찰과 판정의 구분

| 상황 | 기록할 내용 | 하면 안 되는 결론 |
|---|---|---|
| 녹화가 발언자·화면 공유만 보여줌 | 다른 학생은 관찰 불가 | 화면에 없는 학생은 카메라를 껐음 |
| 학생 타일이 일시적으로 보이지 않음 | 해당 구간에서 확인 불가 | 결석·자리 이탈 확정 |
| 고개를 숙이거나 눈이 감긴 장면 | 필요 시 담당자 확인 구간 | 수면·불성실 자동 확정 |
| 앱/카메라 연결 문제 | 기술적 확인 필요 | 규정 위반 확정 |
| 명시된 체크인에 미응답 | 별도 응답 기록 확인 | 영상만으로 공식 출결 변경 |

카메라 꺼짐 여부도 UI에서 명확하게 관찰되는 상태인지 먼저 확인합니다. 화면 배열·타일 이동·이름 중복으로 다른 학생에게 연결하지 않습니다.

## 저장·출력

`media_assets`, `media_observations`, `review_tasks`, `case_evidence`.

관찰 레코드: 수업 참조·원본 ID/버전, 녹화 구간 시작/끝, 저장 완료·수집/분석 시각·상태, 화면 유형, 관찰 범위, 원문 근거, 사실 설명, 식별 확실성, 관찰 불가 사유, 분석 버전, 사람 검토 결과. F07에 전달한 근거 구간을 따로 기록합니다.

출력: 시간대별 확인 목록·원본 바로가기·영상 누락 상태. 학생 전체의 태도 순위는 출력하지 않습니다.

## 예외·승인

- 녹화·접근 권한이 없으면 중단. 컴퓨터 사용은 권한 우회 수단이 아님.
- 녹화/다운로드 제한을 우회하는 화면 캡처·재녹화를 하지 않음.
- 전체 학생이 매 순간 녹화되는 것으로 가정하지 않음.
- 영상 기반 개인 경고는 자동 전송하지 않고 담당자가 사실·예외를 확인.
- 이 기능은 저장된 녹화 구간을 처리하며 수업 중 실시간 학생 감시로 설명하지 않음.
- 표본 관찰은 전체 수업을 검증했다는 의미가 아님.

## 운영 품질 기준

화면 공유·발언자 모드·갤러리·저화질·타일 이동·동명이인·버퍼링 상황에서도 기준을 지켜야 하며, 운영 중 이런 상황을 자동 표시해 측정합니다. 관찰 불가 학생을 불량으로 분류하지 않아야 합니다. 모든 확인 항목은 올바른 원본 시각으로 이동해야 하며 담당자 판정과의 차이를 측정합니다.
