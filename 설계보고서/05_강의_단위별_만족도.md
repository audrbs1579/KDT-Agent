# F06. 강의 단위 종료 시 Forms 만족도 자동화

[전체 목록](00_보고서_안내.md)

운영 단위 정정: 2026-10-28 사용자 설명 반영 · 난이도 3(문항·집계)/4(양식 준비·인증·수집 연결)

## 목적과 운영 범위

**한 기수 안에서 며칠에 걸쳐 진행되는 각 강의가 끝날 때마다 객관식 2개·주관식 1개의 Microsoft Forms 만족도를 1회 받습니다.** 에이전트는 승인 템플릿의 준비·링크 확보·종료 후 안내·응답 수집·집계·의견 요약·결과 보관을 자동 실행하도록 개발합니다.

**운영 단위:** `course_id`는 KDT 과정의 한 기수, `teaching_unit_id`는 그 안에서 며칠에 걸쳐 진행되는 한 강의, `session_id`는 하루 수업 일정입니다. 강의 단위에는 시작일·종료일·강사/보조강사·관련 일별 일정을 명시합니다. 같은 과목명·강사명이나 날짜만으로 강의 경계를 추정하지 않으며, 한 강의가 월을 넘어도 같은 ID를 유지합니다.

예: A기수의 Python 강의가 10월 5~9일이면 9일 마지막 수업 종료 확인 후 1회, 이어지는 데이터 분석 강의가 12~16일이면 16일 종료 확인 후 별도 1회입니다. A기수 자체는 계속 운영 중이어도 앞 강의의 설문은 실행합니다. 매일 수업이 끝났다는 이유만으로 발송하거나 기수 전체가 끝날 때까지 기다리지 않습니다.

한 기수의 수업일당 일정 1개·여러 기수 동시 운영 기준은 유지합니다. 특강·멘토링 등은 운영 설정에서 강의 단위 및 만족도 사용 여부를 지정한 경우 같은 3항목 절차를 적용하며, 행사 종료만으로 별도 설문을 임의 생성하지 않습니다. 퀴즈·참가 신청·동의서는 별도 업무입니다.

## 입력·설정

`course_id`, `teaching_unit_id`, 과정명·기수·강의명, 강의 시작/종료일·마지막 `session_id`/종료 시각·시간대·종료 확인 상태, 해당 강의 강사·보조강사 목록, 만족도 On/Off, 대상 명단 버전/인원, 문항 버전·익명/기명·1인 1응답·응답 기한·재안내 규칙·공개 최소 인원, Forms 소유 조직/계정·form_id·응답 링크·question_map·workflow_id·연결 상태를 등록합니다.

생성·기본 발송 키는 `course_id + teaching_unit_id + lecture_completion_survey`입니다. 같은 기수의 다음 강의는 별도 ID·양식·집계로 구분합니다. 종료일·강사·마지막 수업·문항 버전 변경과 재시도는 기존 강의의 양식/예약을 갱신하며 중복 설문을 만들지 않습니다. 재안내는 같은 링크를 사용합니다. 강의 구간이 없거나 경계가 모호하면 담당자 확인 대기입니다.

## 문항 — 객관식 2개·주관식 1개

기존 양식의 준비도·설명/전달력 두 항목과 자유 의견 한 항목을 유지하고 평가 대상을 해당 강의 단위로 표시합니다.

| 항목 ID | 문구 | 형식·필수 여부 |
|---|---|---|
| Q1 `preparation` | 이번 [강의명]의 교안과 수강 자료가 알차게 구성되었으며, 전체적인 강의 준비가 잘 이루어졌다고 느끼셨나요? | 5점 선택형·필수 |
| Q2 `clarity` | 이번 [강의명]에서 강사의 설명이 명확하고 이해하기 쉬웠으며, 수업 내용이 효과적으로 전달되었나요? | 5점 선택형·필수 |
| Q3 `comment` | [강의명]에서 가장 좋았던 점이나 보완이 필요한 점 또는 개선 의견이 있으면 자유롭게 적어주세요. | 장문 주관식·기본 선택 |

선택지는 `매우 그렇다(5) / 그렇다(4) / 보통(3) / 아니다(2) / 매우 아니다(1)`입니다. 선택형 표 두 행과 주관식 입력란 하나로 총 3항목입니다. 기수·강의명·담당 강사·기간은 제목/설명에 표시하고 추가 질문으로 받지 않습니다. 제목 예시는 `[과정명] [기수] [강의명] 강의 만족도 조사`입니다. 공동 강의의 점수를 강사별로 임의 분할하지 않으며 강의와 담당자 매핑을 함께 보여줍니다.

## 처리 구조

```text
최초 템플릿·권한·규칙 승인 + 기수 내 강의 단위/마지막 수업 등록
→ 해당 강의의 만족도 On/Off·기존 양식/발송 여부 확인
→ 강의 단위별 승인 템플릿 준비·기수/강의명/강사/기간 치환(F19)
→ 3항목·선택지·응답 설정·form_id·링크·문항 매핑 확인
→ 해당 form_id의 Logic Apps 수집 워크플로 연결·확인
→ 해당 강의의 마지막 수업 종료·종료 확인 상태 재확인
→ 해당 강의 수강생의 교육 Teams 채널로 기본 안내 1회(강사·보조강사·회사 직원 준비 채팅과 구분)
→ Forms 새 응답 → 상세 조회 → Service Bus → 점수 검증·중복 제거·DB 저장
→ 같은 링크로 허용된 재안내 → SQL 집계 + AI 주관식 요약
→ 강의 단위별 대시보드·집계 Excel/요약 보관
```

강의 중간 일자에는 발송하지 않습니다. 마지막 날이 연기·취소되면 미발송 예약을 갱신합니다. 같은 기수의 이전/다음 강의·다른 기수 자료가 섞이지 않게 하며, 기존의 잘못된 기수 전체 종료 전용 예약은 강의 단위 매핑을 확인한 뒤 이관합니다. 실제 강의 종료가 아니라 단순 날짜 변경으로 새 설문을 추가하지 않습니다.

## 실행 경로와 실현 가능성

| 구간 | 구현 경로 | 검증할 조건 |
|---|---|---|
| 표준 양식 준비 | F19 Playwright로 승인 Forms 복제·제목/설정·링크 검사 | 공식 Forms 커넥터가 생성/복제 액션을 제공한다고 가정하지 않음. UI·로그인·정책·문항 ID 확인 |
| 응답 자동 수집 | Logic Apps Consumption Forms 새 응답 트리거·상세 조회, Service Bus 전달 | 교육 조직 계정 OAuth·양식별 연결·실제 응답 구조 확인 |
| 강의별 연결 | 승인 Azure 템플릿에 form_id 지정 | 새 양식 자동 감지를 가정하지 않고 배치·연결 재사용·시험 응답 검증 |
| 강의 종료 후 1회 | teaching_unit_id·종료 조건·고유 실행 키·발송 이력 | 중간 일자 차단, 같은 기수의 연속 강의·다른 기수·월 경계·일정 변경 분리 |
| 결과 | PostgreSQL/SQL·Foundry·SharePoint 별도 파일 | 점수·응답 수·요약 근거·권한·복구 대조 |

Logic Apps는 기존 Azure 운영 구독에 두고 Forms 연결에는 권한 있는 교육 조직 계정으로 최초 OAuth 인증합니다. Managed Identity·Graph 앱 동의를 Forms 인증과 동일하게 보지 않습니다. 수집 연결 확인 전 발송을 차단합니다. Excel 다운로드는 장애 복구·과거 응답 보충·대조용이며 정상 운영마다 사람 다운로드를 요구하지 않습니다. 양식 수·커넥터 한도·비용은 기수 수만이 아니라 종료한 강의 단위 수와 응답 수 기준으로 산정합니다.

**실현 가능성:** 양식 준비까지의 무인화는 UI·인증·강의별 연결·종료 조건을 실제 환경에서 검증해야 하는 조건부 설계입니다. 이번 문서 정정을 자동화 성공·실배포 기록으로 보지 않습니다.

## 저장·출력

`teaching_units`, `unit_instructors`, `form_versions`, `survey_instances`, `survey_bindings`, `responses`, `response_items`, `survey_summaries`.

- course_id·teaching_unit_id·강의명·기간·강사 목록·마지막 session_id·종료 확인·대상 명단 버전·양식/문항 버전·form_id·question_map·workflow_id·응답 링크·수집/발송 상태.
- 기본 발송 키 `course_id + teaching_unit_id + lecture_completion_survey`, 응답 고유 키 `tenant_id + form_id + response_id`. 양식과 강의의 매핑을 검증하고 재시도·복구 파일은 중복 계산하지 않음.
- Q1/Q2 평균·5점 분포·두 항목 평균·유효 응답 수·Q3 요약과 원문 근거. 주관식 공란은 유효 응답이고 점수 평균에서 제외.
- 응답률 분모는 해당 강의 대상 명단 인원. 익명에서 1인 1응답 보장이 불명확하면 응답 건수와 대상 인원을 구분.
- 운영 채널 `중간평가 및 설문`에 기수·강의 단위·양식 버전을 식별한 결과 Excel/요약을 저장. 같은 기수의 다음 강의 결과를 덮어쓰지 않음.
- 화면은 강의별 결과와 기간·담당자·응답 수·기준 시각을 표시. 동일 문항·척도일 때 비교하고, 여러 날 강의의 한 설문을 일별 응답이나 공동 강사의 개인 점수로 분해하지 않음.

## 예외·사람 역할

최초 문항·권한·공개 범위·규칙 승인, 강의 경계/담당자 확인, 인증 복구·중요 개선 결정은 사람이 맡습니다. 익명 응답은 학생 신원·출결과 결합하지 않고 개인 미응답 명단을 만들지 않습니다. 소수 집계·개인 사유 공개 범위를 제한합니다. 발송 결과 불명 시 기존 결과를 대조합니다. 낮은 점수만으로 강사/학생 제재를 자동 결정하지 않습니다.

## 검증 시나리오

1. 같은 A기수의 Python 강의 종료 후 1회, 다음 데이터 분석 강의 종료 후 별도 1회. 기수 전체 종료 전에도 각각 실행.
2. 여러 날 강의의 중간 일자에는 미발송, 마지막 수업 종료 확인 후에만 발송.
3. 같은 기수·같은 강사·같은 강의명이라도 서로 다른 명시적 강의 단위는 구분. 강사 교체·일정 연기·월별 일정 발행·재시도로 동일 강의를 복제하지 않음.
4. A/B기수와 연속 강의의 form_id·수집 연결·응답이 섞이지 않음.
5. 객관식 2개·선택 주관식 1개, 점수 매핑·공란·중복·오류·원본/집계 일치 확인.
6. UI/OAuth/수집 단절을 응답 0건으로 표시하지 않고 복구·대조 이력 보존.
7. 노트북 종료 상태 실행·사람 개입·시간·비용 기록. 기수 전체 종료 전용의 기존 잘못된 예약 이관 확인.

## 근거·연관

이번 정정은 사용자가 설명한 강의 단위와 문항 수를 반영한 설계 수정이며 새로운 실환경 검증이 아닙니다. 제품 기능 조사 기록과 권한·복구 통제는 유지합니다.
