# F06. 과정 종료 시 1회 Forms 만족도 자동화

[전체 목록](../00_보고서_안내.md)

현재 운영 기준: 2026-10-28 사용자 최종 방침 · 난이도 3(문항·집계)/4(양식 준비·인증·수집 연결)

## 목적과 운영 범위

**만족도 조사는 각 기수의 전체 교육 과정이 끝날 때 1회, 객관식 2개·주관식 1개의 Microsoft Forms만 운영합니다.** 에이전트는 승인된 양식의 준비·응답 링크 확보·과정 종료 후 안내·응답 수집·집계·의견 요약·결과 보관을 자동 실행하도록 개발합니다.

여기서 과정 종료는 해당 기수 교육 과정의 종료일과 마지막 수업 종료를 확인한 시점입니다. 매일 수업 종료, 교과목/모듈 종료, 중간 시점마다 보내는 의미가 아닙니다. 일별·중간·별도 6문항 최종·특강·멘토링 만족도는 운영하지 않으며 기존 예약도 비활성화합니다. 만족도 양식은 이 한 종류로 통일합니다. 퀴즈·행사 참가 신청·동의서 등 만족도와 목적이 다른 업무의 입력 양식은 해당 기능 명세를 따릅니다.

한 기수 수업일당 하루 강의 1개·여러 기수 동시 운영이라는 일정 기준은 유지합니다. 만족도 발송 주기는 일별 수업 주기와 분리합니다. 같은 날짜에 A기수 과정이 끝나고 B기수가 계속 운영되면 A기수에만 발송합니다.

## 입력·설정

`course_id`(기수별 과정 인스턴스), 과정명·기수, 과정 시작/종료일·마지막 수업 종료 시각·시간대·종료 확인 상태, 응답 대상 명단 기준 버전/인원, 승인 문항 버전·익명/기명·1인 1응답·응답 기한·재안내 규칙·공개 최소 인원, Forms 소유 조직/계정·form_id·응답 링크·문항 매핑·workflow_id·연결 상태를 등록합니다.

생성·기본 발송 기준 키는 `course_id + completion_survey`입니다. 날짜·강사·마지막 수업·문항 버전 변경은 기존 설문과 예약을 갱신하며 같은 과정의 두 번째 만족도를 자동 생성하지 않습니다. 기한 내 재안내는 같은 양식·링크를 사용하고 새 조사로 세지 않습니다. 과정별 다른 기수는 서로 다른 course_id와 양식으로 구분합니다.

## 문항 — 객관식 2개·주관식 1개

첨부한 양식의 준비도·설명/전달력 두 항목과 자유 의견 한 항목을 유지하고 평가 대상만 해당 과정 전체로 표시합니다. 이해도·커리큘럼·취업 도움 등을 별도 문항으로 추가하지 않습니다.

| 항목 ID | 문구 | 형식·필수 여부 |
|---|---|---|
| Q1 `preparation` | 본 과정의 교안과 수강 자료가 알차게 구성되었으며, 전체적인 강의 준비가 잘 이루어졌다고 느끼셨나요? | 5점 선택형·필수 |
| Q2 `clarity` | 본 과정에서 강사의 설명이 명확하고 이해하기 쉬웠으며, 수업 내용이 효과적으로 전달되었나요? | 5점 선택형·필수 |
| Q3 `comment` | [과정명]에서 가장 좋았던 점이나 보완이 필요한 점 또는 개선 의견이 있으면 자유롭게 적어주세요. | 장문 주관식·기본 선택 |

선택지는 `매우 그렇다(5) / 그렇다(4) / 보통(3) / 아니다(2) / 매우 아니다(1)`입니다. 화면은 선택형 표 두 행과 주관식 입력란 하나로 구성합니다. Forms의 질문 블록 번호가 두 개여도 응답 항목은 총 3개입니다. 이름·날짜·강사를 묻는 추가 질문은 넣지 않고 과정·기수는 서버 매핑으로 연결합니다.

제목은 `[과정명] [기수] 과정 종료 만족도 조사`, 설명은 해당 과정 기간·종료일과 응답 기한입니다. 여러 강사가 참여해도 과정 전체 응답을 특정 강사 한 명의 성적으로 귀속하거나 강사별 조사로 분리하지 않습니다.

## 처리 구조

```text
최초 양식·규칙·권한 승인 + 기수별 과정 종료 일정 등록
→ 기존 과정 만족도 양식/발송 여부 확인
→ 과정별 승인 템플릿 준비·제목/기간/기수 치환(F19)
→ 3항목·선택지·응답 설정·form_id·링크·문항 매핑 확인
→ 해당 form_id의 Logic Apps 수집 워크플로 연결·확인
→ 과정 종료일/마지막 수업 종료·종료 상태 재확인
→ 해당 과정 대상자에게 기본 안내 1회
→ Forms 새 응답 → 응답 상세 조회 → Service Bus
→ 문항·점수 검증·응답 중복 제거·DB 저장
→ 같은 링크로 허용된 기한/횟수 내 재안내
→ SQL 집계 + AI 주관식 요약
→ 대시보드·집계 Excel/요약 보관
```

일반 수업·특강·멘토링이 끝난 이벤트만으로 발송하지 않습니다. 과정 종료가 연기·취소되면 미발송 예약을 갱신하며, 이미 받은 응답은 원천·버전과 함께 보존합니다. 과거 일별·중간·다른 만족도 예약이 남아 실행되지 않도록 이관 시 정리합니다.

## 실행 경로와 실현 가능성

| 구간 | 구현 경로 | 검증할 조건 |
|---|---|---|
| 표준 양식 준비 | F19 Playwright로 승인 Forms 복제·제목/설정·링크 검사 | 공식 Forms 커넥터의 생성/복제 액션을 가정하지 않음. UI·로그인·정책·문항 ID 확인 |
| 응답 자동 수집 | Azure Logic Apps Consumption Forms 커넥터의 새 응답 트리거·상세 조회, Service Bus 전달 | 교육 조직 계정 OAuth·양식별 연결·실제 응답 구조 확인 |
| 양식별 연결 | 승인된 Azure 템플릿에 form_id를 지정해 연결 | 새 양식 자동 감지를 가정하지 않고 배치·연결 재사용·시험 응답을 검증 |
| 종료 후 1회 실행 | 과정 종료 조건·고유 실행 키·발송 이력 확인 | 일반 수업 종료/중간 시점 차단, 종료 연기·재시도·다른 기수 분리 |
| 결과 | PostgreSQL/SQL·Foundry·SharePoint 별도 파일 | 점수·응답 수·요약 근거·접근 권한·복구 대조 |

Logic Apps는 엘릭서 Azure 구독에 두고 Forms 연결에는 권한 있는 교육 조직 계정으로 최초 OAuth 인증합니다. Managed Identity·Graph 앱 동의를 Forms 인증과 동일하게 보지 않습니다. 수집 연결 확인 전 발송을 차단합니다.

Excel 다운로드는 장애 복구·과거 응답 보충·대조용이며 정상 운영마다 사람 다운로드를 요구하지 않습니다. 연결 단절 중 과거 응답의 자동 복구는 가정하지 않고 Forms 결과와 대조합니다. 다운로드 사본과 Forms 연결 Excel을 구분합니다. 양식·활성 워크플로·커넥터 호출 한도·비용·보관 기간은 과정 종료 건수와 응답 수 기준으로 산정합니다.

**실현 가능성:** 응답 수집에는 공식 연결 기능이 있습니다. 양식 준비까지의 무인화는 UI·인증·과정별 연결과 종료 조건을 실제 환경에서 검증해야 하는 조건부 구현 설계입니다. 현재 자동화 성공·배포 완료 상태로 보지 않습니다.

## 저장·출력

`form_versions`, `survey_instances`, `survey_bindings`, `responses`, `response_items`, `survey_summaries`.

- 과정·기수·종료일·종료 확인 상태·대상 명단 버전·양식/문항 버전·form_id·question_map·workflow_id·응답 링크·수집/발송 상태.
- 기본 발송 키 `course_id + completion_survey`, 응답 고유 키 `tenant_id + form_id + response_id`. 재시도·복구 파일로 건수를 늘리지 않음.
- 응답/수집 시각·원문 라벨·1~5점 매핑·원천·시험 응답 구분·대조 이력.
- Q1·Q2 평균·5점 분포·두 항목 평균·유효 응답 수·Q3 요약과 원문 근거. 주관식 공란은 유효 응답이고 평균에서 제외.
- 응답률은 과정 종료 조사 대상 명단의 인원을 분모로 사용. 익명에서 1인 1응답 보장이 불명확하면 건수와 대상 인원을 구분해 표시.
- 결과 Excel·요약은 확인된 운영 채널 `중간평가 및 설문`에 저장. 폴더명은 기존 저장 위치이며 여러 조사 유형 운영을 뜻하지 않음.
- 화면은 해당 과정 종료 결과와 응답 수·기준 시각을 표시. 동일 문항·동일 척도일 때만 다른 종료 기수와 비교하며 일별 강의 추이를 만들지 않음.

## 예외·사람 역할

최초 문항·권한·공개 범위·규칙 승인과 인증 복구·중요 개선 결정은 사람이 맡습니다. 익명은 학생 신원·출결과 결합하지 않고 개인 미응답 명단을 만들지 않습니다. 소수 집계·개인 사유 공개 범위를 제한합니다. 발송 결과 불명이면 기존 결과를 대조하고 무조건 재발송하지 않습니다. 과정 전체 점수로 개별 강사·학생을 평가하거나 제재하지 않습니다.

## POC 통과 기준

1. A기수만 종료·B기수는 운영 중인 사례에서 A에만 기본 안내 1회가 나가는지 검사.
2. 일일 수업·과정 중간·특강·멘토링 종료로 별도 만족도가 실행되지 않는지 검사.
3. 종료일 연기·마지막 수업 변경·중복 이벤트·재시도에 양식/기본 안내가 중복 생성되지 않는지 검사.
4. 서로 다른 두 과정의 양식·수집 연결·응답이 섞이지 않는지 시험.
5. 두 선택형 점수와 선택 주관식의 매핑·공란·중복·오류, 원본/집계 일치를 검사.
6. UI·OAuth·수집 단절을 응답 0건으로 표시하지 않고 복구·대조 이력을 남기는지 검사.
7. 노트북 종료 상태의 실행·사람 개입 횟수·시간·비용을 기록. 기존 불필요 만족도 예약 이관 여부도 검사.
