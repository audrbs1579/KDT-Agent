# 타운홀·특강 운영

[전체 목록](00_보고서_안내.md)

난이도: 2~3

## 목적

행사 준비, 참가 의사 확인, 매니저 명단, 강사 이력과 실제 참석을 관리합니다. 특강이 만족도 대상 강의 단위로 등록되고 기능이 켜져 있으면 강의별 만족도의 3항목 설문을 해당 강의 종료 후 1회 적용합니다. 일반 행사 종료만으로 임의 생성하지 않습니다.

## 입력·설정

Outlook 일정, 행사 유형, 대상 과정, 장소/Teams 회의, 초청 강사, 정원, 고정 참석 직원, 신청 기한, 준비 항목.

**폴더 매핑 예시:** KDT 폴더 구조의 운영 채널 `타운홀미팅 / [MMDD 행사명·회차]`는 운영 문서·행사 출석부·초청 명단·사진의 내부 위치이고, 수강생 `일반 / 04. 타운홀 미팅 / [MMDD 행사명·회차]`는 학생 배포 양식·활동 자료 위치입니다. 초청·조편성 Excel과 실제 참석 결과를 혼동하거나 내부 명단·사진을 자동 전체 공개하지 않습니다. Forms 다운로드 결과는 운영 채널 `중간평가 및 설문` 저장 예정 흐름을 따릅니다. 파일명·날짜·회차는 테스트 및 운영을 하면서 바꿀 수도 있으며 실제 ID·권한은 별도 확인합니다.

## 처리 구조

`행사 일정 → 준비 체크리스트 → 사람이 참가 신청 Forms 준비·게시·링크 등록 → Teams 링크 안내 → Forms 응답 → 매니저가 응답 화면에서 Excel 다운로드·전달 → 에이전트 수집·중복/정원 검사 → 고정 매니저 명단 결합 확정 → 안내 → 실제 참석 기록`

별도 외부 신청 페이지를 만들지 않고 **Teams 안내·Forms 응답·Excel 다운로드·에이전트 정리**를 기본 경로로 사용합니다. Teams 자체 투표의 답변을 직접 수집하는 별도 기능으로 설명하지 않습니다.

다운로드한 파일은 해당 시점의 사본이며 새 응답은 다시 다운로드합니다. 양식 버전·응답 ID로 중복을 제거하고 미게시 양식은 안내하지 않습니다. 회의 유형·주최자를 확인하고 채널 수업 생성과 일반 행사 회의를 혼용하지 않습니다.

**만족도 적용:** 대상 특강의 teaching_unit_id·종료 조건·만족도 On/Off를 등록해 강의별 만족도으로 연결합니다. 기수 전체 종료를 기다리는 조건은 없습니다. 참가 신청 Forms와 만족도 양식은 서로 다른 목적·양식으로 구분합니다.

## 리소스·권한

Outlook/Teams/Graph, PostgreSQL, Durable Functions, Service Bus, SharePoint. 직원 행사와 학생 특강의 회의 주최 테넌트를 구분합니다.

## 저장·출력

`events`, `event_registrations`, `instructors`, `tasks`, `attendance_observations`.

출력: 참석 예정자+고정 직원 Excel, 준비 상태, 안내 내역, 실제 참석 결과. “참가 신청”과 “실제 참석”은 별도 상태입니다. 고정 매니저 결합 명단은 09 데이터 컬럼·엑셀 양식을 따릅니다.

## 예외·승인

- 일정 취소 시 대기 안내·참가 신청을 취소/갱신.
- 중복 신청·정원 초과·대기자 이동은 규칙에 따라 안내.
- 고정 직원과 일반 신청자를 중복 계산하지 않음.
- 외부 강사 섭외·비용 지출·장소 계약은 승인.
- 행사에 여러 과정이 섞이면 각 과정의 자료 공개 범위 유지.

## 운영 품질 기준

명단 수·고정 직원 수·중복 제거가 정확해야 합니다. 취소·정원 변경이 안내에 반영되고 참석 예상이 실제 참석으로 잘못 집계되지 않아야 합니다.

## 근거·연관

[OT 준비](03_모집과_OT_준비.md#orientation-preparation) 체크리스트, [강의별 만족도](05_강의_단위별_만족도.md#lecture-satisfaction) 설문, [Teams 메시지](https://learn.microsoft.com/en-us/microsoftteams/platform/bots/how-to/conversations/send-proactive-messages)

# 커리어 멘토링·사전 자료

[전체 목록](00_보고서_안내.md)

난이도: 2~3

문서 형식·파서·모델·리전은 조사 기준의 참고 후보이며 실제 테스트·운영에서 추출 결과·품질·가성비를 보고 변경합니다. 형식 지원 정보와 실제 검증 완료 기록은 구분합니다.

## 목적

멘토링 전에 자소서·질문·필요 자료를 받고 멘토의 준비 여부와 진행 기록을 관리합니다. 만족도 대상 강의 단위로 지정한 회차는 강의별 만족도과 연결하고, 운영 설정 없이 멘토링 종료만으로 별도 설문을 생성하지 않습니다.

## 입력·설정

멘토·학생·회차, 일정, 신청·안내 채널(`{과정명} {기수} 수강생 팀 > 04. 멘토링 요청 게시판`), **수강생이 제출하는 비정형 사전 자료(자소서·포트폴리오·이력서·사전 질문지 — 워드 `.docx`뿐 아니라 아래아한글 `.hwp`/`.hwpx`, `.pdf`, 노션/웹페이지 `.html`/`.md`, `.pptx`, 이미지 등은 접수·추출 검토 후보)**, 마감, 멘토링 사전 질문 수(설정값), 열람 만료, 재안내 정책. 원본 접수 가능과 내용 추출 성공은 구분하며 미지원·추출 실패는 사람 확인으로 남깁니다.

**자료 위치 예시:** 폴더 구조의 수강생 `일반 / 04. 타운홀 미팅 / [MMDD 커리어멘토링 회차]`는 이력서 양식 등 배포 자료이고, 운영 채널 `커리어멘토링 / [행사 폴더]`는 운영 자료입니다. 강사팀 `멘토링 일지 / N차 프로젝트 멘토링 일지.xlsx`는 프로젝트 멘토링 자료이므로 커리어 멘토링과 같은 회차·원본이라고 간주하지 않습니다. 개인 자소서·이력서·상담 원본은 담당자·배정 멘토 제한 위치를 별도 지정하고, Forms 결과는 운영 채널 `중간평가 및 설문` 저장 예정 흐름을 따릅니다. 이름·날짜·파일 구성은 테스트 및 운영을 하면서 바꿀 수도 있으며 실제 ID·권한은 별도 확인합니다.

## 처리 구조

```text
멘토링 일정 → 수강생 팀(04. 멘토링 요청 게시판)에서 신청·제출 안내
→ 개인 사전 자료(.hwp, .hwpx, .pdf, .html, .docx 등)는 권한 확인된 제한 접수 위치로, 질문은 공개 범위에 맞는 Forms/대화로 접수
→ 확장자·형식별 자동 파싱(.pdf·.html·.docx·이미지는 R16 Content Understanding, .hwp·.hwpx는 서버 내 한글 파서/PDF 변환기 처리)
→ PostgreSQL 비정형 필드(`extracted_fields JSONB`) 및 검색 조각(`chunks`) 저장 + 학생·회차 매칭
→ 멘토에게 Teams/M365로 원본 파일 + AI 핵심 요약 묶음 전달
→ 진행 확인·멘토링 기록 보관 → 만족도 대상 강의 단위/On 설정이면 강의별 만족도 연결
```

**만족도 적용:** 대상 회차를 강의 단위로 지정한 경우 객관식 2개·주관식 1개를 종료 후 1회 받습니다. 강의 경계·대상·사용 여부는 과정 설정을 따르며 신청·사전 질문 Forms와는 구분합니다.

## 리소스·권한

Teams(`04. 멘토링 요청 게시판`), Microsoft Forms/SharePoint(엑셀·사전 자료 폴더), **R16 Content Understanding + R02 서버 내 한글(`.hwp`/`.hwpx`)·HTML 전처리 파서**, PostgreSQL(`JSONB` + `vector`), Outlook, Durable Functions. 모든 수집·전달은 **Teams·M365(SharePoint/Forms/엑셀 업로드) 환경**에서 운영합니다.

## 저장·출력

`mentoring_sessions`, `document_requests`, `documents`, `task_responses`.

출력: 제출 현황, 멘토별 자료 묶음, 미제출 안내, 진행 기록. 만족도를 사용한 강의 단위는 강의별 만족도 결과를 연결합니다. 멘토는 배정 학생·기간의 필요한 자료만 봅니다.

## 예외·승인

- Forms 생성·게시·응답 화면의 Excel 다운로드는 사람 담당. 다운로드 파일은 자동 동기화 사본이 아니므로 새 응답은 다시 내려받고 응답 ID로 중복 제거.
- 게시판은 요청·안내용이며 자소서·이력서 원본은 배정 멘토·담당자만 보는 제한 위치로 접수. 여러 학생에게 공개되는 폴더에 모으지 않음.

- 파일 오류·잘못된 형식·대상 불일치: 명시적 반려/재제출 안내.
- 다른 학생의 사전 자료 폴더/파일에 접근하지 못하도록 SharePoint/Teams 권한 구분.
- 일정 변경은 자료 마감·접근 기간도 함께 갱신.
- 자료가 없으면 제출 완료로 추정하지 않음.
- 멘토 교체 시 기존 접근을 회수.
- 민감 상담 내용은 학생 전체 보고서에 포함하지 않음.

## 운영 품질 기준

다른 학생 자료에 접근할 수 없어야 하며, 재제출은 이전 버전과 구분되고 일정 취소 후 요청이 중단되어야 합니다.

# 이력서 취합·인재 검색

[전체 목록](00_보고서_안내.md)

난이도: 3~4

파일 형식·파서·모델·리전은 조사한 참고 후보이며 실제 테스트·운영에서 추출 결과·품질·비용에 따라 변경합니다. 조사상 지원 가능과 실제 검증 완료는 구분합니다.

## 목적

완성된 이력서·경력·기술·희망 직무를 모아, 승인된 목적 안에서 기업 추천이나 보조강사 후보를 찾습니다.

## 입력·설정

**수강생별 비정형 이력서·포트폴리오 버전(아래아한글 `.hwp`/`.hwpx`, `.pdf`, 노션/웹 `.html`/`.md`, `.docx`, `.pptx` 등 자유 양식)**, 필수 연락처·주소 등 실제 필요한 항목, 활용 동의 목적, 공개 범위, 보관 기간, 검색 조건.

**자료 위치 참고:** KDT 폴더 구조의 수강생 `일반 / 04. 타운홀 미팅` 안 이력서 양식은 배포용 샘플이지 개인 이력서의 수집 위치가 아닙니다. 운영 채널 `커리어멘토링`과 연계하더라도 개인 원본·인재풀 결과는 취업 담당자·지정 멘토의 제한 위치를 별도로 등록합니다. 파일명·날짜·구성은 테스트 및 운영을 하면서 바꿀 수도 있으며, 제공된 예시만으로 개인 자료가 이미 접수됐거나 열람 허용됐다고 판단하지 않습니다.

## 처리 구조

```text
자료 요청·접수 → 원본/버전 보관(SharePoint/Blob)
→ 형식별 추출(.pdf·.html·.docx·.pptx는 R16 Content Understanding, .hwp·.hwpx는 서버 한글 파서/PDF 변환 후 추출)
→ 문서마다 양식이 다른 비정형 항목을 PostgreSQL `extracted_fields (JSONB)` + `chunks (vector)`에 구조화 및 불명확 값 확인
→ 권한/활용 목적 필터 후 하이브리드 검색(정형 조건 + JSONB + 벡터 의미 검색)
→ 근거 있는 후보 목록 및 표준 인재풀 엑셀(09 데이터 컬럼·엑셀 양식) 자동 매핑
→ 담당자 검토·학생 의사 확인·외부 제공 승인
```

## 리소스·권한

SharePoint/Blob, PostgreSQL(`JSONB` + `vector` 검색), Foundry + **R16 Content Understanding + 서버 내 한글(`.hwp`/`.hwpx`) 전처리 파서**, Teams/SharePoint 폴더(또는 엑셀 업로드). 별도 외부 업로드 웹을 만들지 않고 M365/Teams 환경에서 수집하며, 취업 담당자와 지정 멘토로 접근을 제한합니다.

## 저장·출력

`resume_versions`, `candidate_profiles`, `skills`, `consent_records`, `referral_requests`.

추출 필드에는 원본 위치·추출 버전·확인 상태를 둡니다. “AI가 추출한 경력”과 본인이 확인한 경력을 구분합니다.

출력: 조건에 맞는 후보, 근거 문장·이력서 링크, 부족/미확인 정보, 승인된 Excel(09 데이터 컬럼·엑셀 양식의 주소 필수 포함 인재풀 시트 참조).

## 예외·승인

- AI는 최종 채용·추천 합격을 결정하지 않음.
- 출결·불만·민원 기록을 무관한 채용 평가에 섞지 않음.
- 동의 목적 밖의 기업 제공·홍보·섭외는 별도 확인.
- 기업 추천 동의와 보조강사 섭외 동의를 목적별로 별도 기록하며 어느 하나의 동의를 다른 목적에 자동 적용하지 않음. 예시 컬럼·동의 항목도 실제 양식에 맞게 변경 가능.
- 주소 등 개인정보를 검색 결과에 항상 노출하지 않고 필요한 역할만 열람.
- 오래된 자료·동의 철회·삭제 요청을 인덱스와 후보 검색에도 반영.
- 외부 전달은 승인된 정확한 수신자·문서 버전에 묶음.

## 운영 품질 기준

검색 결과가 실제 기술/경력 근거와 연결되고, 동의 철회·권한 밖 후보는 제외되어야 합니다. 문서 버전이 바뀌면 낡은 정보가 현재 사실로 남지 않아야 합니다.
