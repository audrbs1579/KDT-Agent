# 운영 문제 조기 감지·참여 지원

[전체 목록](00_보고서_안내.md)

난이도: 4

## 목적

강의 품질·응대 지연·행정 오류·프로젝트 갈등을 일찍 발견해 해결합니다. 학생별 “신고할 가능성”을 평가하거나 비판·신고 자체를 경고 사유로 삼지 않습니다.

> **[발표·보고 시 설명 유의사항 — 원본 기획안 대비 변경 사유]**
> 원본 기획안(3-4, 3-5)에는 *"수업 참여도가 훨씬 낮은 사람 Top 3를 뽑아 자동 메시지를 보내거나, 카메라가 꺼진 사람·자는 사람에게 에이전트가 자동으로 경고를 보낸다"*는 아이디어가 포함되어 있습니다. 그러나 실제 운영에서 채팅량만으로 참여도를 줄 세우거나 AI가 화면만으로 졸음·자리이탈을 단정해 학생에게 자동 경고를 발송하면 **오판으로 인한 학생 반발·민원 및 개인정보/감시 논란**이 발생할 수 있습니다. 따라서 본 설계 보고서에서는 원본 문구와 달리 **① 학생 태도 하위 순위(Top 3) 산출 금지, ② 졸음·불성실 자동 단정 및 자동 경고 발송 금지, ③ 객관적 관찰 사실만 매니저에게 먼저 보고하고 매니저 확인 후 안내**하도록 안전 장치를 두어 변경했습니다.

만족도 근거는 [강의별 만족도](05_강의_단위별_만족도.md#lecture-satisfaction)의 강의 단위 종료별 객관식 2개·주관식 1개 Forms에서 연결합니다. course_id·teaching_unit_id·문항 버전·수집 상태로 구분하고, 점수/분포는 코드 집계·AI는 허용된 의견 요약에 사용합니다. 수집 장애나 낮은 점수만으로 학생/강사의 문제·제재를 확정하지 않습니다.

## 입력·설정

승인된 교육 채팅, 설문, 문의 처리 상태, LMS 관찰, 프로젝트 약속/제출 상태, 이슈 유형, 응대 기한, 경보 임계값, 담당자, 비공개 범위.

**자료 위치 참고:** 운영 채널 구조의 `상담일지 / 일반상담`·`중도퇴소 상담`·`출결 경고`는 기록 위치 예시입니다. 개인별 경고 이미지·상담 기록이 있다고 해서 자동 제재나 태도 판정의 근거로 사용하지 않습니다. 프로젝트 자료도 수강생 `일반 / 06. 프로젝트`·`07. 산출물`과 운영 채널 `프로젝트`를 구분하고 허용된 최신 자료만 확인합니다. 이름·날짜·경로는 테스트 및 운영을 하면서 바꿀 수도 있으며 실제 상담 열람·결과 보관 권한은 별도 확인합니다.

| 신호 | 수신자 | 기본 조치 |
|---|---|---|
| 반복된 교안 미제공·일정 상충·불만 | 매니저 | 근거 묶기·담당자 배정 |
| 문의 답변 기한 초과·반려 안내 누락 | 매니저 | 미처리 업무 생성 |
| 명시적 도움 요청·프로젝트 갈등 | 매니저/멘토 | 맥락 확인·지원 |
| 게시판·LMS 정상 조회 후 유효 사전 신고/예외 없이 입퇴실 기록 미확인 | 해당 학생 | LMS 입퇴실 확인 기준 재확인 후 비공개 미클릭/기록 확인 안내 |
| 사전 지각·조퇴·외출 신고 있음 | 해당 학생/매니저 | 예정 시각·구간별 확인 예약·안내 조정, 예정 초과/상충만 맞춤 안내·예외 보고. 신고만으로 공식 인정하지 않음 |
| 일반 제출물 기록 미확인 | 해당 학생 | 해당 업무의 사전 규칙에 따른 비공개 안내 |
| 병가·공결 증빙의 판독 불확실·요건 보완 후보 | 매니저 | [증빙·반려 안내](06_출결과_증빙_처리.md#document-review) 최종 판단·사유 확인 후 해당 학생에게 결과 안내 |
| 수집 오류·로그인 만료 | 운영 담당자 | 데이터 장애 경보 |

## 처리 구조

```text
수집 이벤트 → 데이터 최신성·권한 확인
→ 객관적 규칙 검사 + AI 맥락 요약
→ 중복 이슈 병합
→ 사실/추정/누락 상태 구분
→ 담당자 경보 또는 학생 안내
→ 접수·조치·해결·오탐 기록
```

실제 연결·권한·대상·규칙을 확인해 운영에 적용합니다. 모델은 테스트·운영 중 품질·수정률·속도·비용을 보고 더 좋은 모델 또는 더 가성비 있는 모델로 변경합니다. 학생 안내는 검증된 원천 데이터와 명시적 규칙이 있는 유형만 자동 전송하고 그 밖의 유형은 담당자 경보로 처리합니다.

출결 게시판의 사전 신고를 읽지 않은 상태에서 LMS 기록 없음만으로 학생을 독촉하지 않습니다. 신고 접수·예정 대조·공식 인정 상태를 구분하고, 수집 장애·모호한 날짜/시각은 담당자 확인으로 남깁니다. 신고된 외출·조퇴 구간을 태도/미참여 경보로 확대하지 않습니다.

증빙의 보완·반려는 일반 미제출 알림으로 우회하지 않습니다. 매니저 확인 전 1차 판독만으로 학생에게 보완·반려를 통보하지 않습니다.

## 리소스·권한

Graph/Teams, PostgreSQL, Foundry, Durable Functions, Service Bus. 경보는 실제 수신자·소속 팀·권한을 확인한 내부 운영 채널 또는 `@elixirr` 운영 채널·담당자 개인 대화로 보냅니다. 제공된 `{기수} 채널` 폴더 예시만으로 전체 채널이 민감 경보를 볼 수 있다고 가정하지 않습니다. 수강생 팀이나 외부 기관의 `출석 관리 팀`에는 내부 경보를 올리지 않으며 학생 미이행 안내는 해당 과정의 비공개 안내 정책을 따릅니다.

## 저장·출력

`cases`, `case_evidence`, `case_actions`, `rule_versions`, `collection_health`.

필드: 과정, 유형, 발생 시각, 수집 기준 시각, 근거 링크, 확인된 사실, AI 요약/불확실성, 담당자, 기한, 상태, 이의제기·오탐 사유.

대시보드는 사람이 아니라 **해결할 사건**을 우선 보여줍니다.

## 예외·승인

- 비꼼·인용·일방 진술은 확정 사실과 분리.
- 메시지량이 적다는 이유로 참여 의지가 없다고 판단하지 않음.
- 수집 중단을 “위험 없음”으로 처리하지 않음.
- 개인별 수면·감정·신고 의도 추론은 사용하지 않음.
- 공식 제재·수료 판단·외부 민원 답변은 매니저 승인.
- 같은 사건의 알림 폭주를 막되 심각도 변화와 미응답 기한은 별도 재알림.

## 운영 품질 기준

운영 중 담당자의 처리 결과(조치·오탐·이의제기)로 유형별 정밀도·재현율·중대 누락을 측정합니다. 근거 없는 경보와 중복 경보를 점검합니다. 학생 안내는 검증된 원천 데이터와 명시적 규칙이 있을 때만 실행되어야 합니다.

# 통합 대시보드·업무 진척도

[전체 목록](00_보고서_안내.md)

난이도: 3

## 목적

운영국과 매니저가 여러 과정의 상태와 AI가 수행한 일을 한 화면에서 확인합니다. 학생 현황뿐 아니라 **데이터가 최신인지, 자동화가 실제로 성공했는지**도 표시합니다.

## 입력·설정

로그인 역할, 담당 과정, 표시 기간, 지표·필터, 업무 완료 조건, 경보 우선순위, 갱신 주기.

## 처리 구조

`업무 DB·수집 상태·실행 이벤트 → 권한 범위 필터 → SQL 집계 → 화면 표시 → 근거·실행 상세 → 필요한 승인/재처리`

AI는 요약을 제공하지만 완료율·인원·응답률 계산은 검증 가능한 코드/SQL이 담당합니다.

**일정 표시 기준:** 기수별 하루 일정 1개·여러 기수 동시 운영을 유지하고, 여러 날의 일정들을 강의 단위로 묶어 표시합니다. 강의 시작 D-7 채팅/첫 안내·준비 확인과 강의 단위 종료별 설문 준비/종료 확인/안내/수집/집계 상태를 보여줍니다. 월이 바뀌어도 같은 강의 단위는 같은 ID입니다.

**출결 확인 화면:** 기수·학생·수업일별로 `게시판 사전 예정 → 실제 LMS/호명 기록 → 일치·예정 초과·확인 대기 → 다음 조치`를 표시합니다. 신고가 있어 일반 미클릭 안내를 보류한 이유와 다음 확인 시각을 보여주고, 신고 접수·공식 인정·LMS 정정 완료는 별도 배지로 표시합니다. 개인 사유는 제한된 담당자 화면에서만 열람합니다(LMS 입퇴실 확인·중간 출결·종합).

### 자료 위치 표시

KDT 폴더 구조에 맞춰 카드·파일 링크에 **수강생 `일반` / 기수별 운영 채널 / 강사팀**의 자료 영역과 자료 종류를 표시합니다. 강사팀 호명 출석부 수집, 운영 채널 `출석부 / 월 / 주차 / 일자`의 원본·종합본 보관, 수강생 `일반 / Recordings`의 녹화 상태를 별도로 집계합니다.

운영 채널 `중간평가 및 설문`은 저장 예정 예시와 강의 단위 종료 설문의 실제 자동 수집·집계·결과 파일 생성 상태와 복구/기타 설문 다운로드 상태를 구분하고, 시간표는 기준 원본과 배포본을 표시합니다. **[사용자 제공 구조](09_데이터와_자료_관리.md#teams-folders) 예시 / 실제 ID·권한 확인 / 연동 검증 완료**를 분리해 미확인 연결이 정상 작동 중으로 보이지 않게 합니다. 날짜·이름·파일명·세부 구성은 테스트 및 운영을 하면서 바꿀 수도 있습니다. 상담·계정·평가문제·퀴즈 정답의 링크·미리보기도 열람 역할로 제한합니다.

만족도는 며칠에 걸친 각 강의 종료 후 객관식 2개·주관식 1개를 1회 받습니다. 강의별 Q1/Q2 평균·분포·Q3 주제/근거에 기수·강의명·기간·강사 목록·응답 수·문항 버전을 표시합니다. 같은 문항/척도일 때 강의·기수 비교 기준을 명시하고, 한 강의의 결과를 일별 점수나 공동 강사의 개별 점수로 임의 분할하지 않습니다. 익명은 신원·개인 미응답과 결합하지 않고 수집 실패를 0건으로 표시하지 않습니다([강의별 만족도](05_강의_단위별_만족도.md#lecture-satisfaction)).

## 리소스·권한

Container Apps 웹 UI/API, PostgreSQL, Entra 인증, Teams 탭, Azure Monitor. 직원 기본 로그인은 `@elixirr`. 교육 계정은 직원 역할 매핑 없이 운영 화면 접근 불가.

## 저장·출력

화면 설정·필터, 업무 상태, 승인·재처리 요청과 감사 기록. 각 카드에 원천·기준 시각·규칙 버전·관련 파일/메시지·실행 ID를 연결합니다.

모든 정형 목록은 권한 범위 안에서 Excel 내보내기를 제공합니다.

## 예외·승인

- 데이터 수집 실패를 “문제 없음”으로 표시하지 않음.
- 알림 발송 성공을 실제 업무 완료로 간주하지 않음.
- 재처리 버튼은 새 실행 권한·현재 일정·승인을 재검사.
- 민감한 면접/병가/상담 정보는 요약 화면에서도 접근 제한.
- 여러 과정 선택 시 분모·기간·척도가 다른 지표를 무조건 합산하지 않음.
- 직원에게는 업무 수행 결과를, 학생에게는 필요한 본인 정보만 표시.

## 운영 품질 기준

대시보드 수치가 DB·원천과 일치하고, 연결 장애/오래된 데이터가 명확히 표시되어야 합니다. 담당 과정 변경·권한 회수 시 기존 화면/검색에서도 접근이 차단되어야 합니다.
