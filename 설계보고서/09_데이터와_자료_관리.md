# 공통 데이터·권한·실행 복구 명세

[문서 목록](00_보고서_안내.md)



모델·리전·지원 형식은 공통 참고 기준에 따라 테스트·운영에서 변경할 수 있습니다. 아래 엔터티·컬럼은 설계 예시이며 접근 통제·승인·추적 원칙을 지키는 범위에서 양식/매핑 버전으로 조정합니다.

## 1. 데이터 저장 원칙

**한곳에서 찾을 수 있게 연결하되, 모든 원본을 DB 안에 복제하지 않습니다.**

- **운영진·강사 협업 문서:** 공유 엑셀·워드 원본은 사람이 M365에서 공동 편집합니다. 에이전트는 허용된 SharePoint 파일을 Drive API로 다운로드·파싱해 집계하며, 원본 셀·Word 내용을 직접 수정하지 않습니다. 수정이 필요하면 담당자 업무로 알리고 결과물은 별도 파일로 생성합니다. Excel 셀 API의 위임 권한과 앱 전용 파일 접근 권한은 다릅니다.
- **수강생 응답:** 과정 종료 만족도는 과정 종료 시 1회 객관식 2개·주관식 1개입니다. 승인된 양식의 F19 자동 준비·링크 확보 후 양식별 Logic Apps Forms 커넥터로 응답을 수집합니다. `(tenant_id, form_id, response_id)` 고유 키로 중복 제거하고 문항 ID·버전·과정/기수·수집 시각을 기록합니다. 참가 신청·동의서·퀴즈 등 다른 목적 양식의 사람 준비/다운로드 경로는 해당 기능 기준을 따릅니다. 다운로드 사본은 과정 종료 설문의 장애 복구·과거 응답 대조에도 쓰며 자동 갱신 파일로 가정하지 않습니다([F06](기능/F06_만족도조사.md)).
- **파일 버전:** 변경 알림 또는 주기 조회로 `eTag`·수정 시각을 대조하고, 다운로드 전후 버전이 다르면 재수집합니다. 원본 버전·해시·컬럼 매핑 버전·수집 시각을 기록하며 실시간 셀 동기화나 사람의 동시 편집 내용을 덮어쓰는 처리는 약속하지 않습니다.
- **자료 영역:** KDT 폴더 구조의 수강생 팀 `일반`·기수별 운영 채널·강사팀을 구분합니다. 수강생 파일 공유는 `일반` 안에서만 하며, 운영 채널·강사팀에 있는 자료를 자동으로 학생에게 복사하지 않습니다. 날짜·파일명·세부 구성은 테스트 및 운영을 하면서 바꿀 수도 있습니다.
- **출결 보관·외부 전달:** 강사팀 `출석부 / 월 / 주차 / 일자 / MMDD.xlsx`는 호명 원본 수집 위치 예시이고, 내부 원본 3종·종합본은 운영 채널 **`출석부 / 월 / 주차 / 일자`**에 자료 종류·버전별 별도 파일로 보관합니다. 원본을 덮어쓰지 않습니다. 수강생 `일반 / Recordings`와 월·주차·일자 계층이 비슷해도 같은 저장소가 아닙니다. 민감 증빙은 담당자 제한 위치를 별도 지정합니다. 출석 관리 팀은 승인된 외부 기관 업무용이며 기본 보관소가 아닙니다. 실제 ID·권한은 연결 시 확인합니다.
- **Forms 결과 보관:** 과정 종료 설문 응답의 업무 원본은 수집된 DB 기록이며 집계 Excel·요약은 운영 채널 `중간평가 및 설문`에 별도 생성합니다. 다른 목적 양식의 다운로드 Excel과 과정 종료 설문 응답 복구 사본도 이 영역에서 자료 역할·양식·시각·버전으로 구분합니다. 파일 존재만으로 Forms 자동 동기화·집계 완료를 뜻하지 않습니다. 일일 퀴즈 정답·개인 응답 등은 필요한 역할만 볼 수 있는 위치를 별도 지정합니다.
- **여러 위치의 유사 파일:** 운영 채널·수강생 팀의 시간표·계정 파일·매뉴얼은 이름만으로 동일 원본·최신본이라 판단하지 않습니다. 기준 원본과 배포본·파생본의 관계를 등록합니다. 계정 Excel의 비밀번호를 모델·로그·검색 색인으로 수집하지 않으며 실행 자격 증명은 Key Vault에서 관리합니다.

| 데이터 | 저장 위치 | 이유 |
|---|---|---|
| 학생·강사·등록·일정·출결·설문·업무 | PostgreSQL | 정확한 조회·관계·변경 이력 |
| 설정·규칙 | PostgreSQL의 구조화 필드/JSON | 버전·유효성 검사 |
| 교안·이력서·자소서·사전자료·동의서·증빙·녹화 원본 파일(**한글 `.hwp`/`.hwpx`·PDF·HTML·Markdown·Word·PPT·Excel·이미지·영상 등 모든 비정형 파일**) | 기존 SharePoint 또는 Blob | 큰 파일·보관 정책. 파일 자체는 DB에 넣지 않음 |
| 비정형 문서 메타데이터·추출 구조화 데이터(`JSONB`)·텍스트 조각·벡터 | PostgreSQL(`documents`·`document_versions`·`chunks`, `JSONB`, `vector`) | R16 Content Understanding 및 서버 내 한글(`.hwp`/`.hwpx`)/HTML 파서가 추출한 비정형 내용을 구조화(`extracted_fields JSONB`)·조각화해 권한에 맞게 검색 |
| 실행 증거 | 마스킹한 Blob 파일 + DB 참조 | 실패 확인·재현 |
| 비밀 | Key Vault | 문서·대화·일반 DB에 비밀번호 저장 금지 |
| 실행 흐름 내부 상태 | Durable Task Scheduler | 대기·복구, 업무 DB와 역할 분리 |

**수강생·강사 비정형 문서 파일(`.hwp`, `.hwpx`, `.pdf`, `.html`, `.docx`, `.pptx`, 이미지 등) 처리 흐름:**

아래 지원 형식·파서 경로는 조사 기준의 구현 후보입니다. 실제 검증 완료 여부는 형식·API/분석기·파서 버전별 테스트 기록으로 구분하고 운영 중 변경할 수 있습니다. 파일 접수 가능과 내용 추출 성공은 다릅니다.
1. **원본 보관:** 수강생이 제출하는 문서([F02](기능/F02_모집_면접.md) 지원서·포트폴리오, [F12](기능/F12_멘토링_사전자료.md) 커리어 멘토링 자소서·사전 질문·노션/웹 내보내기 `.html`, [F13](기능/F13_이력서_인재검색.md) 이력서, [F14](기능/F14_LMS_서류_반려안내.md) 병가·증빙 서류)와 강사 교안([F07](기능/F07_퀴즈.md))은 양식과 확장자가 통일되어 있지 않으므로 원본 그대로 SharePoint/Blob에 보관합니다.
2. **형식별 자동 파싱·변환 파이프라인:**
   - **`.pdf`, `.html`, `.md`, `.txt`, `.rtf`, `.docx`/`.doc`, `.pptx`/`.ppt`, `.xlsx`/`.xls`, `.odt`, 이미지(`.jpg`/`.png`):** 조사 당시 R16 Content Understanding의 지원 후보이며 실제 선택 API/분석기에서 텍스트·표·레이아웃·필드 추출 결과를 확인합니다.
   - **아래아한글(`.hwp`, `.hwpx`):** Microsoft R16은 한국 고유 포맷인 `.hwp`/`.hwpx`를 기본 지원하지 않으므로, **R02 컨테이너 서버 내 전처리 파이프라인**에서 **① `.hwpx`(개방형 한글 XML)는 내부 XML 본문·표 구조를 직접 파싱**하고, **② `.hwp`(구형 바이너리)는 전용 파서(OLE 텍스트·표 추출) 또는 LibreOffice/변환기로 `.pdf` 변환본(`converted_pdf_uri`)을 생성한 뒤    R16에 전달**하여 추출합니다. 변환 과정의 표·서식 누락 가능성을 검사하고, 지원되지 않거나 불명확한 자료는 원본과 함께 사람이 확인합니다.
3. **DB(`PostgreSQL`) 비정형 대응 저장:** 추출된 내용은 문서마다 항목 구성이 다르므로 고정 컬럼 대신 **`document_versions.extracted_fields (JSONB)`**에 유연하게 저장하고, 본문·표 텍스트 조각과 임베딩은 **`chunks` (`section_type`, `table_json JSONB`, `embedding vector`)**에 저장하며, `acl_bindings`로 열람 권한을 연결합니다. 원본 변경·삭제 시 조각·JSONB·벡터도 함께 갱신·삭제합니다. 상세 근거는 [03 리소스](03_Azure_리소스_근거.md).

### 실행에 필요한 연결 필드

| 대상 | 추가로 기록할 필드와 제약 |
|---|---|
| 과정 출결 모드 | `attendance_mode`(온라인/수기/없음), 기간·시간대·유효 버전. 모드는 하나만 선택하며 출결 없음은 [F14](기능/F14_LMS_서류_반려안내.md)~[F16](기능/F16_중간출결.md)·출결 의존 예약을 차단. 수기는 온라인 독촉·3종 종합 대신 사람 확인/입력 업무로 전환 |
| 수업·강사 배정 | `course_id`, `class_date`, `session_id`, `instructor_id`, `starts_at`, `ends_at`, 시간대. 활성 강의 일정은 `(course_id, class_date)`당 1개. 공동 멘토링 담당자는 같은 session_id에 연결하고 강의를 추가하지 않음. 다른 기수는 같은 날짜·시간의 일정 허용 |

**일정·설문 단위:** 한 기수의 수업일당 강의 1개·여러 기수 동시 운영은 유지합니다. 만족도는 전체 과정 종료 시 1회이며 `course_id + completion_survey`를 기본 생성/발송 키로 사용합니다. 과정 종료일·마지막 수업·문항 버전 변경은 기존 양식·예약을 갱신하고 동일 과정에 새 조사나 일별 설문을 추가하지 않습니다. 만족도는 과정·기수에 연결하며 특정 학생·일별 강사 점수로 분리하지 않습니다.

과정 종료 만족도는 Q1 준비도·Q2 설명/전달력의 1~5점과 Q3 개선 의견을 별도 저장합니다. 집계는 SQL로 수행하고 주관식 공란을 점수 0이나 무효 응답으로 보지 않습니다. 응답 수정/삭제의 자동 반영을 가정하지 않으며 마감 대조·정정 이력으로 처리합니다. 익명 응답은 학생 ID와 결합하지 않고 원문·AI 요약·워크플로 실행 이력에 같은 접근 범위를 적용합니다.

**출결 사전 신고 처리:** 유효한 학생 신고는 승인 대기 중에도 오안내 방지를 위한 확인 예정 시각·문구 조정에 반영합니다. 공식 출결 인정은 별도 승인 기록을 따릅니다. 원문 수정·취소·담당자 확인은 버전으로 보존하며 발송 직전 최신 신고·LMS를 대조합니다. 게시판 수집 실패·신고 불명·실제 기록 없음은 각각 구분합니다. 민감 사유는 일반 검색/공개 안내에 넣지 않습니다([F15](기능/F15_LMS_입퇴실.md)).

## 3. 권한 있는 검색

`로그인·작업 권한 확인 → 허용 과정·목적·문서 범위 필터 → 검색 → 필요한 근거만 AI 전달 → 원문·기준 시각 표시`

- 허용 범위 밖 문서는 모델에 보내기 전에 제외합니다.
- 요약·벡터·메모리에도 원본과 같은 범위를 적용합니다.
- 직원이라고 모든 면접 평가·병가 서류를 볼 수 있는 것은 아닙니다.
- AI가 서류 내용을 명령으로 해석해 도구 권한을 확대하지 못하게 합니다.
- 검색 실패·원문 없음·권한 없음·자료 미수집을 구분합니다.
- 동의 확보와 별개로 목적·접근·보관 기간을 실행 코드에서 검사합니다.

## 4. 저장 비용과 삭제

1. 파일 해시가 같은 자료는 같은 권한 범위에서 재분석을 피합니다.
2. SharePoint 원본이 유지되면 불필요한 Blob 복제를 피합니다.
3. 원본 변경 시 추출·요약·임베딩 버전을 갱신합니다.
4. 녹화는 전체 반복 처리보다 필요한 구간 분석을 기본으로 합니다.
5. 자주 안 쓰는 Blob은 보관 등급을 조정하되 복원 시간·조회 비용을 고려합니다.
6. 삭제는 원본·사본·검색 조각·벡터·요약·메모리로 전파합니다.
7. 백업은 보관 기간과 복구 후 삭제 재적용 절차를 정의합니다.
8. 정형 업무는 Excel 가져오기/내보내기를 지원합니다. 원본 영상·문서는 링크 목록으로 내보냅니다.

Excel 입력은 형식·동명이인·중복·변경 대상을 미리 검증합니다. 내보내기는 수식으로 해석되는 사용자 입력을 안전하게 처리합니다.

## 5. 실행 상태

```text
작성 → 검증 → 예약 → 실행 → 결과 확인 → 완료
                  ├ 승인 대기
                  ├ 재인증 대기
                  ├ 재시도 대기
                  ├ 결과 불명/담당자 확인
                  ├ 취소
                  └ 영구 실패
```

“명령을 보냈음”, “파일이 있음”, “메시지 발송 요청 성공”은 업무 완료와 같지 않습니다. 각 기능의 결과 확인 조건을 통과해야 완료로 기록합니다.

## 6. 중복 방지·복구

- 실행 키는 `과정 + 기능 + 규칙 버전 + 대상 + 발생 이벤트/예약 시각`으로 만듭니다.
- DB의 고유 제약으로 중복 실행 접수를 막습니다.
- outbox 재발행·대기열 중복 전달이 가능하다고 가정합니다.
- 외부 시스템이 멱등성 키를 지원하면 사용합니다.
- 지원하지 않는 PC 발송은 실행 전후 상태를 기록합니다. 결과 불명 시 재전송하지 않고 확인 대기로 전환합니다.
- 계정/브라우저 세션 잠금에는 유효시간과 실행 소유자를 둡니다. 죽은 실행기가 잠금을 영구 점유하지 않게 합니다.
- 업무 취소와 발송이 경합하면 외부 발송 직전 유효성을 재확인하고, 이미 발송된 사실은 보존합니다.
- 반복 실패는 실패 대기함에 넣고 운영국에 알립니다. 재처리 전 오래된 일정·대상·승인을 다시 확인합니다.
- 외부 메시지까지 포함한 “무조건 정확히 한 번 실행”은 보장하지 않습니다. 중복 차단·불명 상태 확인으로 피해를 제한합니다.

# 09. 데이터 컬럼 설계 및 표준 엑셀(Excel) 입출력 양식

[문서 목록](00_보고서_안내.md)

기준일: 2026-10-28

## 1. 목적 및 설계 원칙

원문 요구사항의 **데이터 컬럼 설계(만족도 양식 등) 및 엑셀 단위 데이터 수집·입출력 표준화**를 개발할 때 참고하는 **예시 양식 및 샘플 명세**입니다.

**Excel 예시 파일**은 기존 예시를 시트로 옮긴 설명용 합성 데이터입니다. 과정 종료 Forms의 자동 수집·3항목 예시는 이 MD와 F06의 최신 명세를 따릅니다. 실제 Forms 다운로드 파일·LMS 원천·기존 출결 사이트 결과를 검증한 증거가 아니며 실운영 연락·발송에 사용하지 않습니다. 시트명·컬럼·금액·담당 배정·완료 상태는 예시이며 만족도는 전체 과정 종료 시 1회 객관식 2개·주관식 1개만 운영합니다. 개인정보처럼 보이는 값도 예시이며 새 이메일 예시는 발송 불가 도메인 `example.invalid`를 사용합니다.

> **[중요 — LLM/개발자 구현 시 절대 고정(하드코딩) 금지 안내]**
> 1. **이 문서의 모든 시트명·컬럼 구성·문항·담당자/강사/기수 이름(`박명균`, `이대건`, `팀장님`, `책임님`, `권진욱`, `강명호`, `AI 5기` 등)은 이해를 돕기 위한 ‘예시’일 뿐 고정된 확정값이 아닙니다.** LLM이나 개발자가 이 문서의 컬럼·담당자 이름을 코드에 그대로 박아 넣으면(하드코딩하면) 안 됩니다.
> 2. **양식과 컬럼은 언제든 바뀔 수 있습니다:** 실제 운영 과정이나 기수·기관 요구에 따라 **컬럼 이름이 바뀌거나, 컬럼이 새로 추가·삭제**될 수 있으며, **아예 새로운 엑셀 양식이나 그 양식을 기반으로 한 신규 자동화 업무가 추가**될 수도 있습니다.
> 3. **배포 전 확인·실제 운영 과정에서 써보고 바로 수정 가능한 구조로 개발합니다:** 고정 컬럼에만 묶이지 않도록 DB에는 핵심 키 외에 **유연한 확장 필드(JSONB)·버전 관리(`form_versions`, `rule_versions`)·엑셀 컬럼 매핑 설정**을 두고, 실제 데이터를 넣어 확인해 보면서 화면/설정에서 컬럼 추가·삭제·이름 변경과 담당자 변경을 바로 반영할 수 있게 구현합니다.

- **사람의 공동 편집과 자동 파일 수집을 구분합니다.**
  1. **운영진·강사 문서:** 사람은 Teams/SharePoint 공유 엑셀·워드를 공동 편집합니다. 에이전트는 변경 알림·주기 조회로 저장 버전을 확인한 뒤 Drive API로 다운로드·파싱합니다. 원본 수정은 사람 담당이며 자동 결과는 별도 파일입니다. 원본과 다운로드 후 버전이 다르면 재수집합니다.
  2. **수강생 응답:** 과정 종료 만족도는 과정 종료 시 1회 객관식 2개·주관식 1개를 받습니다. 에이전트가 승인 템플릿의 Forms 준비·링크 확보, 양식별 Logic Apps 수집 연결, Teams 안내, 응답 검증·집계·결과 생성을 자동 실행합니다. 퀴즈·동의서·다른 설문은 각 기능의 준비/게시 기준을 따릅니다. 과정 종료 설문 응답 Excel 다운로드는 복구·대조용이며 다운로드 사본과 Forms 연결 Excel을 구분합니다([F06](기능/F06_만족도조사.md)).
- **공통 추적 필드:** 과정/회차 ID·양식/컬럼 매핑 버전·원본 파일 ID/eTag·수집 시각·사람 확인/게시 상태를 기록합니다. 예시의 ‘완료’ 상태는 화면 설명용 샘플이며 실제 자동화 검증 결과가 아닙니다.
- **기수별 구분 기본 포함**: 각 시트는 과정·기수 식별 키(예: `AI 5기`, `AI 11기`, `DT 3기` 등 — 모두 예시)를 기본으로 가집니다.
- **개발 인력과 운영 배정 예시 구분:** 현재 개발 담당 박명균은 05에 명시합니다. 이 문서의 OT·매니저·강사 배정은 운영 화면 설명용 예시이며 개발 인력 배치표가 아닙니다. 추후 인원이 배정되면 LLM 배치안과 사람 확인을 거쳐 설정으로 변경할 수 있습니다.
- **자료 위치와 시트 예시의 구분:** KDT 폴더 구조의 수강생 `일반`·기수별 운영 채널·강사팀을 구분합니다. 이 문서와 Excel 샘플의 `AI 5기` 등은 별도의 합성 데이터이며 실제 `AI 11기` 파일명·컬럼을 재현한 것이 아닙니다. 폴더·파일명은 테스트 및 운영을 하면서 바꿀 수도 있습니다.

## 4. 과정 종료 시 1회 만족도 — 객관식 2개·주관식 1개 (F06)

**만족도는 각 기수의 전체 과정 종료 시 이 Forms 한 종류만 1회 운영합니다.** 일별·중간·별도 다문항 최종·특강·멘토링 만족도 양식은 사용하지 않습니다. 수업일당 강의 1개라는 일정 단위와 만족도 발송 주기는 별개입니다.

### 4.1 문항과 표시

| 항목 | 문구 | 응답 |
|---|---|---|
| Q1 `preparation` | 본 과정의 교안과 수강 자료가 알차게 구성되었으며, 전체적인 강의 준비가 잘 이루어졌다고 느끼셨나요? | 5점 선택형·필수 |
| Q2 `clarity` | 본 과정에서 강사의 설명이 명확하고 이해하기 쉬웠으며, 수업 내용이 효과적으로 전달되었나요? | 5점 선택형·필수 |
| Q3 `comment` | [과정명]에서 가장 좋았던 점이나 보완이 필요한 점 또는 개선 의견이 있으면 자유롭게 적어주세요. | 주관식·기본 선택 |

선택지는 `매우 그렇다=5 / 그렇다=4 / 보통=3 / 아니다=2 / 매우 아니다=1`입니다. 화면은 선택형 표의 두 행과 주관식 입력란 하나로 총 3항목입니다. 준비도·설명/전달력 외 이해도·운영·취업 등의 질문을 별도 추가하지 않습니다. 기수·과정명·기간/종료일은 자동 표시하고 추가 응답 질문으로 받지 않습니다.

|---|---|---|---|---|---|---|
| COURSE-A | A기수 | 2026-10-28 18:00 KST | 종료 확인 예시 | COMPLETE-A | completion-v1 | COURSE-A+completion_survey |
| COURSE-B | B기수 | 2026-11-30 18:00 KST | 운영 중 | COMPLETE-B | completion-v1 | COURSE-B+completion_survey |

2026-10-28에는 종료한 A기수만 1회 안내하고 운영 중인 B기수에는 발송하지 않습니다. 시각·기간은 합성 예시입니다. 종료일 변경은 기존 예약을 갱신하며 매 수업일·강사별로 새 양식을 만들지 않습니다. 응답 링크·외부 문항/행 ID 매핑·workflow_id·OAuth 연결 참조·대상 명단 버전/인원·수집 상태를 함께 기록합니다.

| 과정 | 원본행 | 유효응답 | 중복 | 오류 | Q1평균 | Q2평균 | 두항목평균 | 주관식작성 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| COURSE-A | 4 | 2 | 1 | 1 | 4.0 | 3.0 | 3.5 | 1 |

계산은 Q1 `(5+3)/2=4.0`, Q2 `(4+2)/2=3.0`, 두 항목 `(5+4+3+2)/4=3.5`입니다. 주관식은 평균에서 제외합니다. 분모는 과정 종료 조사 대상 명단 기준 인원이며, 1인 1응답 확인 시 예시 대상 20명에 대해 `2/20=10%`입니다. 응답 2건은 계산 예시일 뿐 공개 허가·실적이 아닙니다.

화면은 과정별 두 항목 평균·응답 분포·주관식 주제/근거·수집 상태를 제공합니다. 같은 문항·척도의 종료 기수 간 비교만 허용하고 일별 강의 추이·강사별 순위로 해석하지 않습니다.

**기존 Excel 샘플:** `샘플_데이터_입출력.xlsx`는 이전 운영 가정의 예시이며 일별·다문항·별도 멘토링 등 구성이 남을 수 있습니다. 현재 만족도 문항·발송·집계 구현은 이 절과 F06을 기준으로 하며 구버전 샘플로 현재 운영을 재정의하지 않습니다. 이번 수정 범위는 MD입니다.

## 5. 기수별 하루 강의·여러 기수 동시 운영 — 1개월 단위 채널 수업 생성 (F04, F05)

**한 기수는 수업일마다 하루 강의 일정 1개를 운영하고, 같은 날짜에 여러 기수가 각자의 강의를 동시에 운영합니다.** 기수별 달력에는 해당 기수의 일별 강의 하나가 표시되고, 통합 달력에는 같은 날짜에 서로 다른 기수의 강의들이 함께 표시됩니다. 강사·과목은 날짜에 따라 바뀝니다. 공동 멘토링의 복수 담당자는 같은 하루 일정의 속성이며 별도 강의로 나누지 않습니다.

사람이 저장한 공유 일정표 또는 업로드 파일을 에이전트가 다운로드·파싱하고 다음 기준을 적용합니다.

1. **1개월 단위 발행:** 여러 달의 일정이 있어도 대상 월만 Teams 웹 채널 수업으로 생성하고 실제 참가 링크를 직원 Outlook에 연결합니다. 다음 달은 DB 대기로 둡니다.
2. **기수·날짜 구분:** 활성 강의 일정은 `(course_id, class_date)`당 하나입니다. 다른 기수의 같은 날짜·시간 일정은 허용하고 각각의 팀·채널·대상자를 연결합니다.
3. **강사 변경·공동 담당:** 날짜별 담당 강사 변경은 해당 날짜 일정에 반영합니다. 공동 멘토링은 같은 session_id에 여러 담당자를 연결하며 설문을 담당자 수만큼 만들지 않습니다.
4. **설문:** 각 기수의 전체 과정 종료 시 1회 객관식 2개·주관식 1개만 안내합니다. 일반 수업·휴강·특강·멘토링 종료에는 만족도를 보내지 않습니다.
5. **대상·권한:** 실제 팀·채널 유형·SharePoint 위치와 강사 접근을 확인하고 사전 승인된 범위에서만 연결합니다.

# KDT Teams 폴더 구조 및 기능별 자료 위치 예시

## 해석 기준

- 수강생 팀의 파일 공유는 `일반 (General)` 탭 안에서 합니다. 출결·교육문의·멘토링 요청 등의 게시판 채널은 소통용이며, 별도 파일 공유 위치로 가정하지 않습니다.
- SharePoint에서 확인한 `일반` 하위 폴더 이름과, 사용자가 제공한 세부 폴더·파일 목록을 함께 정리했습니다. 세부 구조 전체를 SharePoint에서 직접 열어 검증한 결과는 아닙니다.
- 날짜·시간·주차·이름·강사명·강의명·파일명 및 세부 폴더 구성은 예시이며 고정값이 아닙니다. 실제 구성은 테스트 및 운영을 하면서 바꿀 수도 있습니다.
- 아래 이름은 업무 흐름과 저장 위치를 설명하기 위한 참고 자료입니다. 모든 기수에 공통 적용되는 표준이나 자동화 연동·권한이 확인된 경로를 뜻하지 않습니다.
- 파일 내용은 확인하지 않았으며, 아래에는 제공된 폴더명과 파일명만 기록합니다.
- 트리의 `※` 행은 이름·날짜 규칙을 설명하는 주석이며 실제 폴더나 파일이 아닙니다.

아래 구분과 기능별 매핑을 설계 보고서·기능 명세·이미지의 공통 참고 기준으로 사용합니다. **구조 예시를 제공받은 것과 실제 자동화 연결을 확인한 것은 다릅니다.** 팀·채널 유형, 소속 팀, 테넌트·사이트·드라이브·폴더 ID 및 읽기·쓰기 권한은 연결 시 별도로 확인합니다.

## 자동화 설계 시 유의점

- 파일 공유 기준 위치는 `일반 (General)` 탭입니다. 위 예시 밖의 채널이나 폴더를 수강생 팀의 파일 공유 위치로 가정하지 않습니다.
- 폴더명 규칙은 검색·분류·보관 자동화의 후보로만 참고합니다. 날짜 형식, 강의명·강사명 표기, 회차·주차명은 실제 자료에 맞춰 조정해야 합니다.
- 이름이 비슷한 자료가 `05. 강의자료`와 `기타 자료` 양쪽에 있을 수 있으므로, 이름만으로 중복·최신본·정본 여부를 단정하지 않습니다.
- `03. 계정` 및 수강생 산출물 등에는 계정정보나 개인·민감정보가 포함될 수 있습니다. 자동화 적용 전 실제 파일 내용, 접근 권한, 처리 목적과 보관 기준을 확인해야 합니다.
- 이 문서는 폴더 구조 예시이며, 파일 내용 검토·계정정보 확인·권한 확인 또는 실제 자동 연동 검증을 의미하지 않습니다.

### 운영·자동화 검토 시 주의

- `중간평가 및 설문`은 기존 저장 위치 이름입니다. 만족도 유형을 여러 개 운영한다는 뜻이 아니며, 전체 과정 종료 시 1회 3항목 Forms → Logic Apps 응답 수집 → DB 집계 → 결과 Excel·요약 저장으로 개발합니다. 다운로드 사본은 장애 복구·대조용입니다. 참가 신청·동의서 등 다른 목적 양식은 해당 기능 기준을 따르며 실제 ID·권한·UI/수집 연결 검증은 별도입니다.
- 상담일지·중도퇴소·출결 경고·계정·합격자 명단·출석부 등은 개인 또는 민감정보가 포함될 수 있는 자료 유형입니다. 구조 예시만으로 자동 수집·열람·분석을 결정하지 말고, 목적·최소 권한·보관·승인 절차를 별도 확인합니다.
- 매뉴얼과 양식은 기수·시점에 따라 개정되거나 중복본이 있을 수 있습니다. 파일명만으로 최신본·적용 규정·업무 기준을 판단하지 않습니다.
- 제공된 일부 항목은 이름이 생략되거나 말줄임표로 잘려 있습니다. 원래 파일명을 추정해 보완하지 않았습니다.

### 강사팀 자료를 활용할 때의 주의

- 결과보고서·산출물·멘토링 일지·중간평가 문제·출석부는 파일명이 비슷하더라도 내용과 목적이 다를 수 있습니다. 파일명만으로 최신본, 승인본, 최종본 또는 평가 결과라고 판단하지 않습니다.
- 이름이 포함된 파일명은 구조 예시입니다. 자동화할 때는 꼭 필요한 경우에만 식별정보를 사용하고, 접근 권한과 보관·처리 목적을 먼저 확인합니다.
- 이 구조 예시만으로 강사 제출 여부 확인, 평가·상담 내용 분석, 출석 판단 또는 결과보고서 자동 작성이 검증되었다고 간주하지 않습니다.
