# 구현·운영 기준·비용 명세

[문서 목록](00_보고서_안내.md)



**워크샵 사전 참고안입니다.** 예산·일정·인력 배치를 승인받기 위한 문서가 아니며, 기간·공수·순서는 실제 테스트·운영에서 변경할 수 있습니다. 모델은 조사한 후보를 운영에 적용한 뒤 품질·수정률·속도·비용을 보며 더 좋은 모델 또는 더 가성비 있는 모델로 바꿉니다. 리전·지원 형식 역시 공통 참고 기준에 따라 갱신합니다.

## 1. 난이도 기준

| 수준 | 의미 | 해당 예 |
|---|---|---|
| 1 | 일반 입력·조회·양식 | 기본 명단 |
| 2 | 단일 서비스 연결 | 자료 수집·기본 설문 |
| 3 | 일정·여러 기능·예외 결합 | 퀴즈·진척도 |
| 4 | 권한·외부 상태·정확도 검증 | 테넌트 연결·LMS |
| 5 | 화면·정책·성능 불확실성이 큼 | 영상 관찰·새 사이트 |

숫자는 성공 확률이나 확정 공수가 아닙니다. 설정 가능한 설계와 실제 연결·호출 확인 결과를 구분합니다.

**일정 운영 기준(사용자 설명·캘린더 기준): 한 기수는 수업일마다 하루 수업 일정 1개를 운영하고, 같은 날짜에 여러 기수가 각각의 강의를 동시에 운영합니다.** 기수별 달력에는 해당 기수의 일별 수업 일정 하나가 보이며, 전체 달력의 같은 날짜에 보이는 여러 강의는 서로 다른 기수의 일정입니다. 강사·과목은 날짜에 따라 바뀔 수 있고, 공동 멘토링의 복수 담당자도 하루 일정 하나에 연결합니다. 오전·오후 출결이나 분할 녹화는 같은 하루 강의의 내부 구간입니다.

## 2. Teams 역할과 구현 순서

### 2.1 `@dataschool` 팀·채널 역할

아래 역할에는 사용자 제공 AI 11기 폴더 구조를 반영했습니다. **수강생 팀 `일반`·기수별 운영 채널·강사팀**은 서로 다른 자료 영역입니다. 이름·날짜·파일명은 참고 예시로 테스트 및 운영을 하면서 바꿀 수도 있습니다. 기수별 운영 채널의 소속 팀과 실제 ID·채널 유형·폴더·권한은 연결 시 확인하며, 기존 공통 팀을 기수마다 중복 생성하지 않습니다.

| 역할·팀 예시 | 채널·대상 | 에이전트 업무 |
|---|---|---|
| `{과정명} {기수} 수강생 팀` | 수강생·강사·운영진. `공지사항`, `01. 출결 게시판`, `02. LMS 정정 요청 게시판`, `03. 교육문의 게시판`, `04. 멘토링 요청 게시판`, `05. 기타 문의 게시판`, `06. 공유 게시판`, `10. 자유 게시판`, `일반` | `일반` 채널 수업 일정·참석 CSV 수집. **파일 공유는 `일반 / 공유 탭`에서만** 수행하며 `01. OT`·`02. 시간표`·`03. 계정`·`04. 타운홀 미팅`·`05. 강의자료`·`06. 프로젝트`·`07. 산출물`·`기타 자료`·`Recordings`를 참고. 다른 게시판은 안내·문의용이며 민감 원본을 첨부하지 않음 |
| `출석 관리 팀` | `{기수} 출석 관리팀` 등. 운영진과 대학교 등 외부 기관 담당자 | **외부 기관과 출석 업무가 있을 때** 승인된 출석부 공유·소통. 내부 출결 원본·증빙의 기본 보관소가 아님 |
| `강사팀` | `{기수} 강사팀 / 공유 탭` 등. 강사·운영진 | `강사님 양식(산출물, 결과보고서)`·`결과보고서`·`멘토링 일지`·`산출물`·`중간평가문제`·`출석부` 및 강사 매뉴얼. 호명 출석부 원본을 읽고 수강생 배포용 교안·일일 퀴즈 정답과 구분 |
| 기수별 운영 채널 (소속 팀 미확정) | `{기수} 채널 / 공유 탭` 예: `11기 채널`. 별도 `일반` 운영 보고 채널의 실제 소속·수신자는 연결 시 확인 | `교육자료 및 가이드라인`·`운영관리 매뉴얼`·`상담일지`·`중간평가 및 설문`·`출석부`·`커리어멘토링`·`타운홀미팅`·`프로젝트` 및 루트 명단·시간표. **`출석부 / 월 / 주차 / 일자`에 내부 3종 원본·종합본을 별도 파일로 보관**. 상담·계정·평가 결과 등은 실제 열람 권한 확인 |

현재 공통 팀에서 다른 기수 자료가 보일 수 있습니다. 문서에서 기존 자료가 기수별로 완전히 차단되어 있다고 가정하지 않습니다. 표준 채널은 팀 멤버십을 따르고 비공개·공유 채널은 별도 조건을 확인합니다. 에이전트는 넓은 열람 권한이 있어도 **해당 업무에 지정된 과정·파일만** 처리하며 기존 권한을 임의 회수하지 않습니다.

**보관과 외부 공유를 구분하는 업무 지시**

- 내부 보관: `대상 기수·수업일·파일 종류·버전 → 확인된 내부 출석부 폴더에 저장 → 결과 링크 보고`.
- 외부 업무: `기관·업무 목적·수신 채널/담당자·공유할 출석부 버전 지정 → 매니저 검수·승인 → 출석 관리 팀에 전달 → 전달 결과 기록`.
- 구조·위치가 미확정이거나 기관·자료·승인이 빠지면 확인 대기로 두고 임의 저장·외부 전송하지 않습니다. 병가 원본·판독 결과를 출석부와 함께 자동 외부 공유하지 않습니다.
- 운영 채널 시간표와 수강생 `일반 / 02. 시간표`의 기준 원본·배포본 관계를 지정합니다. 강의 단위 종료 Forms 응답은 Logic Apps 커넥터로 수집하고 에이전트가 집계 Excel·요약을 운영 채널 `중간평가 및 설문`에 생성하도록 개발합니다. 다른 설문 다운로드·강의 단위 종료 설문 복구 사본은 원천을 구분하며 현재 자동 수집 중이라는 뜻은 아닙니다. 제한된 개인 자료·일일 퀴즈 검수본·정답의 위치는 별도로 지정합니다.

### 2.2 구현 순서

1. **권한·대상 확인:** 세 계정 관리자 권한은 실환경 확인 절의 확인 사실을 사용합니다. 라이선스·정책과 실제 팀·채널·SharePoint 구조·공통 팀 가입의 영향을 별도로 확인합니다.
2. **연결 구축:** 저장된 파일 다운로드·파싱, Teams 채널 수업 일정의 컴퓨터 사용, 실제 회의 링크의 직원 Outlook 반영, 봇 안내·응답 수신, LMS·중간출결·출결 종합 사이트를 연결합니다.
3. **공통 플랫폼:** 기능 ON/OFF, 규칙 버전·예약·대기열·DB·권한·감사·사람 작업 대기 상태를 구현합니다. 확인된 역할·ID 매핑을 재사용합니다.
4. **주요 운영:** 사람이 편집한 OT·일정·면접·출석부를 읽습니다. 강의 시작 D-7 단체 채팅·준비 대사와 강의 단위 종료별 객관식 2개·주관식 1개 Forms 준비·수집 연결·안내·집계·결과 보관을 자동화합니다. 같은 기수의 연속 강의와 월 경계·일정 변경을 분리해 검증합니다. 퀴즈 검수·정답/배점·게시 등은 퀴즈 기준입니다.
5. **연결 기능:** 오전 첫 저장 완료 녹화로 오후 퀴즈 초안을 준비하고 검수·게시 후 안내합니다. LMS 증빙 1차 판독·매니저 최종 판단, 출결 게시판 사전 지각·조퇴·외출 일정 기반 LMS 대조·맞춤 안내, 3종 출결 종합·내부 보관, 승인된 외부 출석 업무, 운영 경보·영상 관찰을 연결합니다.
6. **운영 적용·개선:** 실제 연결·권한·대상·완료 조건을 확인한 기능을 운영에 적용합니다. 모델 품질·속도·가성비는 테스트·운영 중 측정하며 교체합니다. 사전에 최적 모델이나 고정된 품질을 확정해야 한다는 뜻은 아닙니다. 새 기수는 규칙·양식만 복제하고 실제 계정·채널·폴더를 다시 확인하며 미완성 연결을 작동 중으로 표시하지 않습니다.

### 2.3 개발 단계·일정 예시와 현재 담당

**현재 설계·개발·연결·배포·테스트 담당은 박명균입니다.** 아래 기간은 순서를 설명하려고 둔 참고용 입력 예시이며 실측 공수·납기·승인 요청이 아닙니다. 단계는 겹치거나 반복될 수 있으므로 단순 합산해 완료일로 사용하지 않습니다.

| 단계 예시 | 범위·산출물 예시 | 기간 예시(변경 가능) | 현재 개발 담당 | 확인할 결과 예시 |
|---|---|---|---|---|
| 1. 공통 연결 | 직원 로그인·파일 수집·DB·Teams 안내 | 1~2주 | 박명균 | 허용 대상 처리와 범위 밖 접근 차단 |
| 2. 첫 운영 흐름 | 과정·기능 설정·OT 준비·강의 준비 단체 채팅·강의별 만족도·대시보드: 설정·체크리스트·D-7 단체 채팅·강의 단위별 3항목 Forms | 2~3주 | 박명균 | 같은 기수의 연속 강의 각 1회 조사·중간 일자 미발송·채팅/응답 분리 검증. 기간은 기존 참고 예시 |
| 3. 일정·수업 확장 | [강의 준비 단체 채팅](02_과정_설정과_일정_운영.md#lecture-preparation-chat)·[수업 일정·Outlook 연결](02_과정_설정과_일정_운영.md#class-outlook-calendar)·[퀴즈](04_수업_자료와_학습_지원.md#quiz)·[질문·답변 취합](04_수업_자료와_학습_지원.md#class-questions-answers), 월별 수업·퀴즈·Q&A | 2~4주 | 박명균 | 실제 회의 링크 일치, 검수·게시 대기 구분 |
| 4. 사이트·분석 확장 | [증빙·반려 안내](06_출결과_증빙_처리.md#document-review)~[중간 출결·종합](06_출결과_증빙_처리.md#attendance-merge)·[컴퓨터 사용 자동화](01_공통_아키텍처.md#computer-automation), 필요한 문서·영상 분석 | 2~4주 | 박명균 | 원천 대조·실패 경보·승인 후 안내 |
| 5. 운영 중 개선 | 모델·비용·파서·절차 갱신 | 계속 조정 | 박명균 | 수정률·오류·지연·비용 기록으로 개선 |

추후 인원이 배정되면 역할·가용 시간·경험·의존 작업을 입력해 **LLM으로 배치안을 생성하고 담당자가 확인한 뒤 설정으로 반영**합니다. 현재 담당자나 예시 이름을 코드에 고정하지 않으며, 학생·강사의 실제 업무 역할과 개발 인력 배치를 혼동하지 않습니다.

## 3. 공통 운영 품질 기준

수치는 제안 목표이며 현재 달성한 성능이 아닙니다. 배포 전 확인과 운영 중 로그·대시보드로 점검하고, 기준 이탈은 해당 기능 중단·담당자 경보로 처리합니다.

| 항목 | 확인 상황 | 기준 |
|---|---|---|
| 노트북 독립 | 운영자 PC 종료 | 서버 자동 실행, 사람 단계는 대기 표시 |
| 권한·대상 | 다른 기수 자료가 보이는 계정·잘못된 폴더 | 업무 범위 밖 수집·전달 0건, 미확정 경로 쓰기 차단 |
| 원본 문서 | 사람의 동시 편집·버전 변경 | 원본 덮어쓰기 없음, 저장된 버전 대조·재수집 |
| 일정 | 월별 발행·재시도·휴강·강사 교체 | 지정 1개월만 생성, 동일 채널 수업 중복 생성 방지 |
| 강의 단위별 준비·만족도 | D-7 채팅·준비 대사, 강의 종료별 1회 조사·중간 일자 차단·일정 변경·중복/인증/수집 장애 | 같은 기수의 연속 강의·월 경계에서도 방/양식/응답 분리, 객관식 2개·주관식 1개·원본 일치 집계, 장애를 0건으로 표시하지 않음 |
| 퀴즈 | 오전 파일 지연·분할 녹화·미검수·미게시 | 없는 구간을 근거로 쓰지 않음, 게시 링크 확인 전 발송 차단 |
| 과정 유연성 | 단기·출결 없음·수기 입력 | 등록된 기능은 설정 조합, 수기 확인·입력은 사람 |
| 취소·중복 | 변경·전송 직후 응답 유실 | 취소 발송 0건, 결과 불명은 확인 대기 |
| LMS·증빙 | 사전 지각/조퇴/외출 신고·수정/취소·승인 대기·게시판/LMS 수집 장애·저화질 | 신고 예정별 확인 시각 조정·잘못된 일반 독촉 방지, 실제 시각 별도 보존, 공식 인정/반려는 매니저. LMS 입퇴실 확인 사례 검증 |
| 출결 보관·외부 공유 | 내부 종합본·기관별 출석 업무 | 내부 출석부 폴더 보관과 승인된 외부 전달을 별도 완료 상태로 관리 |

## 6. 확인 기록과 미확인 목록의 관리

실환경 확인 절은 확인한 값·근거·실패 결과를 보존하고, 연결 체크리스트 절은 미확인·미결정 항목을 관리합니다. 완료한 체크 항목은 근거·확인일을 실환경 확인 절에 기록한 뒤 체크리스트에서 제거합니다. 관리자 요청을 보냈다는 것만으로 완료 처리하지 않습니다.

| 지정 발신자 메일 전송 | Exchange `Application Mail.Send` | 필요한 발신 메일함으로 제한 |
| 팀 강사 구성원 추가 | Graph `TeamMember.ReadWrite.All` 또는 작업에 지원되는 최소 범위 | 표준 채널은 팀 가입을 따름. 공통 팀 가입으로 다른 기수 자료가 보일 수 있으므로 실제 구조와 사전 승인 범위 확인 |
| 비공개·공유 채널 강사 추가 | Graph `ChannelMember.ReadWrite.All` 등 해당 API 지원 권한 | 표준 채널 가입의 대체 권한이 아님. 채널 유형·참여 조건·기존 팀 관계 확인 후 사용 |
| 특정 팀의 채널 읽기 | Teams RSC `ChannelMessage.Read.Group` | 해당 팀에 앱 설치·리소스 동의 |
| 강의 준비 그룹 채팅 생성 | Graph `Chat.Create`(위임/애플리케이션 지원) | 기수·강의 단위·참여자·조직 조건 확인, 생성 후 chat_id 바인딩 |
| 준비 채팅에 앱 설치 | `TeamsAppInstallation.ReadWriteSelfForChat.All` 등 작업별 최소 권한 | 해당 앱의 RSC 동의 필요 여부·카탈로그/정책 확인. 설치와 메시지 발송 별도 검증 |
| 특정 채팅 읽기 | Teams RSC `ChatMessage.Read.Chat` | 해당 채팅 범위 동의 |
| 특정 팀 채널 발송 | Teams RSC `ChannelMessage.Send.Group` 또는 지원되는 봇 발송 경로 | 실제 API/SDK·가용 상태·설치 조건 확인 |
| 특정 회의 녹취 | Teams RSC `OnlineMeetingTranscript.Read.Chat` | 회의/채팅 범위·자료 생성 조건 |
| 특정 회의 녹화 | Teams RSC `OnlineMeetingRecording.Read.Chat` | 회의/채팅 범위·자료 생성 조건 |
| 지정 SharePoint 파일 읽기·별도 결과 파일 저장 | Graph `Sites.Selected` + 대상 사이트의 작업별 허용 범위 | Drive API 다운로드·파싱 및 지정 결과 폴더 쓰기. Excel 셀 API의 애플리케이션 권한은 미지원이며 Word 원문 편집도 별개. 원본 수정은 사람이 수행 |

RSC 문서는 일부 권한에 연결된 기능이 GA가 아닐 수 있다고 안내합니다. 권한 이름이 목록에 있다는 것과 선택한 API 조합이 운영 가능하다는 것을 구분해 배포 전 확인합니다.

Exchange Application RBAC와 Entra에 직접 부여한 전역 권한은 독립 경로입니다. 범위 제한을 해 놓고 전역 권한을 함께 부여해 제한을 무력화하지 않도록 합니다. `Test-ServicePrincipalAuthorization` 검사만으로 Entra의 별도 권한까지 검사되는 것은 아니므로 실제 API의 범위 밖 거부도 확인합니다.

## 7. 관리자 역할 해석

- Azure Owner: 해당 구독의 리소스·Azure RBAC 관리.
- Entra Global Administrator/적절한 동의 관리자: 해당 조직의 앱·권한 승인.
- Teams Administrator: Teams 정책·앱 관리.
- Exchange Administrator: 메일·일정 관련 설정.
- Power Platform 환경 역할/Dataverse 역할: Copilot Studio를 사용할 때의 별도 조건.

세 계정(`@msacademy`, `@elixirr`, `@dataschool`) 모두 현재 사용자 계정에 **Global Administrator** 역할이 있음을 확인했습니다. 다만 관리자 계정의 전체 권한을 에이전트에 그대로 부여하지 않고, 각 조직에 신규 연결 앱을 등록해 아래 최소 권한만 부여합니다.

### 회사(`@elixirr`) 및 교육(`@dataschool`) 테넌트에 직접 설정할 최소 범위

1. 신규 연결 앱 등록 및 소유자 지정.
2. 합의된 Graph 애플리케이션 권한 및 RSC 권한에 대한 관리자 동의.
3. Exchange Application RBAC로 지정 캘린더·발신 메일함 범위 제한 설정.
4. Teams 앱 설치·사용 정책 및 보고/안내 대상 채널 설정.
5. 회사 직원 로그인 앱의 허용 사용자/그룹과 운영 역할 설정.

## 8. 연결 방식의 선택

현재 기준안은 **테넌트별 앱을 중앙 서버에 연결**하는 방식입니다. 세 조직의 승인을 각각 명확하게 검증하기 쉽습니다.

향후 연결 기관이 많이 늘면 멀티테넌트 앱과 조직별 서비스 주체·관리자 동의로 설치를 표준화할 수 있습니다. 멀티테넌트 앱도 상대 조직의 동의는 필요합니다.

단순 API 연결을 위해 직원·학생 전체를 B2B 게스트로 복제하거나 테넌트를 합병할 필요는 없습니다. 특정 UI·협업 기능에 필요한 교차 테넌트 설정은 해당 기능에 한정해 판단합니다.
