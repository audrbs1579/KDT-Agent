# 11. 추후 업데이트

[문서 목록](00_보고서_안내.md)



현재 기능([F01](기능/F01_과정_기능_규칙.md)~[F19](기능/F19_컴퓨터유즈_경험메모리.md), [F21](기능/F21_대시보드.md))과 구분하여 **지금 개발하지 않는 후보와 그 이유**만 정리합니다. 이는 워크샵 참고 범위이며 도입 여부·순서·일정은 실제 테스트·운영 필요에 따라 바뀔 수 있습니다. 범위 변경은 원문 대비 설명표에도 함께 반영합니다.

## 기능과 제외 이유

| ID | 기능 | 하는 일 | 추후로 둔 이유 |
|---|---|---|---|
| **U01** | 경험 개선 | 컴퓨터 사용의 성공·실패 기록으로 절차·프롬프트 개선 후보 생성. R07 DB와 향후 Memory·Optimizer 계열 서비스 활용 검토 | 충분한 운영 기록이 먼저 필요하고 서비스·자동 변경의 신뢰성 확인이 필요함. Memory·Optimizer는 현재 리소스 구성에 포함하지 않는 추후 후보 |
| **U02** | 카카오톡 일반 단체방 읽기·공지(기존 F20) | 필요한 기수에 한해 전용 Windows VM·PAD로 PC 앱 대화 확인·공지 | 기본 방향은 Teams 일원화지만 **기존 단톡방은 갑자기 없애지 않고 단계적으로 전환**. 다른 기수에는 카카오톡이 계속 필요할 수 있음. 일반 단톡방 읽기 공식 API 부재·화면 변경·정책·유지 부담 때문에 지금 구축하지 않음 |
| **U03** | 단위기간 서류 이메일·고용24 제출 패키지 | 원문의 단위기간 제출 서류 이메일과, 기간별 출결·승인 증빙을 기관 양식으로 묶는 업무 | 현재 F17은 과정별 출결 모드이며 단위기간 이메일 기능이 아님. 서류·수신자·기관 양식·승인 규칙을 확인한 뒤 별도 설계·구현 |
| **U04** | 기존 출결 종합 사이트 내재화 | 별도 VM 「MS 출결 정보 자동 업데이트」의 3종 파일 병합을 에이전트 서버 내부로 구현 | 기존 사이트의 컴퓨터 사용 경로를 먼저 활용하고, 동일 기능의 중복 개발·기존 계산과 차이가 생기는 위험을 줄임 |
| **U05** | Forms 생성·입력·게시 자동화 | 설문·퀴즈 문항 생성 화면 입력부터 정답·배점·게시까지 자동 연결 | 현재는 사람이 Forms를 준비·검수·게시하고 응답 화면에서 Excel을 다운로드해 전달하면 에이전트가 집계. 화면 자동화는 실제 UI·권한·가져오기 한계·정답 설정과 결과 검증이 추가로 필요함 |

## 도입 시 지킬 기준

- **U01:** 규칙·절차 원본은 DB, 자동 개선 평가는 실제 발송이 차단된 도구로 수행하고 사람 검토 후 적용.
- **U02:** 기수별 채널 전환 상황을 확인하고, 도입할 때 방·계정·수신 대상·전송 결과를 검증. Teams 사용을 이유로 기존 기수의 필요한 소통을 갑자기 중단하지 않음.
- **U03:** [F14](기능/F14_LMS_서류_반려안내.md) 증빙·[F16](기능/F16_중간출결.md) 일일 출결의 원본과 매니저 판단을 재사용하되 기관별 제출·승인을 별도로 확인.
- **U04·U05:** 기존 결과와 대조하고 오류·부분 완료·재시도를 확인한 뒤 도입. 사람 확인이 필요한 단계까지 무조건 자동화한다고 약속하지 않음.
