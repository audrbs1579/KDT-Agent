# 추후 확장

[문서 목록](00_보고서_안내.md)



현재 기능([과정·기능 설정](02_과정_설정과_일정_운영.md#course-settings)~[컴퓨터 사용 자동화](01_공통_아키텍처.md#computer-automation), [대시보드](08_운영_경보와_대시보드.md#operations-dashboard))과 구분하여 **지금 개발하지 않는 후보와 그 이유**만 정리합니다. 이는 워크샵 참고 범위이며 도입 여부·순서·일정은 실제 테스트·운영 필요에 따라 바뀔 수 있습니다. 범위 변경은 원문 대비 설명표에도 함께 반영합니다.

## 기능과 제외 이유

| 기능 | 하는 일 | 추후로 둔 이유 |
|---|---|---|
| 경험 개선 | 컴퓨터 사용의 성공·실패 기록으로 절차·프롬프트 개선 후보 생성. R07 DB와 향후 Memory·Optimizer 계열 서비스 활용 검토 | 충분한 운영 기록이 먼저 필요하고 서비스·자동 변경의 신뢰성 확인이 필요함. Memory·Optimizer는 현재 리소스 구성에 포함하지 않는 추후 후보 |
| 카카오톡 일반 단체방 읽기·공지(기존 카카오톡 소통) | 필요한 기수에 한해 전용 Windows VM·PAD로 PC 앱 대화 확인·공지 | 기본 방향은 Teams 일원화지만 **기존 단톡방은 갑자기 없애지 않고 단계적으로 전환**. 다른 기수에는 카카오톡이 계속 필요할 수 있음. 일반 단톡방 읽기 공식 API 부재·화면 변경·정책·유지 부담 때문에 지금 구축하지 않음 |
| 기존 출결 종합 사이트 내재화 | 별도 VM 「MS 출결 정보 자동 업데이트」의 3종 파일 병합을 에이전트 서버 내부로 구현 | 기존 사이트의 컴퓨터 사용 경로를 먼저 활용하고, 동일 기능의 중복 개발·기존 계산과 차이가 생기는 위험을 줄임 |
| 표준 강의 단위 만족도 외 범용 Forms·퀴즈 생성/게시 자동화 | 새 유형의 문항·정답·배점·게시 일반화 | 강의 단위 종료별 객관식 2개·주관식 1개 Forms 준비·안내·응답 수집은 강의별 만족도 현재 범위. 다른 임의 양식·퀴즈는 UI·권한·정답 검증 필요 |

## 도입 시 지킬 기준

- **경험 개선:** 규칙·절차 원본은 DB, 자동 개선 평가는 실제 발송이 차단된 도구로 수행하고 사람 검토 후 적용.
- **카카오톡 소통:** 기수별 채널 전환 상황을 확인하고, 도입할 때 방·계정·수신 대상·전송 결과를 검증. Teams 사용을 이유로 기존 기수의 필요한 소통을 갑자기 중단하지 않음.
- **범용 양식 자동화 범위:** 승인된 강의 3항목 템플릿 자동화까지 추후로 미루지 않습니다. 강의별 만족도의 양식별 연결·UI/인증 검증을 통과해 적용하고, 다른 설문·퀴즈는 해당 기능 기준을 유지합니다.
- **출결 종합 내재화·범용 양식 자동화:** 기존 결과와 대조하고 오류·부분 완료·재시도를 확인한 뒤 도입. 사람 확인이 필요한 단계까지 무조건 자동화한다고 약속하지 않음.
