# F02. 모집·지원자·면접 기록

[전체 목록](../00_보고서_안내.md)

난이도: 2~3

## 목적

지원서와 인성·기술 면접 기록을 같은 사람에게 연결하고, 매니저가 근거를 찾아볼 수 있게 합니다.

## 입력·설정

Forms 지원서는 응답 화면에서 Excel로 다운로드한 파일을 받습니다. 파일 형식·파서·모델은 현재 조사한 구현 후보이며 실제 테스트·운영에서 결과를 보고 바꿀 수 있습니다. 원본 접수와 내용 추출 성공을 구분합니다.

지원자 Excel(또는 Forms 지원서 응답 다운로드 Excel), **비정형 지원서·자소서·포트폴리오 파일(아래아한글 `.hwp`/`.hwpx`, `.pdf`, 노션/웹 내보내기 `.html`/`.md`, `.docx`, `.pptx`, 이미지 등 조사한 지원 후보)**, 면접 일정, 면접관, **Teams/SharePoint에서 여러 면접관·매니저가 실시간 동시 편집하는 면접 평가 공유 엑셀**, 모집 과정, 열람 역할, 보관 기간. 실제 접수 가능 형식·한도는 설정으로 관리하고 추출 미지원·실패는 사람 확인으로 남깁니다. 합격·대기·불합격 상태는 담당자가 확정합니다.

## 처리 구조

**자료 위치 참고:** 운영 채널 구조 예시의 루트 합격자 명단은 입과 명단의 입력 후보이지 지원서·면접 평가 원본이 아닙니다. 지원서·면접 평가·AI 요약은 모집 담당자 제한 위치를 별도로 지정하고 수강생 팀 `일반`에 공개하지 않습니다. 기수·파일명은 참고용으로 바뀔 수 있으며 실제 ID·권한·컬럼을 확인한 뒤 연결합니다.

```text
파일/양식 접수 → 형식·중복·필수값 검사
→ 지원자 임시 기록 → 인물 매칭 확인
→ 원본 보관(SharePoint/Blob) + 형식별 비정형 텍스트·표 추출
  (.pdf·.html·.docx·.pptx·이미지는 R16 Content Understanding, .hwp·.hwpx는 서버 한글 파서/PDF 변환 후 추출 → PostgreSQL extracted_fields JSONB 저장)
→ Teams/SharePoint 면접 평가 공유 엑셀 연결
→ 인성·기술 면접관이 공유 엑셀에 동시 편집으로 점수·메모 입력 (또는 엑셀 업로드) → 에이전트가 저장된 버전의 파일을 Drive API로 다운로드·파싱해 취합·근거 요약
→ 입과 확정 시 수강 등록 생성
```

정형 값은 DB로, 원본은 SharePoint/Blob으로 저장합니다. 문서마다 양식이 다른 비정형 자소서·포트폴리오 항목은 PostgreSQL `document_versions.extracted_fields (JSONB)`와 `chunks`에 저장합니다.

## 리소스·권한

PostgreSQL, SharePoint/Blob, Container Apps, Foundry. 면접관·모집 담당자의 역할로 제한하며, 강사나 다른 과정 학생에게 평가 내용이 노출되지 않게 합니다.

## 저장·출력

`people`, `applications`, `interview_sessions`, `interview_scores`, `documents`, `enrollments`.

평가 필드: 작성자, 평가 시각, 질문/항목 버전, 점수, 관찰 메모, 원문 근거. AI 요약과 면접관 원문은 별도 필드입니다.

출력: 지원자 카드, 면접 일정, 인성/기술 평가표, 누락 자료 목록, Excel 내보내기. 표준 엑셀 시트 컬럼과 샘플은 09 데이터 컬럼·엑셀 양식을 따릅니다.

## 예외·승인

- 동명이인·같은 연락처·여러 계정은 자동 병합하지 않고 확인합니다.
- 추출 실패 자료는 원본 상태로 보관하고 수동 확인을 요청합니다.
- AI가 합격·불합격을 확정하거나 개인의 성격을 사실처럼 추론하지 않습니다.
- 등록 전 탈락자 자료도 정해진 보관 기간을 적용합니다.
- 기업 제공·외부 면접관 제공은 허용 목적과 접근 기간을 확인합니다.

## 운영 품질 기준

동명이인과 복수 지원을 분리하고, 입과 후에도 면접 원문이 올바른 수강생과 연결되어야 합니다. 추출된 점수·연락처를 원본과 표본 대조하고, 권한 없는 계정의 조회는 차단되어야 합니다.
