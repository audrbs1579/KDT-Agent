# F04. Teams 강의·강사 소통·유연한 업무 추가

[전체 목록](../00_보고서_안내.md)

난이도: 3~4

## 목적

`@dataschool`에서 온라인 강의와 **여러 강사·학생 소통**을 기본 운영하고, `@elixirr` 직원 Teams에는 필요한 보고·승인만 전달합니다.

한 기수 안에서도 **일자별·교과목별로 담당 강사가 계속 바뀌거나(예: 권진욱 → 강명호 → 인선미 → 권진욱) 하루에 여러 강사가 시간을 나누어 공동 수업·멘토링을 진행**하므로, 캘린더 일정에 매핑된 **해당 날짜·해당 과목의 실제 담당 강사(들)**에게 교안 확인·출석부 점검·Q&A 전달이 자동으로 라우팅됩니다.

## 입력·설정

과정·강사풀·회차별 시작/종료 시각·순서, 학생 계정, `@dataschool` 팀·채널의 업무 역할·구성원 설정, 주최자·월별 일정, 교안·출석부 위치, 확인 양식·대상·마감·재안내·예외. 수강생 팀·강사팀·내부 기수 채널·외부 출석 관리 팀을 구분하고 실제 구조·채널 유형·파일 경로 확인 후 등록합니다.

### 자료 위치·제출 구분

폴더 구조 예시의 강사팀에는 `강사님 양식(산출물, 결과보고서)`·`결과보고서`·`멘토링 일지`·`산출물`·`중간평가문제`·`출석부`가 있습니다. 이 위치별 자료 종류와 회차·강사·파일 버전을 대조해 제출 여부를 확인합니다. 결과보고서 날짜가 `YYYYMMDD`·`YYMMDD`로 혼재하므로 파일명만으로 강사·수업·제출 완료를 확정하지 않습니다.

학생에게 배포하는 교안은 수강생 `일반 / 05. 강의자료`, 프로젝트 안내는 `일반 / 06. 프로젝트`, 학생 산출물은 `일반 / 07. 산출물`을 참고합니다. **강사팀 산출물·결과보고서와 학생 배포 교안·산출물은 별개**이며 자동 복사하지 않습니다. 같은 이름의 자료가 `기타 자료`·운영 채널 `교육자료 및 가이드라인`에도 있으면 정본·버전을 확인합니다. 날짜·강사명·파일명·구성은 테스트 및 운영을 하면서 바꿀 수도 있으며 실제 ID·권한은 연결 시 확인합니다.

## 처리 구조

```text
과정 활성화 및 엑셀 일정표(1개월 단위 배치) 동기화
→ 실제 팀·채널·공통 팀 관계·권한 범위 확인 후 기존 연결 매핑
→ 강사 접근 확인: 표준 채널은 팀 가입, 비공개·공유는 별도 참여 조건 확인
→ 사전 승인된 누락 구성원만 추가, 불명확한 권한 영향은 매니저 확인 대기
→ 멤버·앱 설치·문서 권한 확인
→ 일자별·교과목별 담당 강사(단독 또는 복수 강사) 자동 매칭 및 수업별 확인·출석부/중간평가 수거 업무 생성
→ 수업 전날/당일 해당 강사에게 `강사팀 > {기수} 강사팀`(또는 강사 개인 봇 채팅)으로 확인·출석부/중간평가 업로드 안내 자동 발송
→ 응답자 권한·업무 버전 확인
→ 상태 저장
→ 소속 팀·수신자·권한을 확인한 기수별 운영 보고 채널 및 `@elixirr` 직원 대시보드 보고
```

예: “전날 교안 확인”을 “교안 링크 + 실습 환경 확인 + 당일 강의 계획”으로 바꾸면 양식·조건·템플릿 버전을 갱신합니다.

## 리소스·권한

Teams 앱/SDK, Microsoft Graph, Foundry, PostgreSQL, Durable Functions, Service Bus, SharePoint.

- 읽기: 필요한 팀·채팅의 RSC 지원 여부와 범위 확인.
- 발송: 설치된 앱/봇과 대화 컨텍스트 사용.
- 신규 팀·채널·멤버 생성: 해당 Graph 권한 별도 확인.
- 회의·녹화: 메시지 권한과 별개. F05의 Teams 웹 채널 수업 생성·실제 참가 링크 Outlook 연결을 사용.

Graph의 관리자 동의만으로 설치·메시지 수신·발송 조건이 모두 충족되지는 않습니다.

공통 팀에서 다른 기수 자료가 보일 수 있습니다. 기존 기수별 격리를 가정하거나 기수마다 공통 팀을 새로 만들지 않습니다. 호명 원본은 강사팀 `출석부`에서 읽고, 내부 3종 원본·종합본의 보관은 운영 채널 `출석부 / 월 / 주차 / 일자`로 구분합니다. 출석 관리 팀은 승인된 외부 기관 출석 업무에만 사용합니다.

## 저장·출력

`channel_bindings`, `class_sessions`, `tasks`, `form_versions`, `delivery_attempts`.

대화 대상은 tenant ID와 외부 ID로 저장합니다. 메시지 ID·응답 시각·상태를 기록하되 전체 회사 대화를 불필요하게 보관하지 않습니다.

## 예외·승인

- 앱 미설치·정책 차단·삭제된 팀: 연결 장애로 표시.
- 강사 변경: 기존 강사 재안내 취소, 새 강사에 새 업무 배정.
- 오래된 카드 응답: 적용된 양식/업무 버전을 확인해 갱신 안내.
- 대량 또는 민감 발송: 대상 미리보기와 승인.
- 채널이 바뀌면 과거 응답·작업 이력은 보존.
- 읽기·쓰기 경로가 막혔다고 PC 조작으로 조직 권한을 우회하지 않음.

## 운영 품질 기준

강사 확인 항목 추가·발송 시각 변경·재안내 취소가 설정만으로 가능해야 합니다. 교체된 강사에게 오발송하지 않아야 합니다. 직원용 민감 보고가 학생 채널에 나타나지 않아야 합니다.
