# F05. Teams 채널 수업 일정·직원 Outlook 연결

[전체 목록](../00_보고서_안내.md)

난이도: 4

## 목적

매니저가 일일이 만들던 **Teams 채널 수업 이벤트를 저장된 일정표에 따라 1개월씩 생성·수정**하고, 실제 참가 링크를 `@elixirr` 직원 Outlook 일정에 연결합니다. 학생에게 직원 개인 일정 전체를 공유하지 않습니다.

**일정 운영 기준(사용자 설명·캘린더 기준): 한 기수는 수업일마다 하루 강의 일정 1개를 운영하고, 같은 날짜에 여러 기수가 각각의 강의를 동시에 운영합니다.** 기수별 달력에는 해당 기수의 일별 강의 하나가 보이며, 전체 달력의 같은 날짜에 보이는 여러 강의는 서로 다른 기수의 일정입니다. 강사·과목은 날짜에 따라 바뀔 수 있고, 공동 멘토링의 복수 담당자도 하루 일정 하나에 연결합니다. 오전·오후 출결이나 분할 녹화는 같은 하루 강의의 내부 구간입니다.

## 입력·설정

- 사람이 M365에서 공동 편집한 근무표·커리큘럼 일정표의 저장 파일 또는 업로드 파일.
- 과정·기수·일자·과목·회차 ID, 기수별 하루 강의 시작/종료 시각, 당일 담당 강사(공동 멘토링은 복수 담당자), 휴일·수업/행사 구분, 담당 매니저·시간대.
- 대상 연월(`YYYY-MM`), 교육 주최자, 실제 팀·채널 유형·ID, 직원 Outlook 캘린더, 사전 승인된 멤버 추가 범위.

에이전트는 SharePoint Drive API로 파일 버전·변경을 확인하고 **다운로드·파싱**합니다. 원본 셀 편집과 누락된 강사 시간 입력은 사람 담당입니다. 09 일정 예시의 총시간만으로 강의 시작·종료 시각을 추정하지 않습니다.

**일정표 위치 예시:** KDT 폴더 구조의 운영 채널 루트 `AISCHOOL 11기_시간표.xlsx`와 수강생 `일반 / 02. 시간표 / AISCHOOL 11기 시간표.xlsx` 중 **기준 원본과 배포본 관계를 지정**합니다. 두 파일을 번갈아 원본으로 삼거나 이름만으로 자동 동기화하지 않습니다. 수업 대상은 수강생 팀의 지정된 `일반` 채널이며, 날짜·기수·파일명은 테스트 및 운영을 하면서 바꿀 수도 있습니다. 실제 파일 ID·채널 유형·권한은 별도 확인합니다.

## 처리 구조

```text
저장된 일정표 변경 확인 또는 월별 발행 시각 도래
→ 원본 버전·기수·대상 월·기수별·수업일별 강의 1개·시각·휴일 검증
→ 전체 기간 중 지정된 1개월만 발행 대상으로 선택
→ 실제 팀·채널 유형·강사 접근 확인, 사전 승인된 추가만 수행
→ 컴퓨터 사용으로 Teams 웹 일정에서 해당 채널 수업 생성·수정
→ 실제 수업 일정·주최자·시간·회의 링크 확인
→ 같은 참가 링크를 직원 Outlook 일정에 Graph로 반영
→ 원본 회차와 Teams 일정 참조·조회 가능한 ID·Outlook 이벤트 ID 연결
→ 해당 회차의 강사 확인·출결·퀴즈 예약 재계산
→ 전체 과정 종료일·마지막 수업 종료 변경 시 F06 종료 설문 예약 갱신
  (과정 종료 시 객관식 2개·주관식 1개, 기본 안내 1회.
   일일 수업·중간·특강·멘토링 종료만으로 설문을 발송하지 않음)
```

- **월별 발행:** 6개월 일정표가 있어도 지정 월만 생성하고 나머지는 DB 대기 상태로 둡니다.
- **기수별 하루 일정:** 같은 기수·수업일에는 강의 일정 1개만 생성합니다. 날짜가 바뀌면 과목·강사가 바뀔 수 있습니다. 공동 멘토링은 같은 하루 일정에 담당자를 복수 연결하고 별도 강의로 분할하지 않습니다.
- **여러 기수 동시 운영:** 같은 날짜·시간의 다른 기수 일정은 각각 생성하며 기수·팀/채널·강사·설문·회의 링크를 구분합니다. 통합 달력의 여러 카드를 한 기수의 복수 강의로 해석하지 않습니다.
- **멤버십:** 표준 채널은 팀 가입을 따릅니다. 비공개·공유 채널은 별도 조건을 확인합니다. 공통 팀 가입으로 다른 기수 자료가 보일 수 있으므로 확인되지 않은 채널에 임의 가입시키지 않습니다.
- **휴강·방학:** 대상 회차 발행과 관련 자동 작업을 중지하고 기존 예약은 취소·재계산합니다.

일반 캘린더 온라인 회의를 만든 뒤 채널에 링크를 게시하는 것은 **실제 채널 수업 생성과 다릅니다**. 채널 수업은 Teams 웹 일정 경로를 사용하고, 일반 행사 회의는 회의 유형을 명시한 별도 지원 API 경로로 구분합니다.

## 리소스·권한

Teams 웹 일정·[F19](F19_컴퓨터유즈_경험메모리.md) 컴퓨터 사용, Exchange Online/Graph, SharePoint Drive API, PostgreSQL, Durable Functions/Task Scheduler, Service Bus.

Teams 주최자·라이선스·회의 정책·로그인/MFA·조건부 접근과 화면 절차는 실제 환경에서 확인해야 합니다. 직원 일정은 허용된 메일함·필드만 읽고 씁니다. 실제 파일·채널 구조가 확인되기 전 자동화 완료를 주장하지 않습니다.

## 저장·출력

`calendar_bindings`, `monthly_schedule_batches`, `calendar_events`, `class_sessions`, `session_instructors`, `work_runs`.

필드: 원본 버전·대상 월·기수·수업일·하루 회차·시작/종료 시각, `meeting_type`, 주최자·팀·채널, Teams 일정 참조·회의 링크·조회 가능한 회의 ID, 직원 Outlook 이벤트 ID, 외부 수정 버전, 생성/변경/취소·부분 동기화 상태.

화면에서 확인할 수 없는 ID를 임의 생성하지 않습니다. 회의와 파일은 같은 실제 수업으로 대조하며 필요한 참조가 없으면 수집 작업을 확인 대기로 둡니다.

## 예외·승인

- 팀·채널 구조·강사별 시각 미확정: 담당자 보완 후 생성.
- 재시도: 과정·회차·월·원본 버전과 외부 결과를 대조해 중복 생성 방지.
- Teams 생성 후 Outlook 반영 실패: 부분 동기화로 표시하고 새 Teams 회의를 다시 만들지 않음.
- 화면 변경·MFA·세션 만료: 중단·담당자 알림. 정책 우회 금지.
- 양쪽 수정 충돌: 기준 필드와 원본 버전을 확인하고 무한 왕복 갱신 금지.
- 이미 진행된 회차: 과거 출결·설문을 새 일정으로 덮어쓰지 않음.

## 운영 품질 기준

지정된 **1개월치 실제 채널 수업**만 생성되고 직원 Outlook은 같은 회의 링크를 가리켜야 합니다. 휴강·강사 교체·부분 실패·재시도에서 대상 회차와 멤버십 범위를 지키는지 배포 전 확인합니다.
