# F09. 운영 문제 조기 감지·참여 지원

[전체 목록](../00_보고서_안내.md)

난이도: 4

## 목적

강의 품질·응대 지연·행정 오류·프로젝트 갈등을 일찍 발견해 해결합니다. 학생별 “신고할 가능성”을 평가하거나 비판·신고 자체를 경고 사유로 삼지 않습니다.

> **[발표·보고 시 설명 유의사항 — 원본 기획안 대비 변경 사유]**
> 원본 기획안(3-4, 3-5)에는 *"수업 참여도가 훨씬 낮은 사람 Top 3를 뽑아 자동 메시지를 보내거나, 카메라가 꺼진 사람·자는 사람에게 에이전트가 자동으로 경고를 보낸다"*는 아이디어가 포함되어 있습니다. 그러나 실제 운영에서 채팅량만으로 참여도를 줄 세우거나 AI가 화면만으로 졸음·자리이탈을 단정해 학생에게 자동 경고를 발송하면 **오판으로 인한 학생 반발·민원 및 개인정보/감시 논란**이 발생할 수 있습니다. 따라서 본 설계 보고서에서는 원본 문구와 달리 **① 학생 태도 하위 순위(Top 3) 산출 금지, ② 졸음·불성실 자동 단정 및 자동 경고 발송 금지, ③ 객관적 관찰 사실만 매니저에게 먼저 보고하고 매니저 확인 후 안내**하도록 안전 장치를 두어 변경했습니다.

## 입력·설정

승인된 교육 채팅, 설문, 문의 처리 상태, LMS 관찰, 프로젝트 약속/제출 상태, 이슈 유형, 응대 기한, 경보 임계값, 담당자, 비공개 범위.

**자료 위치 참고:** 운영 채널 구조의 `상담일지 / 일반상담`·`중도퇴소 상담`·`출결 경고`는 기록 위치 예시입니다. 개인별 경고 이미지·상담 기록이 있다고 해서 자동 제재나 태도 판정의 근거로 사용하지 않습니다. 프로젝트 자료도 수강생 `일반 / 06. 프로젝트`·`07. 산출물`과 운영 채널 `프로젝트`를 구분하고 허용된 최신 자료만 확인합니다. 이름·날짜·경로는 테스트 및 운영을 하면서 바꿀 수도 있으며 실제 상담 열람·결과 보관 권한은 별도 확인합니다.

| 신호 | 수신자 | 기본 조치 |
|---|---|---|
| 반복된 교안 미제공·일정 상충·불만 | 매니저 | 근거 묶기·담당자 배정 |
| 문의 답변 기한 초과·반려 안내 누락 | 매니저 | 미처리 업무 생성 |
| 명시적 도움 요청·프로젝트 갈등 | 매니저/멘토 | 맥락 확인·지원 |
| 정상 조회 후 입퇴실/일반 제출물 기록 미확인 | 해당 학생 | 사전 규칙에 따른 비공개 안내 |
| 병가·공결 증빙의 판독 불확실·요건 보완 후보 | 매니저 | [F14](F14_LMS_서류_반려안내.md) 최종 판단·사유 확인 후 해당 학생에게 결과 안내 |
| 수집 오류·로그인 만료 | 운영 담당자 | 데이터 장애 경보 |

## 처리 구조

```text
수집 이벤트 → 데이터 최신성·권한 확인
→ 객관적 규칙 검사 + AI 맥락 요약
→ 중복 이슈 병합
→ 사실/추정/누락 상태 구분
→ 담당자 경보 또는 학생 안내
→ 접수·조치·해결·오탐 기록
```

실제 연결·권한·대상·규칙을 확인해 운영에 적용합니다. 모델은 테스트·운영 중 품질·수정률·속도·비용을 보고 더 좋은 모델 또는 더 가성비 있는 모델로 변경합니다. 학생 안내는 검증된 원천 데이터와 명시적 규칙이 있는 유형만 자동 전송하고 그 밖의 유형은 담당자 경보로 처리합니다.

증빙의 보완·반려는 일반 미제출 알림으로 우회하지 않습니다. 매니저 확인 전 1차 판독만으로 학생에게 보완·반려를 통보하지 않습니다.

## 리소스·권한

Graph/Teams, PostgreSQL, Foundry, Durable Functions, Service Bus. 경보는 실제 수신자·소속 팀·권한을 확인한 내부 운영 채널 또는 `@elixirr` 운영 채널·담당자 개인 대화로 보냅니다. 제공된 `{기수} 채널` 폴더 예시만으로 전체 채널이 민감 경보를 볼 수 있다고 가정하지 않습니다. 수강생 팀이나 외부 기관의 `출석 관리 팀`에는 내부 경보를 올리지 않으며 학생 미이행 안내는 해당 과정의 비공개 안내 정책을 따릅니다.

## 저장·출력

`cases`, `case_evidence`, `case_actions`, `rule_versions`, `collection_health`.

필드: 과정, 유형, 발생 시각, 수집 기준 시각, 근거 링크, 확인된 사실, AI 요약/불확실성, 담당자, 기한, 상태, 이의제기·오탐 사유.

대시보드는 사람이 아니라 **해결할 사건**을 우선 보여줍니다.

## 예외·승인

- 비꼼·인용·일방 진술은 확정 사실과 분리.
- 메시지량이 적다는 이유로 참여 의지가 없다고 판단하지 않음.
- 수집 중단을 “위험 없음”으로 처리하지 않음.
- 개인별 수면·감정·신고 의도 추론은 사용하지 않음.
- 공식 제재·수료 판단·외부 민원 답변은 매니저 승인.
- 같은 사건의 알림 폭주를 막되 심각도 변화와 미응답 기한은 별도 재알림.

## 운영 품질 기준

운영 중 담당자의 처리 결과(조치·오탐·이의제기)로 유형별 정밀도·재현율·중대 누락을 측정합니다. 근거 없는 경보와 중복 경보를 점검합니다. 학생 안내는 검증된 원천 데이터와 명시적 규칙이 있을 때만 실행되어야 합니다.
