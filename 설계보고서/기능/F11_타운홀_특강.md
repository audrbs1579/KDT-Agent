# F11. 타운홀·특강 운영

[전체 목록](../00_보고서_안내.md)

난이도: 2~3

## 목적

행사 준비, 참가 의사 확인, 매니저 명단, 강사 이력, 종료 후 만족도를 같은 흐름으로 운영합니다.

## 입력·설정

Outlook 일정, 행사 유형, 대상 과정, 장소/Teams 회의, 초청 강사, 정원, 고정 참석 직원, 신청 기한, 준비 항목, 설문.

**폴더 매핑 예시:** KDT 폴더 구조의 운영 채널 `타운홀미팅 / [MMDD 행사명·회차]`는 운영 문서·행사 출석부·초청 명단·사진의 내부 위치이고, 수강생 `일반 / 04. 타운홀 미팅 / [MMDD 행사명·회차]`는 학생 배포 양식·활동 자료 위치입니다. 초청·조편성 Excel과 실제 참석 결과를 혼동하거나 내부 명단·사진을 자동 전체 공개하지 않습니다. Forms 다운로드 결과는 운영 채널 `중간평가 및 설문` 저장 예정 흐름을 따릅니다. 파일명·날짜·회차는 테스트 및 운영을 하면서 바꿀 수도 있으며 실제 ID·권한은 별도 확인합니다.

## 처리 구조

`행사 일정 → 준비 체크리스트 → 사람이 참가 신청·만족도 Forms 준비·게시·링크 등록 → Teams 링크 안내 → Forms 응답 → 매니저가 응답 화면에서 Excel 다운로드·전달 → 에이전트 수집·중복/정원 검사 → 고정 매니저 명단 결합 확정 → 안내 → 실제 참석 기록 → 같은 방식으로 만족도 집계`

별도 외부 신청 페이지를 만들지 않고 **Teams 안내·Forms 응답·Excel 다운로드·에이전트 정리**를 기본 경로로 사용합니다. Teams 자체 투표의 답변을 직접 수집하는 별도 기능으로 설명하지 않습니다.

다운로드한 파일은 해당 시점의 사본이며 새 응답은 다시 다운로드합니다. 양식 버전·응답 ID로 중복을 제거하고 미게시 양식은 안내하지 않습니다. 회의 유형·주최자를 확인하고 채널 수업 생성과 일반 행사 회의를 혼용하지 않습니다.

## 리소스·권한

Outlook/Teams/Graph, PostgreSQL, Durable Functions, Service Bus, SharePoint. 직원 행사와 학생 특강의 회의 주최 테넌트를 구분합니다.

## 저장·출력

`events`, `event_registrations`, `instructors`, `tasks`, `attendance_observations`.

출력: 참석 예정자+고정 직원 Excel, 준비 상태, 안내 내역, 실제 참석 결과, 강사/행사 만족도. “참가 신청”과 “실제 참석”은 별도 상태입니다. 고정 매니저 결합 명단 및 특강 만족도 양식은 09 데이터 컬럼·엑셀 양식을 따릅니다.

## 예외·승인

- 일정 취소 시 대기 안내·설문 취소.
- 중복 신청·정원 초과·대기자 이동은 규칙에 따라 안내.
- 고정 직원과 일반 신청자를 중복 계산하지 않음.
- 외부 강사 섭외·비용 지출·장소 계약은 승인.
- 행사에 여러 과정이 섞이면 각 과정의 자료 공개 범위 유지.

## 운영 품질 기준

명단 수·고정 직원 수·중복 제거가 정확해야 합니다. 취소·정원 변경이 안내에 반영되고 참석 예상이 실제 참석으로 잘못 집계되지 않아야 합니다.
