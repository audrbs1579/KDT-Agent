# F12. 커리어 멘토링·사전 자료

[전체 목록](../00_보고서_안내.md)

난이도: 2~3

문서 형식·파서·모델·리전은 조사 기준의 참고 후보이며 실제 테스트·운영에서 추출 결과·품질·가성비를 보고 변경합니다. 형식 지원 정보와 실제 검증 완료 기록은 구분합니다.

## 목적

멘토링 전에 자소서·질문·필요 자료를 받고, 멘토의 준비 여부와 종료 후 만족도를 관리합니다.

## 입력·설정

멘토·학생·회차, 일정, 신청·안내 채널(`{과정명} {기수} 수강생 팀 > 04. 멘토링 요청 게시판`), **수강생이 제출하는 비정형 사전 자료(자소서·포트폴리오·이력서·사전 질문지 — 워드 `.docx`뿐 아니라 아래아한글 `.hwp`/`.hwpx`, `.pdf`, 노션/웹페이지 `.html`/`.md`, `.pptx`, 이미지 등은 접수·추출 검토 후보)**, 마감, 문항 약 3개 또는 설정 수, 열람 만료, 재안내 정책. 원본 접수 가능과 내용 추출 성공은 구분하며 미지원·추출 실패는 사람 확인으로 남깁니다.

**자료 위치 예시:** 폴더 구조의 수강생 `일반 / 04. 타운홀 미팅 / [MMDD 커리어멘토링 회차]`는 이력서 양식 등 배포 자료이고, 운영 채널 `커리어멘토링 / [행사 폴더]`는 운영 자료입니다. 강사팀 `멘토링 일지 / N차 프로젝트 멘토링 일지.xlsx`는 프로젝트 멘토링 자료이므로 커리어 멘토링과 같은 회차·원본이라고 간주하지 않습니다. 개인 자소서·이력서·상담 원본은 담당자·배정 멘토 제한 위치를 별도 지정하고, Forms 결과는 운영 채널 `중간평가 및 설문` 저장 예정 흐름을 따릅니다. 이름·날짜·파일 구성은 테스트 및 운영을 하면서 바꿀 수도 있으며 실제 ID·권한은 별도 확인합니다.

## 처리 구조

```text
멘토링 일정 → 수강생 팀(04. 멘토링 요청 게시판)에서 신청·제출 안내
→ 개인 사전 자료(.hwp, .hwpx, .pdf, .html, .docx 등)는 권한 확인된 제한 접수 위치로, 질문은 공개 범위에 맞는 Forms/대화로 접수
→ 확장자·형식별 자동 파싱(.pdf·.html·.docx·이미지는 R16 Content Understanding, .hwp·.hwpx는 서버 내 한글 파서/PDF 변환기 처리)
→ PostgreSQL 비정형 필드(`extracted_fields JSONB`) 및 검색 조각(`chunks`) 저장 + 학생·회차 매칭
→ 멘토에게 Teams/M365로 원본 파일 + AI 핵심 요약 묶음 전달
→ 진행 확인 → 사람이 게시·링크 등록한 Forms 만족도 안내 → Forms 응답 → 매니저가 Excel 다운로드·전달 → 에이전트 집계
```

## 리소스·권한

Teams(`04. 멘토링 요청 게시판`), Microsoft Forms/SharePoint(엑셀·사전 자료 폴더), **R16 Content Understanding + R02 서버 내 한글(`.hwp`/`.hwpx`)·HTML 전처리 파서**, PostgreSQL(`JSONB` + `vector`), Outlook, Durable Functions. 모든 수집·전달은 **Teams·M365(SharePoint/Forms/엑셀 업로드) 환경**에서 운영합니다.

## 저장·출력

`mentoring_sessions`, `document_requests`, `documents`, `task_responses`, `survey_instances`.

출력: 제출 현황, 멘토별 준비 자료 묶음, 미제출 안내, 만족도([09 데이터 컬럼·엑셀 양식](../09_데이터_컬럼_엑셀양식.md) 참조). 멘토는 배정 학생·기간에 한해 필요한 자료를 봅니다.

## 예외·승인

- Forms 생성·게시·응답 화면의 Excel 다운로드는 사람 담당. 다운로드 파일은 자동 동기화 사본이 아니므로 새 응답은 다시 내려받고 응답 ID로 중복 제거.
- 게시판은 요청·안내용이며 자소서·이력서 원본은 배정 멘토·담당자만 보는 제한 위치로 접수. 여러 학생에게 공개되는 폴더에 모으지 않음.

- 파일 오류·잘못된 형식·대상 불일치: 명시적 반려/재제출 안내.
- 다른 학생의 사전 자료 폴더/파일에 접근하지 못하도록 SharePoint/Teams 권한 구분.
- 일정 변경은 자료 마감·접근 기간도 함께 갱신.
- 자료가 없으면 제출 완료로 추정하지 않음.
- 멘토 교체 시 기존 접근을 회수.
- 민감 상담 내용은 학생 전체 보고서에 포함하지 않음.

## 운영 품질 기준

다른 학생 자료에 접근할 수 없어야 하며, 재제출은 이전 버전과 구분되고 일정 취소 후 요청이 중단되어야 합니다.
