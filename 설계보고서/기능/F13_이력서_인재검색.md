# F13. 이력서 취합·인재 검색

[전체 목록](../00_보고서_안내.md)

난이도: 3~4

파일 형식·파서·모델·리전은 조사한 참고 후보이며 실제 테스트·운영에서 추출 결과·품질·비용에 따라 변경합니다. 조사상 지원 가능과 실제 검증 완료는 구분합니다.

## 목적

완성된 이력서·경력·기술·희망 직무를 모아, 승인된 목적 안에서 기업 추천이나 보조강사 후보를 찾습니다.

## 입력·설정

**수강생별 비정형 이력서·포트폴리오 버전(아래아한글 `.hwp`/`.hwpx`, `.pdf`, 노션/웹 `.html`/`.md`, `.docx`, `.pptx` 등 자유 양식)**, 필수 연락처·주소 등 실제 필요한 항목, 활용 동의 목적, 공개 범위, 보관 기간, 검색 조건.

**자료 위치 참고:** KDT 폴더 구조의 수강생 `일반 / 04. 타운홀 미팅` 안 이력서 양식은 배포용 샘플이지 개인 이력서의 수집 위치가 아닙니다. 운영 채널 `커리어멘토링`과 연계하더라도 개인 원본·인재풀 결과는 취업 담당자·지정 멘토의 제한 위치를 별도로 등록합니다. 파일명·날짜·구성은 테스트 및 운영을 하면서 바꿀 수도 있으며, 제공된 예시만으로 개인 자료가 이미 접수됐거나 열람 허용됐다고 판단하지 않습니다.

## 처리 구조

```text
자료 요청·접수 → 원본/버전 보관(SharePoint/Blob)
→ 형식별 추출(.pdf·.html·.docx·.pptx는 R16 Content Understanding, .hwp·.hwpx는 서버 한글 파서/PDF 변환 후 추출)
→ 문서마다 양식이 다른 비정형 항목을 PostgreSQL `extracted_fields (JSONB)` + `chunks (vector)`에 구조화 및 불명확 값 확인
→ 권한/활용 목적 필터 후 하이브리드 검색(정형 조건 + JSONB + 벡터 의미 검색)
→ 근거 있는 후보 목록 및 표준 인재풀 엑셀(09 데이터 컬럼·엑셀 양식) 자동 매핑
→ 담당자 검토·학생 의사 확인·외부 제공 승인
```

## 리소스·권한

SharePoint/Blob, PostgreSQL(`JSONB` + `vector` 검색), Foundry + **R16 Content Understanding + 서버 내 한글(`.hwp`/`.hwpx`) 전처리 파서**, Teams/SharePoint 폴더(또는 엑셀 업로드). 별도 외부 업로드 웹을 만들지 않고 M365/Teams 환경에서 수집하며, 취업 담당자와 지정 멘토로 접근을 제한합니다.

## 저장·출력

`resume_versions`, `candidate_profiles`, `skills`, `consent_records`, `referral_requests`.

추출 필드에는 원본 위치·추출 버전·확인 상태를 둡니다. “AI가 추출한 경력”과 본인이 확인한 경력을 구분합니다.

출력: 조건에 맞는 후보, 근거 문장·이력서 링크, 부족/미확인 정보, 승인된 Excel(09 데이터 컬럼·엑셀 양식의 주소 필수 포함 인재풀 시트 참조).

## 예외·승인

- AI는 최종 채용·추천 합격을 결정하지 않음.
- 출결·불만·민원 기록을 무관한 채용 평가에 섞지 않음.
- 동의 목적 밖의 기업 제공·홍보·섭외는 별도 확인.
- 기업 추천 동의와 보조강사 섭외 동의를 목적별로 별도 기록하며 어느 하나의 동의를 다른 목적에 자동 적용하지 않음. 예시 컬럼·동의 항목도 실제 양식에 맞게 변경 가능.
- 주소 등 개인정보를 검색 결과에 항상 노출하지 않고 필요한 역할만 열람.
- 오래된 자료·동의 철회·삭제 요청을 인덱스와 후보 검색에도 반영.
- 외부 전달은 승인된 정확한 수신자·문서 버전에 묶음.

## 운영 품질 기준

검색 결과가 실제 기술/경력 근거와 연결되고, 동의 철회·권한 밖 후보는 제외되어야 합니다. 문서 버전이 바뀌면 낡은 정보가 현재 사실로 남지 않아야 합니다.
