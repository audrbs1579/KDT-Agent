# F14. LMS 병가·공결 증빙 서류 판독·조건 검사 및 매니저 확인 후 결과 안내

[전체 목록](../00_보고서_안내.md)

난이도: 4

파일 형식·OCR/모델·API/분석기·리전과 서류 조합은 현재 조사 기준의 참고안입니다. 기관별 실제 요건과 테스트·운영 결과에 따라 바꾸며, 조사상 지원과 실제 검증 완료를 구분합니다. 질병코드 등의 아래 조건 예시는 모든 기관에 적용되는 확정 규정이 아닙니다.

## 목적

LMS 사이트 또는 권한을 확인한 제한 접수 위치에 병가·공결·훈련 관련 증빙 신청이 새로 들어오면, **수강생이 올린 저화질 휴대폰 촬영본·화면 캡처·프린터 스캔본 등을 정밀 화면 판독(OCR/멀티모달 분석)**하여 **필수 서류·필수 항목 조건(예: 질병코드 유무 및 대체 조합 조건 등)이 제대로 갖춰졌는지 1차 자동 점검**합니다. 수강생 팀 `01. 출결 게시판`·`02. LMS 정정 요청 게시판`은 요청·안내용이며 의료 원문을 공개 첨부하는 위치로 사용하지 않습니다.

**승인·반려의 최종 판단은 반드시 매니저가 내리며**, 에이전트는 ① 새로 들어온 서류가 조건에 맞게 잘 왔는지 판독 결과를 매니저에게 브리핑하고, ② **매니저가 최종 승인·반려(및 반려 사유)를 결정하면 그 결과와 사유를 학생에게 정확히 공지·안내**합니다.

## 입력·설정

- **기본 연결:** LMS 계정·허용 작업·로그인 정책, 과정/학생 매핑, 출결/LMS 정정 요청 게시판, 담당자 제한 보고·승인 위치, 조회 주기. 실제 팀·SharePoint 폴더·열람 역할은 구조 확인 후 등록합니다.
- **자료 위치 참고:** 운영 채널 예시의 `운영관리 매뉴얼` 내 출결·LMS 처리 안내는 적용 버전을 확인할 참고 자료입니다. `상담일지`·`출결 경고`가 있다고 의료 증빙·판독 결과의 권한까지 확인된 것은 아닙니다. 제한 증빙·승인 결과의 위치는 별도 지정하고, 수강생 `일반`·강사팀·외부 출석 관리 팀에 자동 공유하지 않습니다. 이름·날짜·파일 구성은 테스트 및 운영을 하면서 바꿀 수도 있습니다.
- **수강생 제출 비정형·저화질 증빙 파일:**
  - 휴대폰 카메라 촬영본(기울어짐·그림자·빛 반사·저해상도), 모니터/모바일 화면 캡처본(`.jpg`, `.png`), 복합기/프린터 흑백·저화질 스캔본(`.pdf`, `.tiff`), 전자발급 문서(`.pdf`, `.html`, `.hwp`, `.hwpx`, `.docx`).
- **유형별 서류 충족 조건 규칙 (화면에서 커스텀 조건 추가·수정 가능):**
  - **병가 기본 조건 예시 (OR 조합 규칙 지원):**
    -     **조건 A (단독 충족):** `진료확인서` 1장 안에 **‘질병분류코드(질병코드)’가 명확히 기재**되어 있는 경우 → **서류 요건 충족 후보**
    - **조건 B (복수 서류 결합 충족):** `진료확인서`에 질병코드가 없더라도, **`진료확인서` + ‘질병코드가 기재된 다른 증빙 서류(처방전 등)’를 함께 제출**한 경우(성명·진료일자·병원명 일치 확인) → **서류 요건 충족 후보**
    -     **보완/확인 필요 후보:** 진료확인서에 질병코드가 없고 질병코드를 확인할 다른 증빙도 없거나, 제출된 처방전에도 질병코드가 없는 경우. 성명·진료일·발급기관 등 추가 필수값은 설정된 규칙으로 검사하며 판독 불가와 실제 누락을 구분
  - **커스텀 조건 추가 (`+ 서류 검증 규칙 추가`):** 병가 외에 예비군/민방위, 면접/시험 공결, 경조사, 취업활동 등 신청 유형별로 **`[필수 서류 종류 + 필수 포함 텍스트/필드(성명·일자·코드·직인 등) + 대체 가능 서류 조합(AND/OR)]`** 조건을 설정 화면에서 자유롭게 추가·변경할 수 있습니다([F01](F01_과정_기능_규칙.md) 과정·기능·규칙 연동).

## 처리 구조

### 1. 이미 확정된 LMS 결과·반려 사유 조회 안내

원문의 “왜 반려되었는지 설명”은 신규 OCR 심사와 별도 흐름입니다.

`학생 문의/결과 변경 감지 → 허용된 LMS에서 신청 번호·학생·과정·서류 버전 확인 → 확정 상태·반려/보완 사유·처리 시각 조회 → 현재 결과와 대조 → 필요한 제출 안내만 해당 학생에게 개인 전달 → 원천·기준 시각·안내 이력 기록`

확정 사유가 없거나 상태·문서 버전이 맞지 않으면 담당자 확인으로 남기고 AI가 이유를 만들어내지 않습니다. 이미 확정된 동일 결과를 단순 안내할 때 새 판독·새 승인 결정을 생성하지 않으며, 출결 정정·판정 변경은 매니저가 수행합니다.

### 2. 신규 증빙 1차 판독·매니저 판단 후 안내

```text
LMS·제한 접수 위치에서 병가/공결/훈련 신청 신규 접수 감지 (게시판에서는 요청·안내만)
→ 첨부된 증빙 서류(캡처·휴대폰 촬영·프린터 스캔·PDF·HWP 등) 수집
→ 이미지 전처리(기울기 보정·대비 개선·해상도 보완) + R16 Content Understanding / 고성능 비전 모델 정밀 판독
→ 서류 종류 분류(진료확인서 / 처방전 / 진단서 등) 및 핵심 필드 추출
  (학생 성명, 진료/발급 일자, 병원/발급기관명, 질병분류코드 유무·코드값, 직인 유무, 판독 신뢰도)
→ 설정된 서류 조건 규칙(예: [진료확인서+질병코드] OR [진료확인서 + 질병코드 있는 처방전] 및 기타 커스텀 조건) 자동 대조
→ 담당자만 열람 가능한 내부 위치·대시보드에 1차 판독 요약 보고
  - 첨부 원본 미리보기 + 추출된 항목(질병코드 표시 위치 등) + 조건 충족 여부 초안 + 화질 불량/판독 불확실 구간 표시
→ ★ 매니저 최종 판단 (승인 / 반려 및 반려·보완 사유 확정)
→ 해당 수강생에게 최종 판단·반려/보완 안내 개인 전달 (게시판에는 민감 내용 없는 일반 안내만)
→ 처리 결과 및 이력 DB 기록
```

## 리소스·권한

Foundry Browser Automation/Playwright(또는 PAD), **R16 Content Understanding + Foundry 멀티모달 비전 모델(저화질 스캔·촬영·캡처 정밀 OCR 및 필드 추출)**, Key Vault, PostgreSQL(`JSONB` 규칙·추출 결과 저장), Teams/메일, Durable Functions.
- **LMS 로그인:** 현재 사용 사이트는 사용자 설명상 ID/비밀번호 방식입니다. 실제 로그인·계정 권한·사이트 정책·무인 실행을 확인한 뒤 연결하며 모든 사이트에 MFA가 없다고 일반화하지 않습니다. 자격 증명은 Key Vault에서 관리하고 정책 변경·인증 요구 시 사람 확인 대기로 둡니다.

## 저장·출력

`document_requests`, `document_verification_rules`, `lms_status_observations`, `support_requests`, `approvals`, `delivery_attempts`.

필드: 신청 번호·학생/과정·유형, 첨부 문서 버전/해시·화질·판독 신뢰도, 규칙 버전·추출 필드(JSONB)·근거 위치, 조합 충족/판독 불가/보완 후보, 매니저 판단·확정 사유·승인 대상 해시, 개인 안내 상태. 원본은 담당자 제한 내부 위치에 보관하며 재제출·규칙 변경 시 기존 승인을 새 자료에 자동 적용하지 않습니다. 외부 출석 관리 팀에 의료 원문을 자동 공유하지 않습니다.

기존 결과 조회는 LMS 원천 상태·확정 시각을, 신규 판단은 매니저 판단과 LMS 반영 상태를 구분합니다. LMS 반영 전 판단을 “LMS 반영 완료”라고 안내하지 않습니다. 컬럼·샘플은 09 예시를 참고하며 실제 요건에 따라 변경합니다.

## 예외·승인

- **승인·반려 최종 결정은 100% 매니저 권한:** 에이전트가 혼자서 LMS 승인/반려를 확정하거나 매니저 확인 없이 학생에게 반려 통보를 먼저 보내지 않습니다.
- **저화질·흐림·잘림으로 질병코드나 날짜가 불확실할 때:** AI가 임의로 추측해 읽지 않고, 매니저 보고 카드에 **`[판독 불확실 — 육안 확인 또는 재촬영 요청 필요]`**로 표시합니다.
- **조건 커스텀 유연성:** 기수나 기관 기준이 바뀌어 새로운 증빙 서류 조합이나 필수 기재 항목이 추가되면 코드 배포 없이 서류 검증 규칙(`document_verification_rules`)에서 조건을 추가·수정합니다.
- 로그인 만료·학생 매칭 실패·화면 변경 시 조회 실패로 표시하고 운영진에게 알립니다.
- 재제출·결과 안내에 다른 학생 서류나 민감 의료 정보를 노출하지 않습니다.

## 운영 품질 기준

캡처·휴대폰 촬영·스캔본에서 서류 종류와 필수 조건(질병코드 유무 및 `진료확인서 + 질병코드가 있는 다른 증빙(처방전 등)` 조합)을 판독한 결과가 실제 원본과 일치해야 합니다. 불선명한 이미지를 억지로 정상 판독 처리하지 않아야 하며, 반드시 매니저의 최종 판단을 거친 내용만 학생에게 안내되어야 합니다.
