# F15. LMS 입퇴실 확인·미기록 안내

[전체 목록](../00_보고서_안내.md)

난이도: 4

## 목적

실제 수업에서는 **① 강사님 또는 매니저의 오전·오후 출석 호명(출석부)**과 함께 **② 수강생이 직접 LMS에 오전·오후 입퇴실을 클릭**합니다. 에이전트는 LMS의 오전·오후 입퇴실 기록 누락 여부를 조회해 학생에게 안내하고, 호명 출석부와의 대조를 돕습니다. (LMS와 별도 사이트에서 진행되는 중간 출결 및 3종 출결 파일 종합은 [F16](F16_중간출결.md) 중간 출결·3종 출결 종합에서 다룹니다.)

## 입력·설정

수업 일정, LMS 과정, 학생 매핑, **오전 입실 / 오후 퇴실 확인 시각**(오전·오후 출석 호명 시간 연계), 유예시간, 병가·공결·휴강 예외, 학생 공지/문의 채널(`{과정명} {기수} 수강생 팀 > 01. 출결 게시판`·`02. LMS 정정 요청 게시판`), 실제 소속 팀·권한을 확인한 내부 출석부 업무 보고 채널, 안내 횟수·기한.

**출석부 위치 예시:** 폴더 구조의 강사팀 `출석부 / 월 / 주차 / 일자 / MMDD.xlsx`에서 호명 원본을 읽고, 내부 보관은 운영 채널 `출석부 / 월 / 주차 / 일자`로 구분합니다. 학생 게시판은 안내·문의용이고 수강생 팀의 파일 공유는 `일반` 안에서만 합니다. LMS 조회 원본·대조 이력은 [F16](F16_중간출결.md) 병합 입력 3종과 별도로 추적합니다. 이름·날짜·세부 구성은 테스트 및 운영을 하면서 바꿀 수도 있으며 실제 운영 보고 채널·소속 팀·파일 ID·권한은 별도 확인합니다.

## 처리 구조

```text
예약 시각(오전 입실 직후 / 오후 퇴실 직후) → 오늘 수업·예외 확인
→ 확인된 LMS 로그인 절차(Key Vault 자격 증명)·과정·날짜 선택
→ 오전 입실 / 오후 퇴실 현황 화면·파일(Excel/CSV) 조회
→ 조회 성공·형식·날짜·행 수 검증
→ 학생별 기록(및 강사/매니저 오전·오후 호명 출석부)과 예외 대조
→ 미클릭·미확인 대상 학생에게 Teams(`01. 출결 게시판` 또는 개인 알림) 안내
→ 결과·기준 시각·원본 파일을 별도 대조 이력으로 저장 (F16 병합 사이트의 3종 입력에는 추가하지 않음)
```

## 리소스·권한

Durable Functions/Task Scheduler, Service Bus, Browser Automation(Playwright)/검증된 PC 실행기, Key Vault, PostgreSQL, Teams.
- **LMS 로그인:** 현재 사이트는 사용자 설명상 ID/비밀번호 방식이며 실제 계정·정책·무인 실행을 확인해야 합니다. MFA·세션 만료·정책 변경 시 사람 확인 대기로 두며 우회하지 않습니다. 같은 LMS 계정 작업은 직렬화합니다.

## 저장·출력

`attendance_observations`, `attendance_exceptions`, `delivery_attempts`, `work_runs`.

관찰 결과와 공식 출결 판정을 분리합니다. 출력은 “09:10 기준 입실 기록 미확인”처럼 조회 시점을 포함합니다.

## 예외·승인

- 조회 실패·빈 오류 화면·엑셀 대신 내려온 HTML을 미입실 명단으로 취급하지 않음.
- 시간대·수업 날짜·과정 선택이 틀리면 전체 발송 차단.
- 늦게 반영된 LMS 기록은 다음 조회에서 정정하고 기존 안내 이력은 유지.
- 이름만 같거나 계정이 미매칭이면 담당자 확인.
- 중복 이벤트·재시도에도 같은 기준의 안내는 한 번만 발송.
- 공식 출결 정정·인정·제재는 승인과 근거 필요.

## 운영 품질 기준

정상·로그인 만료·틀린 날짜·공결·중복 이름·부분 다운로드 상황을 운영 중 자동 판별해야 합니다. 검증 불가 데이터에서 학생 경고는 0건이어야 합니다. 정상 결과는 LMS와 일치해야 합니다.
