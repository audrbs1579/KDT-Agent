# F15. 출결 게시판 사전 신고 연계·LMS 입퇴실 확인·맞춤 안내

[전체 목록](../00_보고서_안내.md)

난이도: 4 · 사전 신고 연계 명세 보완: 2026-10-28

## 목적

수강생이 Teams **`01. 출결 게시판`에 미리 남긴 지각·조퇴·외출·결석 예정과 변경/취소 내용**을 읽고, 해당 기수·학생·수업일의 LMS 실제 입퇴실 기록 및 호명 출석부와 자동 대조합니다. 게시판은 안내를 보내는 곳이면서 **학생의 사전 출결 일정 입력 원천**입니다. 사전 신고를 반영한 학생별 확인 시각·안내 규칙으로 잘못된 미클릭 독촉을 방지합니다.

한 기수는 수업일당 하루 강의 1개이며 여러 기수가 동시에 운영됩니다. 출결 신고·LMS 기록·안내는 `course_id + student_id + class_date`와 해당 하루 강의의 `session_id`로 연결합니다. 오전·오후 호명과 LMS 입퇴실 확인은 같은 하루 강의의 내부 확인 구간입니다.

에이전트는 반복적인 신고 수집·대조·예약 갱신·필요 안내를 자동 실행합니다. **신고 접수, 사전 일정에 따른 안내 조정, 공결/지각 등 공식 출결 인정, LMS 정정 완료는 서로 다른 상태**입니다. 게시글만으로 공결 승인이나 정상 출석을 확정하지 않습니다. 공식 출결 정정·인정과 중요한 판단은 담당자에게 연결합니다. F16의 중간출결·3종 파일 종합은 별도 흐름입니다.

## 입력·설정

- 기수별 수업일·시작/종료 시각·휴일·시간대, 학생 계정/등록 ID, LMS 과정·학생 매핑.
- `01. 출결 게시판`: 사전 지각·조퇴·외출·결석 예정, 학생의 변경/취소, 담당자 확인 답글. 조회 허용 범위의 원문·답글·작성자·작성/수정 시각·메시지 ID/링크를 수집하도록 구현합니다.
- `02. LMS 정정 요청 게시판`: 누락 클릭·시각 오류 등 사후 정정 신청과 담당자 처리 상태. 사전 신고와 구분하고 둘이 관련되면 같은 출결 건으로 연결합니다.
- 오전 입실·오후 퇴실 확인 시각, 지연 반영 대기와 유예시간, 사전 신고별 학생 확인 예정 시각·유효 구간, 안내 문구·횟수·기한, 신고/승인 상태별 정책.
- 사전 신고 템플릿: 대상 수업일, 신고 유형, 입실/퇴실 또는 외출 시작/복귀 예정 시각. 작성자 계정으로 학생을 연결하고 이름만으로 자동 매칭하지 않습니다.
- 호명 출석부, 병가·공결 승인 참조, 제한된 내부 보고 채널·민감 증빙 위치.

**신고 수집·해석:** 새 글과 수정/취소·허용된 답글을 주기적으로 확인하고, 수업 전·관련 예정 시각·발송 직전에 최신 상태를 재확인합니다. 자연어는 AI가 날짜·유형·시간을 추출하되 서버가 기수·학생·수업일·시각 범위를 검증합니다. `내일` 등 상대 날짜는 게시 시각과 과정 시간대로 해석하며 모호하거나 학생 매칭/시간이 빠진 신고는 확인 필요로 남깁니다. 신고 접수 후 학생에게 해석한 날짜·예정 시각을 비공개로 확인 안내해 수정할 수 있게 합니다. 게시판 본문이 실행 규칙이나 승인 권한을 변경하지 못하게 합니다.

**자료 위치:** 강사팀 `출석부 / 월 / 주차 / 일자 / MMDD.xlsx`의 호명 원본과 운영 채널의 내부 보관 위치를 구분합니다. 게시판에는 예정·요청·안내만 두고 의료 원문은 제한 접수 위치로 연결합니다. LMS·게시판 대조 이력은 F16의 3종 입력에 네 번째 파일로 추가하지 않습니다. 실제 팀·채널·파일 ID·권한·수집 절차는 연결 시 확인합니다.

## 처리 구조

### 사용자 제공 게시판 예시와 해석 기준

2026-10-28 제공한 사진에서 확인한 작성 형식을 반영합니다. 아래 학생 표시는 익명 예시이며 실제 이름·학생번호를 옮기지 않습니다.

| 입력 원천 | 사진에서 확인한 작성 방식 | 구조화·처리 기준 |
|---|---|---|
| 출결 게시판: 외출 | 제목에 대상 날짜와 외출, 본문에 성함/번호·날짜/시간·사유. 예: 10월 28일 11시~2시 | 신고 유형은 외출로 보존. 11:00~14:00은 수업 시간대를 고려한 해석 후보이며 오전/오후·시각 범위를 검증. 외출 시작·복귀 예정에 대조 예약 |
| 출결 게시판: 결석 | 제목에 미래 날짜와 결석, 본문에 학생·대상일·예비군 등 사유 | 게시 날짜와 결석 대상 날짜 분리. 해당 학생·대상 수업일에만 예정 반영. 신고만으로 공결 승인하지 않음 |

| 출결 게시판: 기간·유형 불명 | 제목은 10월 27~30일 조퇴 또는 결석 예정, 본문은 10월 27일 14:20~ | 날짜 범위·조퇴/결석 선택·종료 시각이 모두 확정된 것으로 처리하지 않음. 27일 14:20 이후 예정과 나머지 날짜의 불명확 구간을 구분해 보완 확인 |

| LMS 정정 요청: 입실 클릭 지연 | 호명 때 있었으나 LMS 입실을 늦게 눌렀다는 진술 | 호명 원본·LMS 실제 클릭 시각·해당 일자 근거를 묶어 정정 검토. 늦은 클릭만으로 실제 지각 확정하지 않음 |
| LMS 정정 요청: 입퇴실 동시 클릭 | 오전 입실을 잊고 오후 17:51에 입실·퇴실을 모두 눌렀다는 진술 | 동일/비정상 시각 기록 후보로 표시하고 LMS 원천·호명·참석 근거 대조. 하루 결석이나 정상 출석으로 자동 확정하지 않음 |

작성자 계정·본문 학생번호·기수 명단을 함께 대조하고 불일치하면 확인 대기로 둡니다. 제목·본문의 대상일이 다르거나 범위가 불명확하면 어느 쪽도 임의로 확정하지 않습니다. 편집된 글은 이전 버전과 예약 영향을 보존하고 최신 내용을 재검사합니다. 스레드의 답글 위치가 보인다는 사실만으로 담당자의 승인·정정 완료가 확인된 것은 아닙니다.

출결 게시판은 예정 신고, LMS 정정 요청 게시판은 사후 기록 오류 요청으로 분류합니다. 사후 정정 요청을 다음 날의 사전 출결 예정으로 잘못 반영하지 않습니다. 정정은 요청 접수·근거 대조·담당자 판단·LMS 실제 반영 확인·학생 안내 상태로 관리하며, 사진에 없는 관리자의 처리 절차·자동 수정 권한은 확인 완료로 기록하지 않습니다.

```text
수업 전: 기수별 하루 강의·학생 명단 확인
→ 출결 게시판의 사전 신고·변경/취소·담당자 확인과 정정 요청 수집
→ 기수·학생·대상 수업일·유형·예정 구간·승인 상태 검증
→ 학생별 LMS 확인 시각·재조회·안내 예약 생성/갱신
→ 해당 확인 시각에 LMS 로그인·과정·날짜 선택
→ 실제 입퇴실 화면/파일 조회·성공/형식/날짜/기준 시각 검증
→ LMS 기록 + 호명 출석부 + 현재 유효 신고 + 승인 기록 대조
→ 일치 / 일반 미클릭 / 사전 신고 후 기록 확인 대기 / 예정 초과
   / 신고 모호·충돌 / 자료 수집 장애로 구분
→ 발송 직전에 최신 신고·LMS·중복 안내 여부 재확인
→ 허용된 학생별 비공개 안내 또는 매니저 예외 보고
→ 원천·대조·예약 변경·안내 결과 저장
→ 수업 후 미해결 건·정정 요청·공식 처리 상태 확인
```

신고가 새로 들어오거나 시간이 바뀌면 기존 독촉 예약을 취소·재계산합니다. 발송 직전 변경도 반영하며 이미 나간 안내는 삭제된 사실로 만들지 않고 정정 이력을 남깁니다.

## 지각·조퇴·외출별 확인 규칙

| 상황 | 자동 확인·예약 | 안내·처리 |
|---|---|---|
| 사전 지각 예정 | 기본 시작 시각과 별도로 신고한 입실 예정 시각 + 설정 유예 후 실제 입실 재조회 | 기본 시각의 일반 미입실 독촉을 보류. 예정 후에도 기록 미확인이면 신고를 반영한 중립적 기록 확인 안내 |
| 사전 조퇴 예정 | 신고한 퇴실 예정 시각 전후로 LMS 실제 퇴실 확인 | 정상 종료까지 남아 있으라는 안내를 보내지 않음. 예정 시각 뒤 퇴실 기록이 없을 때 해당 퇴실 클릭/기록만 확인 |
| 사전 외출·복귀 예정 | 신고 구간에 중간 확인/재안내 예외 적용, 복귀 예정 후 상태 재확인 | 신고 구간의 부재를 단순 미응답 독촉 사유로 삼지 않음. LMS가 외출/복귀를 지원할 때만 해당 기록을 조회하고, 아니면 호명·담당자 확인으로 연결 |
| 사전 결석·공결 신청 | 당일 신고 범위와 담당자 승인/미승인·F14 증빙 상태 대조 | 사전 신고한 학생을 단순 미클릭자로 안내하지 않음. 출결 인정은 승인 상태를 따르고 미승인은 확인 필요로 보고 |
| 신고 없이 실제 입실 지연 | 강의 시작·유예와 LMS 실제 입실 시각의 차이를 관찰 | `입실 시각 지연 관찰`로 기록하고 공식 지각은 적용 규칙·담당자 판단을 따름. 실제 시각을 신고 시간으로 덮어쓰지 않음 |
| 신고 없이 입퇴실 기록 없음 | 게시판/정정 요청·LMS 조회가 정상이고 유효 예외가 없는지 확인 | 사전 승인된 규칙에 따라 개인에게 미클릭/기록 확인 안내. 출석부와 상충하면 확인 필요 보고 |
| 신고 예정과 실제 기록 불일치 | 예정/실제 시각과 차이, 최신 변경·취소·정정 상태 대조 | 예정 시각 초과·복귀 미확인 등 구체적 상태로 안내/보고하고 결석·제재로 자동 확정하지 않음 |

**신고와 승인:** 승인 전이라도 유효하게 접수된 사전 신고는 오안내 방지를 위한 확인 시각·문구 조정에 반영합니다. 이는 출석 인정이나 공결 승인과 다릅니다. 승인 대기를 이유로 무기한 제외하지 않고 예정 시각·유효 구간·응답 기한 이후 재확인합니다. 반려·취소는 현재 규칙으로 재계산하고 과거 이력은 보존합니다.

**시각 예시:** 수업 시작 09:00, 학생의 사전 입실 예정 10:00이면 09:10에 일반 미클릭 독촉을 보내지 않고 10:00 + 설정 유예 후 LMS를 재조회합니다. 사전 조퇴 예정이 16:00이면 그 시각 이후 퇴실 기록을 확인합니다. 시각·유예값은 설명용이며 기관별 공식 지각/조퇴 인정 기준을 의미하지 않습니다.

## 리소스·권한

Durable Functions/Task Scheduler, Service Bus, 검증된 Playwright/PC 실행기, Key Vault, PostgreSQL, Teams 메시지 수집·비공개 안내 연결. 허용된 출결 게시판과 정정 요청 게시판을 학생 계정·기수로 연결합니다. 실제 채널 유형·메시지/답글 수집·수정 이력 접근·권한 범위는 배포 전 확인하며 읽기 불가를 신고 없음으로 처리하지 않습니다.

LMS 로그인은 현재 사용자 설명상 ID/비밀번호 방식입니다. 실제 권한·무인 실행·MFA·세션 만료·정책을 확인하고 같은 계정 작업은 직렬화합니다. 게시판 글이나 LMS 화면을 읽는 성공과 실제 출결 정정 쓰기 권한은 별개입니다.

## 저장·출력

`attendance_notices`, `attendance_notice_versions`, `attendance_observations`, `attendance_exceptions`, `attendance_checks`, `support_requests`, `delivery_attempts`, `work_runs`.

필수 필드: 기수·학생·수업일·하루 회차, 신고 유형·입실/퇴실/외출/복귀 예정 시각, 원문 메시지/스레드/답글 ID·링크·버전·작성/수정 시각·수집 시각, 추출 확실성·매칭 상태, 신고 접수/확인/승인/반려/취소 상태, 승인 참조, 실제 LMS 입퇴실 시각·조회 기준 시각, 호명 근거, 적용 규칙 버전, 예정 대조 결과, 다음 확인 시각, 안내 보류/변경 사유·안내 ID·공식 판정/정정 상태.

출력은 `사전 지각 신고 10:00 / 10:05 기준 입실 미확인 / 재확인 대기`처럼 신고·관찰·다음 조치를 함께 표시합니다. 개인 사유·의료 내용은 공개 게시판에 재전송하지 않고 비공개 안내와 제한된 담당자 화면에만 필요한 범위로 표시합니다.

## 예외·승인

- 게시판 수집 실패·권한 없음·지연은 신고 없음과 다릅니다. 최신 신고 확인 없이 일반 독촉하지 않고 수집 장애·확인 대기로 보고합니다.
- LMS 조회 실패·빈 오류 화면·잘못된 날짜·과정·형식은 미입실 명단으로 취급하지 않습니다.
- 학생 매칭 실패·기수 혼동·날짜/시각 모호·상충 신고는 자동 단정하지 않고 보완/담당자 확인으로 연결합니다.
- 사전 예정이 있어도 실제 LMS 클릭이 완료됐다고 간주하지 않습니다. LMS 입실 기록만으로 외출 후 현재 참여 상태를 증명하지도 않습니다.
- 실제 기록의 지연 반영은 재조회하고 안내/정정 이력을 보존합니다. 같은 기준의 중복 알림을 차단합니다.
- 공식 출결 인정·정정·제재는 승인과 근거가 필요하며 게시글·AI 해석만으로 LMS 원본을 수정하지 않습니다.

## 운영 품질·확인 사례

1. 사전 지각 신고 학생은 기본 시각에 일반 미클릭 안내를 받지 않고 예정 입실 시각 뒤 실제 기록으로 확인되는지 검사.
2. 조퇴 예정 학생의 퇴실을 해당 예정 시각에 확인하고 일반 종료 시각의 중복/부적절 안내가 없는지 검사.
3. 외출 구간 중 중간출결 일반 독촉을 보류하고 복귀 예정 이후 확인되는지 검사. 지원하지 않는 LMS 외출 API/기록을 가정하지 않음.
4. 승인 대기 신고는 예정을 반영하되 공식 출석 인정으로 변하지 않고, 예정 초과·반려·취소 시 재계산되는지 검사.
5. 수정/취소·수업일 변경·발송 직전 새 신고·LMS 지연 반영에서 오래된 안내가 차단되는지 검사.
6. 같은 날 여러 기수·동명이인·다른 날짜 신고가 섞이지 않고 게시판/LMS 수집 장애에서 잘못된 학생 독촉이 없는지 검사.
7. 정정 요청 접수·승인·LMS 실제 반영·학생 안내를 각각 확인하고 미반영 결과를 처리 완료로 표시하지 않는지 검사.

## 근거·연관

사용자 운영 설명과 기존 출결 구조에 따른 개발 명세입니다. 게시판과 LMS의 실제 연결·자동 대조 성공은 배포 전 검증 대상입니다.
