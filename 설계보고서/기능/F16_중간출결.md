# F16. 중간 출결·3종 출결 파일 종합

[전체 목록](../00_보고서_안내.md)

난이도: 3~4

## 목적

허용된 수업 시간 안에서 별도 사이트로 중간 출결을 진행하고, 기수별 3종 출결 파일(호명 출석부 `.xlsx`, 중간 출결 `.csv`, Teams 참석 보고서 `.csv`)을 모아 「MS 출결 정보 자동 업데이트」 사이트로 종합한 뒤 지정된 **내부 기수 채널의 파일 > 출석부 폴더**에 원본 3종과 종합본을 보관합니다.

## 입력·설정

파일 컬럼·시트·결과 표시색은 기존 사이트 설명을 바탕으로 한 참고 기준이며 실제 파일로 테스트·운영하면서 매핑을 변경할 수 있습니다. 09의 3종 입력·종합 결과 예시는 설명용 합성 데이터이지 기존 사이트 결과를 실제 검증한 증거가 아닙니다.

과정·기수·수업일, 별도 중간출결 사이트 URL·계정, 허용 시간대, 제외 시간(휴식·시험 등), 횟수, 응답 기한, 「MS 출결 정보 자동 업데이트」 사이트 URL, 내부 기수 채널·SharePoint site/drive/출석부 폴더 ID, 원본 수집 위치·허용 범위, 담당자. 사용자 제공 폴더 예시를 기준으로 아래 매핑을 등록하되, 운영 채널의 소속 팀·실제 ID·권한·파일 내용·연동은 별도로 확인합니다. 외부 기관 업무는 기관·수신 위치·자료 버전·매니저 승인을 별도 지정합니다.

- **호명 원본 수집:** 강사팀 `출석부 / [YY년 MM월] / [N주차 (MMDD ~ MMDD)] / [MMDD] / [MMDD.xlsx]` 예시와 `출석부 양식.xlsx`를 참고합니다. 실제 시트·학생 키·컬럼을 확인하고 원본은 덮어쓰지 않습니다.
- **내부 보관 목적지:** 운영 채널 `출석부 / [YY년 MM월] / [N주차 (MMDD ~ MMDD)] / [MMDD]`. 수강생 `일반 / Recordings`와 월·주차·일자 계층은 비슷하지만 다른 자료 영역입니다. 수강생 `일반` 안에 별도 출석부 폴더가 있다고 가정하지 않습니다.
- **참고성:** 날짜·주차·파일명·세부 구성은 테스트 및 운영을 하면서 바꿀 수도 있습니다. 폴더 이름만으로 원천·기수·수업·제출 완료를 확정하지 않습니다.

- **3종 입력 파일 형식:**
  1. `MS 출결확인 양식 (Excel)`: 오전·오후 호명 출석부 (`.xlsx`, `출결정보` 시트 포함)
  2. `중간 출석 정보 (CSV / Excel)`: 별도 중간출결 사이트 결과 파일 (`.csv`)
  3. `팀즈 참석 보고서 (CSV / Excel)`: 수업 일정 참석 명단 파일 (`.csv`, Graph API는 채널 회의를 지원하지 않고 JSON으로만 반환하므로 **컴퓨터 사용으로 일정에서 직접 `.csv` 다운로드**하여 통일)

## 처리 구조

`수업 일정 확인 → 허용 구간에서 시각 한 번 선택·저장 → 예약 → 별도 중간출결 사이트 실행·CSV 다운로드 → 호명 출석부(.xlsx)·중간출결(.csv)·Teams 참석 보고서(.csv) 3종 수집·기수/날짜 검증 → 컴퓨터 사용으로 「MS 출결 정보 자동 업데이트」 사이트에 3개 파일 업로드 후 [업데이트 실행] → 결과 파일(.xlsx, 변경 셀 #FFB366 표시) 다운로드 → 지정 내부 기수 채널의 출석부 폴더에 원본·결과 저장 → 담당자 알림`

### 사전 외출·조퇴·지각 신고의 반영

F15가 수집한 `01. 출결 게시판`의 기수·학생·수업일별 신고 유형·예정 구간·변경/취소·승인 상태를 중간출결 확인에도 연결합니다. 신고한 외출 구간이나 조퇴 예정 이후의 미응답을 일반 미이행 독촉으로 처리하지 않고 예정·실제 기록·호명·복귀 여부를 대조합니다. 승인 대기는 접수된 예정에 맞춰 안내를 보류/조정하되 공식 출결 면제로 확정하지 않습니다. 복귀 예정·유효 구간 이후 재확인하며 취소/변경은 예약에 반영합니다.

3종 원천 파일은 사실대로 보존합니다. 사전 신고·LMS 이력은 별도의 맥락/예외 기록으로 연결하고 **기존 종합 사이트에 네 번째 파일을 추가하거나 원천 미응답을 출석으로 바꾸지 않습니다.** 종합 결과와 신고가 상충하면 `사전 신고 있음/확인 필요`를 별도 표시합니다. 게시판 수집 실패는 신고 없음이 아니며 확인 전 일반 독촉을 보류합니다. 사이트가 학생별 예외를 지원하는지 실제 검증하고 지원하지 않는 구간은 대조·안내 계층에서 처리합니다.

## 리소스·권한

Durable Functions/Task Scheduler, PostgreSQL, 컴퓨터 사용([F19](F19_컴퓨터유즈_경험메모리.md) — Browser Automation/Playwright, Windows VM/PAD: 중간출결 `.csv` 다운로드, Teams 참석 명단 `.csv` 다운로드, 별도 VM 「MS 출결 정보 자동 업데이트」 사이트 업로드·실행), SharePoint/Teams(출석부 폴더 저장).

난수는 재생되는 예약기 본문에서 매번 다시 뽑지 않고, 시각을 확정해 기록합니다.

## 저장·출력

`checkin_sessions`, `checkin_responses`, `attendance_observations`, `documents`, `work_runs`.

원본 파일명 예시는 `MMDD.xlsx`이며 그대로 출처·버전과 함께 기록합니다. 내부 보관 사본·종합 결과는 같은 일자 폴더에서 원본 3종과 종합본이 충돌하지 않도록 과정·수업일·파일종류·버전으로 구분합니다(예: `호명출석부.xlsx` / `중간출결.csv` / `팀즈참석보고서.csv` / `출결업데이트완료.xlsx`에 식별 정보 추가). 이 이름은 예시이지 새 고정 규칙이 아닙니다. 파일 해시·크기·행 수·원천 시각·수집/보관 폴더 ID·저장 상태를 기록합니다. LMS 입퇴실은 별도 대조 이력이며 병합 사이트에 네 번째 파일을 추가하지 않습니다.

## 예외·승인

- 휴강/일정 이동이면 취소·재계산하고 이력을 남김.
- 기수·날짜가 다르거나 파일이 비어 있으면 「MS 출결 정보 자동 업데이트」에 넣지 않고 담당자 알림.
- 별도 VM 사이트 접속 불가 시 3종 원본 파일 보관 후 경보.
- 내부 폴더 미확정: 접근 제한된 임시 보관 위치·상태를 기록하고 담당자 확인 대기. 임의 팀/폴더를 목적지로 정하지 않음.
- 출석 관리 팀으로 기본 자동 전달하지 않음. 외부 기관 출석 업무가 있을 때만 지정 자료를 매니저 승인 후 별도 공유하고 내부 보관과 전달 결과를 구분.
- 동일 회차 재시도는 새 시각·새 확인 요청을 무작정 만들지 않음.

## 운영 품질 기준

선택 시각이 허용 구간 안에 있어야 하고 재시도에도 동일 회차가 유지되어야 합니다. 각 기수의 정확한 3종 파일(`.xlsx` 1개, `.csv` 2개)이 업로드되어 결과 파일이 해당 기수 출석부 폴더에 저장되어야 합니다.

외출 예정 중 중간 확인, 조퇴 예정 이후 미응답, 복귀 예정 초과, 신고 수정/취소를 검사해 잘못된 일반 독촉이 없는지 확인합니다.

테스트·운영에서 원천별 학생 키·날짜·상태와 종합 결과의 변경 셀을 대조하고, 충돌은 확인 필요로 남깁니다. 종합 파일 생성·저장은 공식 출결 승인과 별개입니다.
