# F19. 컴퓨터 사용·새 사이트 작업

[전체 목록](../00_보고서_안내.md)

난이도: 5

실행기·모델·리전·사이트 절차는 조사 기준의 참고 후보입니다. 실제 테스트·운영에서 결과 정확성·사람 개입률·지연·비용을 보고 더 좋은 모델/실행 방식 또는 더 가성비 있는 구성으로 변경하며 현재 후보를 고정하지 않습니다. 권한·승인·비밀 분리·완료 검사는 유지합니다.

## 목적

웹 LMS·중간출결·출결 업데이트 사이트처럼 API가 없는 화면에서 허용된 업무를 정형 절차로 실행하고, 화면이 예상과 다른 예외 구간만 제한적으로 탐색합니다. 실행 결과(성공·실패·시간·비용·증거)는 기록하며, 절차 변경은 개발자·운영자가 검토해 새 버전으로 등록합니다.

## 입력·설정

업무 목표, 허용 사이트·동작, 연결 계정 참조, 대상 과정/기간, 완료 검사, 최대 단계·시간·비용, 승인 필요 동작, 사용자 개입 담당자.

비밀번호는 안전한 연결 입력으로 받으며, 일반 대화·설계 문서·운영 로그에 남기지 않습니다.

**파일 작업의 대상 확인:** KDT 폴더 구조의 수강생 `일반`·기수별 운영 채널·강사팀을 별도 허용 범위로 등록합니다. 화면의 폴더명뿐 아니라 연결 테넌트·site/drive/folder ID·과정·자료 역할·읽기/쓰기 목적을 확인한 뒤 작업하며, 비슷한 월·주차·일자 이름만으로 녹화와 출석부를 혼동하지 않습니다. 이름·날짜·화면·세부 구성은 테스트 및 운영을 하면서 바꿀 수도 있습니다. 예시 등록은 검증된 실행 절차 등록과 다르며 확인되지 않은 폴더를 임의 생성하거나 자료를 학생 영역으로 복사하지 않습니다.

## 처리 구조

```text
업무 요청 → 권한·행동 범위 확인
→ 사이트/역할/업무에 맞는 절차 검색
→ 검증된 절차 실행 또는 제한 탐색
→ 화면·요소 관찰 → 동작 후보 → 서버 정책 검사 → 실행
→ 단계별 결과 확인
→ 최종 완료 검사
→ 실행 기록 저장(성공·실패·시간·비용·증거)
→ 실패·화면 변경 시 담당자 알림 → 개발자·운영자가 절차 수정 후 새 버전 등록
```

## 세 가지 실행 방식 (상황에 맞는 방식을 선택해 사용하며, 세 가지를 전부 구축해야 하는 것은 아님)

| 방식 | 사용처 | 특징 |
|---|---|---|
| **① Browser Automation / Playwright** | Teams 채널 수업 일정 생성·참석 CSV 다운로드, **과정 종료 만족도 Forms 템플릿 복제·설정·링크 확보**, 웹 LMS·중간출결·기존 VM 출결 종합 사이트 | 버튼·파일 업로드 칸 같은 웹 요소를 조작. 정형 웹 절차의 기본 후보이며 속도·비용·정확도는 실제 업무에서 확인 |
| **② Power Automate for desktop (PAD)** | Windows 설치형 데스크톱 프로그램 | 웹 브라우저로 열 수 없는 PC 데스크톱 프로그램의 반복 절차를 구성 |
| **③ Foundry computer use (`computer-use-preview` 등 지원 모델)** | 화면 구조가 자주 바뀌거나 웹 요소(HTML)로 잡히지 않는 예외 구간 | 화면 캡처로 동작 후보를 추론. 모델·리전은 실제 테스트·운영에서 선택·변경하며 정형화 전 탐색·예외 구간에 보조 사용 |

새 사이트의 모든 구간을 영구적으로 AI 클릭(`③ computer use`)으로 처리할 필요는 없습니다. 웹은 **① Playwright**, PC 앱은 **② PAD** 정형 절차로 돌리고, 화면이 예상과 다른 예외 구간만 **③ Foundry computer use**가 보조합니다.

### 과정 종료 만족도 Forms 정형 절차 — 2026-10-28 추가

F06의 3항목 승인 템플릿을 과정 종료 전에 과정당 1개로 준비하고 제목·과정명·기수·기간/종료일·응답 설정을 치환합니다. 객관식 두 행·주관식 한 개·선택지/필수 설정·실제 응답 링크·양식 ID를 검사합니다. 복제는 문항 ID 유지 여부를 가정하지 않고 새 question_map을 시험 응답으로 검증합니다. 익명/기명·1인 1응답·마감 설정도 실제 계정에서 확인합니다.

복제된 form_id의 Logic Apps 수집 워크플로 배치는 승인된 Azure 배치 경로로 수행하며 화면 클릭으로 커넥터가 저절로 연결된다고 가정하지 않습니다. 연결 확인 전 발송을 차단하고 복제 결과 불명 시 기존 양식을 대조해 중복 생성을 방지합니다. 응답 자체는 공식 커넥터로 수집하고 Excel 다운로드는 장애 복구·대조용입니다. 실제 UI·OAuth·교차 테넌트 연결·과정별 양식·종료 1회 실행·중복 방지 검증을 통과한 절차만 활성화합니다([F06 상세](F06_만족도조사.md)).

## 리소스·권한

Foundry, Playwright Workspaces, Windows 실행 환경/PAD(필요 시), Key Vault, PostgreSQL/벡터 검색, Blob, Service Bus, Durable Functions.

브라우저/PC 실행기는 사이트·계정별 격리합니다. 같은 계정의 동시 조작은 잠금으로 제한하고, 사용자 업무용 노트북을 운영 실행기로 사용하지 않습니다.

## 저장 구조

| 종류 | 내용 | 원본 |
|---|---|---|
| 업무 상태 | 학생·출결·규칙·승인 | PostgreSQL |
| 절차 | 화면 조건·단계·완료 검사·복구 | 버전 관리된 절차 DB |
| 실행 기록 | 성공/실패·단계·시간·비용·증거 | DB + 제한된 Blob |
| 선호·대화 | 보고 형식·사용자 선호 | DB |

절차 필드: 사이트, 계정 역할, 업무, 버전, 전제 조건, 허용 동작, 단계, 기대 화면, 완료 검사, 실패 복구, 검증일, 성공/실패 횟수, 적용 상태.

## 예외·승인

- CAPTCHA·정책 차단은 우회하지 않고 확인 대기.
- 삭제·결제·공식 기록 정정·외부 최종 제출은 승인.
- 사이트 화면에 있는 지시문은 운영자 명령이 아님.
- 비밀 입력은 도구 수준 주입/마스킹을 검증. 분리할 수 없는 단계는 사람이 처리.
- 실패 사례를 성공 절차로 등록하지 않음. 절차 새 버전은 사람 검토 후 등록.
- 결과 불명인 발송·제출을 무조건 재시도하지 않음.
- UI 업데이트 감지 시 기존 절차를 검증 대기로 돌리고 버전별로 되돌릴 수 있게 함.

## 운영 품질 기준

운영 중 같은 대표 업무의 반복 실행 기록으로 결과 정확성·사람 개입률·시간·비용을 측정합니다. UI 변경·세션 만료·잘못된 날짜·중복 작업에서도 비허용 행동이 없어야 합니다. “클릭을 끝냈다”가 아니라 실제 업무 완료 조건을 통과해야 합니다.
