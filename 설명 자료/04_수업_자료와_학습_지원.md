- **실행 계기**  일정의 초안 마감·검수·배포 시각
- **완료 조건**  검수 완료와 게시·대상 학생 접근 확인을 각각 통과

## 목적

당일 교안과 **처음 저장 완료된 오전 수업 녹화·녹취**를 바탕으로 오후에 낼 복습 퀴즈의 문항·정답·해설을 자동 작성합니다. 강사/매니저가 검수하고 **사람이 Microsoft Forms 게시·정답/배점 설정·링크 등록**을 마치면 Teams로 배포·집계합니다.

한 기수의 하루 수업 일정은 1개입니다. 여러 날에 걸친 강의 단위는 별도 ID로 묶습니다. 아래 오전·오후 구간은 같은 하루 강의의 내부 시간 구간이며, 여러 기수가 같은 날 운영되면 교안·녹화·퀴즈를 기수·수업일별로 구분합니다.

## 입력·설정

당일 과목·회차·교안 버전(PDF·PPT·Word·HTML·Markdown·HWP/HWPX 등), 확인된 진도·학습 목표, 오전 분할 녹화·녹취, 담당 강사별 시간대·검수자, 문항 수(예: 20개)·난이도·유형, 초안 마감·배포 시각·응답 기한·채점 방식.

하루 **3~4개로 나뉘어 저장되는 녹화 중 해당 회차의 오전 구간이 저장·분석 완료됐는지** 확인합니다. 하루 전체 수업 종료를 기다리는 방식이 아니며, 오후 내용을 미리 확인한 것으로 취급하지 않습니다. “수업 종료 1시간 전”과 “매시간”은 별도 규칙으로 설정합니다.

**자료 위치 예시:** 폴더 구조의 수강생 `일반 / 05. 강의자료`와 `일반 / Recordings / 월 / 주차 / 일자`를 회차·강사·파일 버전으로 연결합니다. 강사팀 `중간평가문제`는 강사별 중간평가 자료이며 일일 퀴즈 초안·정답·응답 결과의 공용 저장소로 가정하지 않습니다. 검수본·정답·개인 응답의 제한 위치는 별도 지정하고 학생에게는 게시된 Forms 링크만 안내합니다. 경로·날짜·파일명·세부 구성은 테스트 및 운영을 하면서 바꿀 수도 있으며 실제 ID·권한은 확인 전입니다.

## F07 실행 순서

1. 교안·회차·확인된 진도 확인
2. F10 오전 저장/분석 완료 구간 연결
3. 문항·정답·해설·근거 초안과 형식 검사
4. 강사 검수와 사람 Forms 게시/정답 설정
5. 게시 링크 확인 후 예약 안내·응답 Excel 수집

<!--

## 처리 구조

```text
교안·회차·강사별 시간대·확인된 진도 확인
→ F10에서 오전 첫 저장 완료 구간·녹취 수집·분석 상태 확인
→ 확인된 학습 범위로 문제·정답·해설·근거 초안 생성
→ 문항 수·중복·정답 형식·출제 범위 검사
→ 담당 강사/매니저에게 검수용 Excel 및 가져오기용 Word/PDF 전달
→ 사람이 검수·수정, Forms 생성/가져오기 검토·정답/배점 설정·게시
→ 게시 링크·양식 버전 등록 및 대상 학생의 응답 가능 여부 확인
→ 예약 시각에 해당 기수 Teams로 링크 안내
→ 매니저가 Forms 응답 화면에서 Excel 다운로드·전달 → 에이전트 수집·채점·복습 자료 제공
```

**Forms Quick Import는 로컬 Word/PDF(10MB 이하)의 선택형·텍스트형 위주 변환**입니다. Excel은 검토·집계용이며 문제 시트를 그대로 가져오는 기능으로 설명하지 않습니다. 변환 결과·정답·배점은 사람이 확인합니다. 별도 학생용 퀴즈 사이트는 만들지 않습니다.

다운로드한 응답 Excel은 해당 시점의 사본입니다. 새 응답은 다시 다운로드하고 양식 버전·응답 ID로 중복을 제거합니다. 모델·지원 형식·파서 후보는 실제 테스트·운영에서 품질·비용·추출 결과에 맞게 변경하며, 강사 검수·정답/배점·게시 확인은 유지합니다.

## 예외·승인

- 오전 녹화 저장·권한·분석이 늦으면 담당자에게 알리고 **교안과 확인된 진도만으로 초안**을 만들며 녹화 미반영 범위를 표시.
- 교안 없음·실제 진도 불명확: 생성 대기. 없는 구간의 발언·내용을 만들어내지 않음.
- 강사 미승인·정답/배점 미설정·미게시·잘못된 링크: 배포 보류. 사람 작업 시간을 배포 전에 확보.
- 멘토링·중간평가·방학은 일정 분류에 따라 정규 퀴즈 생략 가능.
- 게시 후 오답: 정정·재채점 이력과 학생 안내. 서술형 AI 채점은 피드백 보조.
- 퀴즈 미참여를 수면·불성실·공식 결석으로 자동 환산하지 않음.

## 목적

강의 녹화본을 API 또는 컴퓨터 사용으로 열어, **관찰할 수 있는 장면과 확인이 필요한 구간**을 시각·근거와 함께 매니저에게 제공합니다.

“API로 어려우면 컴퓨터 사용으로 볼 수 있는가?”에 대한 답은 **허용된 화면을 재생·탐색하는 경로는 가능하지만, 자료에 없는 화면이나 모호한 사람 상태까지 알아낼 수는 없다**입니다.

> **[현실적 한계와 활용 범위 — 왜 학생 개별 감시용이 아닌가]**
> 1. **Teams 녹화본의 구조적 한계:** 하루 8시간 수업 녹화본은 용량이 크고, Teams 녹화 화면에는 **발표자(강사 화면 공유) + 발언자 1~4명 정도만 작게** 찍힙니다. 즉 녹화 영상만으로는 **수강생 30명 개개인이 그 시각에 졸았는지·자리에 있었는지를 알아내는 것이 물리적으로 불가능**합니다(Teams가 모든 학생의 웹캠 원본을 개별 녹화하지 않기 때문).
> 2. **원본 기획안(3-4, 3-5) 대비 변경 사유:** 원본 기획안에는 *"녹화본과 채팅을 입체적으로 봐서 참여도가 낮은 사람 Top 3를 뽑거나, 카메라 꺼진 사람·자는 사람에게 에이전트가 자동으로 경고를 보낸다"*고 기재되어 있습니다. 하지만 화면에 안 찍힌 학생이나 필기하느라 고개를 숙인 모습·네트워크 장애를 AI가 '수면'이나 '고의적 카메라 꺼짐'으로 오판해 자동 경고를 보낼 경우 심각한 민원이 발생합니다.
> 3. **본 설계의 현실적 역할:** 따라서 학생 태도 순위 산출과 AI 자동 경고 발송은 제외하고, **① 당일 수업 녹화·녹취가 정상 생성되었는지, ② 강사 화면 공유·교안 표시·음성 송출 사고가 없었는지, ③ 오전/당일 수업 녹화·녹취에서 다룬 내용을 요약해 일일 퀴즈([F07](#f07))·Q&A([F08](#f08)) 생성에 활용하고, 확인이 필요한 구간과 시각만 매니저에게 요약 제공**하도록 설계했습니다.



한 기수의 하루 수업 일정은 1개이며, 하루 3~4개 녹화는 그 강의의 분할 저장 파일입니다. 같은 날 여러 기수가 운영되므로 기수·수업일·일정 참조로 녹화를 구분하고 녹화 개수를 강의 수로 세지 않습니다.
